
# 기능개발 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42586

## 사용 알고리즘 / 자료구조

- `ArrayList`

## 1. 문제 접근

문제에 주어진 진행률과 하루 작업 속도를 이용해 각 기능이 완성되기까지 남은 일수를 계산했다.

```text
남은 일수 = (100 - 현재 진행률) / 하루 작업 속도
```

나눗셈 결과에 나머지가 있으면 그날 작업을 더 해야 기능이 완성되므로 남은 일수에 하루를 추가했다.

기능은 먼저 완성되더라도 앞의 기능이 배포되기 전에는 배포할 수 없다. 따라서 `day` 변수에 현재 배포 묶음의 기준이 되는 앞 기능의 완료일을 저장했다.

- 현재 기능의 완료일이 `day`보다 작거나 같으면 앞 기능을 기다렸다가 함께 배포하므로 `count`를 증가시킨다.
- 현재 기능의 완료일이 `day`보다 크면 이전 배포 묶음의 개수를 결과에 추가하고, 현재 기능부터 새로운 배포 묶음을 시작한다.

배열을 한 번 순서대로 확인하는 것만으로 각 배포일에 배포되는 기능의 수를 구할 수 있다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int[] solution(int[] progresses, int[] speeds) {
        List<Integer> list = new ArrayList<>();

        int day = 0;
        int count = 0;

        for (int i = 0; i < progresses.length; i++) {
            int remainDay = (100 - progresses[i]) / speeds[i];
            if ((100 - progresses[i]) % speeds[i] != 0) remainDay += 1;

            if (remainDay <= day) {
                count++;
            } else {
                if (count > 0) {
                    list.add(count);
                }

                count = 1;
                day = remainDay;
            }
        }
        list.add(count);

        int[] answer = new int[list.size()];
        for (int i = 0; i < answer.length; i++) {
            answer[i] = list.get(i);
        }

        return answer;
    }
}
```

## 3. 새롭게 배운 내용

### 나눗셈 결과 올림하기

기능이 완성되기까지 걸리는 날짜는 정수 나눗셈의 결과를 올림해야 한다.

현재 코드처럼 나머지를 확인할 수도 있다.

```java
int remainDay = (100 - progresses[i]) / speeds[i];
if ((100 - progresses[i]) % speeds[i] != 0) {
    remainDay++;
}
```

양의 정수 `a`, `b`에 대해서는 다음과 같이 한 줄로도 계산할 수 있다.

```java
int remainDay = (a + b - 1) / b;
```

이 문제에 적용하면 다음과 같다.

```java
int remainDay = (100 - progresses[i] + speeds[i] - 1) / speeds[i];
```

### 앞 기능의 완료일이 배포 기준이 된다

각 기능의 실제 배포일은 자신의 완료일만으로 결정되지 않는다. 앞 기능의 배포일보다 일찍 완성된 기능은 앞 기능과 함께 배포된다. 따라서 현재 배포 묶음의 기준일 하나만 기억하면 별도의 큐 없이도 문제를 해결할 수 있다.

## 4. 시간복잡도 / 공간복잡도

- 시간복잡도: `O(n)`
  - 모든 기능을 한 번씩 순회한다.
- 공간복잡도: `O(n)`
  - 배포 묶음별 기능 개수를 `list`에 저장한다.
  - 반환 배열을 제외한 추가 공간만 계산해도 최악의 경우 모든 기능의 배포일이 달라 `O(n)`이다.

## 5. 엣지 케이스

- 기능이 하나뿐인 경우: 결과는 `[1]`이다.
- 모든 기능이 같은 날 또는 앞 기능보다 먼저 완성되는 경우: 모든 기능이 한 번에 배포된다.
- 모든 기능의 완료일이 점점 늦어지는 경우: 각 기능이 서로 다른 날 하나씩 배포된다.
- 나누어떨어지지 않는 경우: 남은 작업량을 속도로 나눈 결과를 반드시 올림해야 한다.
- 뒤의 기능이 먼저 완성되는 경우: 앞 기능의 완료일까지 기다렸다가 함께 배포해야 한다.

## 6. 한줄평

각 기능의 완료일을 구한 뒤, 앞 기능의 배포일을 기준으로 묶으면 간단하게 해결할 수 있는 문제였다.

## 7. 더 나은 풀이와 코드 개선

현재 풀이는 배열을 한 번만 순회하므로 시간복잡도 측면에서 이미 최적이다. 이 문제는 큐 유형으로 분류되지만, 실제로 큐를 만들지 않고 기준 배포일만 기억한 방식이 더 간결하고 추가 자료구조도 적게 사용한다.

다만 다음 부분은 개선할 수 있다.

- 올림 계산을 한 줄로 표현해 중복 계산을 없앤다.
- `day`를 `deployDay`로 바꾸어 배포 기준일이라는 의미를 분명하게 한다.
- `list`를 `deployCounts`로 바꾸어 저장하는 값의 의미를 드러낸다.
- `count`가 0인지 확인하는 대신 첫 번째 기능으로 첫 배포 묶음을 초기화하면 분기 처리가 줄어든다.

### 추천 코드

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public int[] solution(int[] progresses, int[] speeds) {
        List<Integer> deployCounts = new ArrayList<>();

        int deployDay = getRemainingDays(progresses[0], speeds[0]);
        int count = 1;

        for (int i = 1; i < progresses.length; i++) {
            int remainingDays = getRemainingDays(progresses[i], speeds[i]);

            if (remainingDays <= deployDay) {
                count++;
                continue;
            }

            deployCounts.add(count);
            deployDay = remainingDays;
            count = 1;
        }

        deployCounts.add(count);
        return deployCounts.stream().mapToInt(Integer::intValue).toArray();
    }

    private int getRemainingDays(int progress, int speed) {
        return (100 - progress + speed - 1) / speed;
    }
}
```

완료일 계산을 메서드로 분리해 의도를 드러냈고, 첫 번째 기능부터 하나의 배포 묶음을 시작하도록 초기화해 `count > 0` 검사를 제거했다. 다만 코딩테스트에서는 짧은 로직을 반드시 메서드로 분리할 필요는 없다. 현재 코드처럼 반복문 안에서 바로 계산해도 충분히 좋은 풀이이다.
