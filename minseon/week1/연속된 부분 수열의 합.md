# 연속된 부분 수열의 합 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/178870

## 1. 문제 접근

각 시작 인덱스 `i`에서 합이 `k`가 될 때까지 뒤의 원소를 차례로 더하는 방식으로 접근했다.

- 합이 `k`가 되면 현재 구간을 정답 후보로 저장한다.
- 합이 `k`보다 커지면 수열의 모든 원소가 양수이므로 뒤의 원소를 더해도 합이 작아지지 않는다. 따라서 현재 탐색을 중단하고 다음 시작 인덱스로 이동한다.
- 합이 `k`인 구간을 찾았을 때 기존에 찾은 구간보다 짧은 경우에만 정답을 갱신한다.

## 2. 문제 코드

### 접근 1: 시작 위치마다 합을 다시 계산

```java
class Solution {
    public int[] solution(int[] sequence, int k) {
        int[] answer = new int[2];
        int cnt = sequence.length;

        for (int i = 0; i < sequence.length; i++) {
            int j = i;
            int sum = 0;

            while (sum <= k && j < sequence.length) {
                sum += sequence[j];

                if (sum == k && (j - i) < cnt) {
                    cnt = j - i;
                    answer[0] = i;
                    answer[1] = j;
                    break;
                }
                j++;
            }
        }
        return answer;
    }
}
```

#### 시간초과 원인

각 시작 인덱스 `i`마다 `sum`을 0으로 초기화하고, 인덱스 `j`를 다시 `i`부터 이동시킨다. 이 때문에 앞에서 이미 더했던 구간의 합을 여러 번 다시 계산하게 된다.

최악의 경우 바깥쪽 반복문과 안쪽 반복문이 각각 수열 전체를 순회하므로 시간복잡도는 `O(n²)`이다. 수열의 길이는 최대 1,000,000이기 때문에 이 방식은 시간초과가 발생한다.

### 접근 2: 양 끝에 포인터 배치

수열이 비내림차순으로 정렬되어 있기 때문에 `left`를 배열의 처음에, `right`를 배열의 끝에 두는 투 포인터 방식도 생각했다.

```java
class Solution {
    public int[] solution(int[] sequence, int k) {
        int[] answer = new int[2];

        int left = 0;
        int right = sequence.length - 1;
        answer[0] = left;
        answer[1] = right;
        int sum = 0;

        while (left <= right) {
            sum = sequence[left] + sequence[right];

            if (sum < k) left += 1;
            else if (sum > k) right -= 1;

            if (sum == k && answer[1] - answer[0] > right - left) {
                answer[0] = left;
                answer[1] = right;
            }
        }

        return answer;
    }
}
```

#### 해결할 수 없는 이유

이 방식은 정렬된 배열에서 **합이 `k`인 두 원소**를 찾을 때 사용하는 투 포인터 방식이다.

하지만 이 문제에서는 두 원소만 더하는 것이 아니라 `left`부터 `right`까지 연속된 모든 원소를 더해야 한다. 따라서 다음 코드는 구간의 합을 나타내지 않는다.

```java
sum = sequence[left] + sequence[right];
```

예를 들어 `[1, 1, 1, 2]`처럼 세 개 이상의 원소로 이루어진 정답 구간은 양 끝값만 더해서 찾을 수 없다.

또한 `sum == k`인 경우에는 `left`와 `right`가 모두 이동하지 않는다. 다음 반복에서도 같은 합이 계산되므로 무한 반복이 발생한다.

이 문제에서는 포인터를 양 끝에서 시작하는 것이 아니라, 두 포인터를 모두 배열의 왼쪽에서 시작해 구간을 확장하고 축소해야 한다.

## 3. 새롭게 배운 내용

### 투 포인터

이 문제의 수열은 모든 원소가 양수이므로 구간을 넓히면 합이 증가하고, 왼쪽 원소를 제외하면 합이 감소한다. 이 성질을 이용해 두 개의 포인터로 연속 구간을 관리할 수 있다.

1. `right`가 가리키는 값을 더해 구간을 오른쪽으로 확장한다.
2. 합이 `k`보다 크면 합이 `k` 이하가 될 때까지 `left`가 가리키는 값을 빼고 `left`를 이동한다.
3. 합이 `k`라면 현재 구간이 기존 정답보다 짧은지 확인한다.

`left`와 `right`는 뒤로 돌아가지 않고 각각 최대 `n`번만 이동하므로 전체 시간복잡도는 `O(n)`이다.

## 4. 시간복잡도 / 공간복잡도

### 처음 작성한 풀이

- 시간복잡도: `O(n²)`
- 공간복잡도: `O(1)`

### 양 끝 포인터 풀이

- 시간복잡도를 따지기 전에 문제에서 요구하는 연속 구간의 합을 계산하지 못하므로 올바른 풀이가 아니다.
- `sum == k`일 때 포인터가 이동하지 않아 무한 반복이 발생할 수 있다.

### 투 포인터 풀이

- 시간복잡도: `O(n)`
  - `left`와 `right`가 각각 배열을 한 번씩만 이동한다.
- 공간복잡도: `O(1)`
  - 입력 배열과 반환 배열 외에 몇 개의 변수만 사용한다.

## 5. 엣지 케이스

- 원소 하나의 값이 `k`인 경우: 길이가 가장 짧으므로 해당 인덱스를 반환해야 한다.
- 합이 `k`인 구간의 길이가 같은 경우: 시작 인덱스가 더 작은 구간을 선택해야 한다.
- 같은 숫자가 반복되는 경우: 여러 정답 후보 중 가장 앞쪽 구간을 선택해야 한다.
- 합이 `k`보다 커진 경우: 왼쪽 값을 한 번만 빼는 것이 아니라, 합이 `k` 이하가 될 때까지 계속 빼야 한다.
- 정답 구간이 배열의 처음이나 끝에 있는 경우도 정상적으로 찾아야 한다.

## 6. 한줄평

연속된 구간의 합을 반복해서 계산하기보다, 기존 합에서 값을 더하고 빼며 재사용하는 투 포인터 방식이 중요했던 문제였다.

## 7. 더 나은 풀이와 코드 개선

기존 풀이의 핵심 문제는 시작 인덱스가 바뀔 때마다 구간 합을 처음부터 다시 계산한다는 점이다. 투 포인터를 사용하면 이전에 계산한 합을 그대로 유지하면서 구간의 양쪽 끝만 이동할 수 있다.

두 번째로 생각한 양 끝 포인터 방식은 정렬된 배열에서 두 원소의 합을 찾는 문제와 혼동한 경우이다. 코딩테스트에서 투 포인터를 사용할 때는 단순히 정렬 여부만 확인하지 말고, 포인터가 나타내는 범위와 현재 저장한 `sum`이 무엇을 의미하는지 먼저 정해야 한다.

또한 `cnt`에는 실제 원소 개수가 아니라 `끝 인덱스 - 시작 인덱스`가 저장된다. 비교 자체는 가능하지만, `minLength`에 `right - left + 1`을 저장하면 변수명과 값의 의미가 일치해 코드를 이해하기 쉽다.

### 추천 코드

```java
class Solution {
    public int[] solution(int[] sequence, int k) {
        int[] answer = new int[2];
        int left = 0;
        int sum = 0;
        int minLength = Integer.MAX_VALUE;

        for (int right = 0; right < sequence.length; right++) {
            sum += sequence[right];

            while (sum > k) {
                sum -= sequence[left];
                left++;
            }

            int currentLength = right - left + 1;
            if (sum == k && currentLength < minLength) {
                minLength = currentLength;
                answer[0] = left;
                answer[1] = right;
            }
        }

        return answer;
    }
}
```

`right`를 왼쪽부터 순서대로 이동하고 길이가 더 짧을 때만 정답을 갱신한다. 따라서 길이가 같은 구간이 여러 개라면 먼저 발견한, 즉 시작 인덱스가 더 작은 구간이 그대로 유지된다.
