# 피로도 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/87946

## 0. 문제 요약

현재 피로도 `k`로 탐험할 수 있는 **최대 던전 수**를 구한다. 각 던전에는 입장할 때 필요한 `최소 필요 피로도`와 탐험 후 차감할 `소모 피로도`가 있다. 던전은 각각 한 번씩만 탐험할 수 있고, 탐험 순서는 자유롭다. 던전 수는 최대 8개다.

## 사용 알고리즘 / 자료구조

- DFS, 백트래킹, 순서가 있는 완전탐색, 방문 배열

## 1. 문제 접근

문제에서 가장 먼저 본 조건은 **던전 순서가 정해져 있지 않다**는 점이다. 배열의 첫 번째 던전부터 차례로 가는 것만 확인하면 안 된다. `1 → 3 → 2`처럼 중간에 다른 던전을 먼저 탐험하면 남은 피로도가 달라지고, 최종 탐험 수가 더 많아질 수 있다.

따라서 현재 상태에서 **아직 방문하지 않았고, 남은 피로도로 입장할 수 있는 모든 던전**을 다음 후보로 시도한다. 던전을 하나 선택할 때마다 피로도를 차감하고 DFS로 이어 간다. 그 경로가 끝나면 방문 표시를 되돌려 다른 탐험 순서도 확인한다.

```text
현재까지 탐험한 던전 수로 정답 갱신
→ 갈 수 있는 미방문 던전 하나 선택
→ 피로도를 빼고 다음 선택 탐색
→ 방문 표시 복구 후 다른 던전 선택
```

던전은 최대 8개라 가능한 순서를 모두 확인할 수 있다. 그래서 특정 던전을 먼저 가는 규칙을 정하기보다 DFS로 순서를 탐색했다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    int answer = 0;

    public int solution(int k, int[][] dungeons) {
        boolean[] visited = new boolean[dungeons.length];

        dfs(k, visited, dungeons, 0);
        return answer;
    }

    void dfs(int k, boolean[] visited, int[][] dungeons, int cnt) {
        answer = Math.max(answer, cnt);

        for (int i = 0; i < dungeons.length; i++) {
            if (visited[i]) continue;

            if (dungeons[i][0] <= k) {
                visited[i] = true;
                dfs(k - dungeons[i][1], visited, dungeons, cnt + 1);
                visited[i] = false;
            }
        }
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 `visited` | 현재 탐험 순서에서 이미 다녀온 던전을 표시한다. |
| 2 | `dfs()`의 `Math.max()` | 현재까지 탐험한 `cnt`개와 기존 최댓값을 비교한다. |
| 3 | `dfs()`의 `for`문 | 다음 던전을 배열 전체에서 찾는다. 순서를 고정하지 않기 위해 매번 `0`부터 확인한다. |
| 4 | `visited[i]` 검사 | 같은 탐험 순서에서 한 던전을 두 번 가지 못하게 한다. |
| 5 | `dungeons[i][0] <= k` | 입장할 피로도가 충분한지 확인한다. |
| 6 | `dfs(k - dungeons[i][1], ..., cnt + 1)` | 피로도를 소모하고 탐험 수를 늘려 다음 선택으로 간다. |
| 7 | `visited[i] = false` | 돌아온 뒤 다른 탐험 순서를 시도할 수 있도록 방문을 취소한다. |

## 3. 새롭게 배운 내용

### 왜 `visited`가 필요할까?

이 문제는 다음 던전을 항상 현재 번호보다 뒤에서 고르지 않는다. 예를 들어 `2 → 1 → 3` 같은 순서도 후보가 될 수 있다. `i + 1`부터만 고르면 앞 번호의 던전으로 돌아갈 수 없다. 반대로 모든 던전을 매번 확인하면서 방문 기록이 없다면 **같은 던전을 또 탐험**할 수 있다. 그래서 `for`문은 매번 전체 던전을 보고, `visited[i]`로 현재 경로에서 사용한 던전만 제외한다.

### 왜 방문 표시를 다시 `false`로 바꿀까?

`visited[i] = true`는 **현재 탐험 순서에서만** `i`번 던전을 사용했다는 뜻이다. 재귀 호출이 끝나면 다음 순서를 시험해야 한다. 예를 들어 `1 → 3 → 2`를 확인한 다음 `2 → 1 → 3`도 시도하려면, 앞에서 표시한 던전을 다시 사용할 수 있어야 한다. 재귀에서 돌아온 뒤 방문 표시를 취소하는 것이 백트래킹이다.

`k`와 `cnt`는 정수이므로 재귀 호출에 `k - 소모 피로도`, `cnt + 1`을 전달해도 호출한 쪽의 값은 바뀌지 않는다. 여러 호출이 공유하는 `visited` 배열만 원상복구한다.

### 종료 조건 `if`나 `return`이 없어도 될까?

현재 상태에서 갈 수 있는 미방문 던전이 없으면 `for`문에서 재귀 호출이 일어나지 않는다. 반복문이 끝나면 `void dfs()`도 자연스럽게 끝난다. 함수에 들어올 때마다 `answer`를 갱신하므로, 중간에 더 이상 갈 수 없게 된 경로의 `cnt`도 이미 비교했다.

## 4. 처음 보는 문제에서의 사고 흐름

알고리즘 이름부터 정하기보다 **무엇을 바꿔 선택할 수 있는지, 그 선택을 몇 번 시도할 수 있는지**를 확인한다.

| 문제의 문장 | 먼저 할 생각 | 코드로 옮길 것 |
| --- | --- | --- |
| “최대한 많은 던전” | 무엇을 비교해야 하지? | `cnt`의 최댓값을 `answer`에 저장 |
| “던전 순서는 자유” | 첫 번째 던전부터 가는 것만 보면 되나? | 매 단계 모든 던전을 다음 후보로 확인 |
| “던전마다 한 번” | 같은 경로에서 재방문을 어떻게 막지? | `visited[i]` 확인·표시 |
| “최소 필요 피로도” | 지금 입장할 수 있나? | `k >= dungeons[i][0]` |
| “소모 피로도” | 선택 후 상태는 어떻게 바뀌나? | 다음 DFS에 `k - dungeons[i][1]` 전달 |
| “던전 최대 8개” | 모든 순서를 확인해도 되나? | DFS 완전탐색 가능 |

예시 `k = 80`, 던전 `[[80,20], [50,40], [30,10]]`에서는 `1 → 2 → 3`으로 가면 두 개만 탐험할 수 있다. `1 → 3 → 2`로 가면 `80 → 60 → 50 → 10`이 되어 세 개 모두 탐험할 수 있다. **순서가 결과를 바꾼다**는 사실이 여러 순서를 탐색해야 하는 이유다.

## 5. 시간복잡도 / 공간복잡도

던전 수를 `n`이라고 하자. DFS는 가능한 방문 순서를 따라가며, 각 호출에서 던전 `n`개를 확인한다. 시간복잡도는 **`O(n × n!)`**, 방문 배열과 재귀 호출에 드는 추가 공간복잡도는 **`O(n)`**이다.

최대 `n = 8`일 때 탐색 상태 수는 `1 + 8 + 8×7 + … + 8! = 109,601`개 이하다. 각 상태에서 최대 8개 던전을 확인하므로 약 `109,601 × 8 ≈ 8.8 × 10⁵`번의 후보 확인 규모다. 일부 던전에 입장할 피로도가 부족하면 실제 탐색은 더 줄어든다. 흔히 참고하는 `10⁸`회보다 작지만, 이 수치는 실행 시간을 보장하는 절대 기준은 아니다.
