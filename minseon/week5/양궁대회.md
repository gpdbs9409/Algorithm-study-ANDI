# 양궁대회 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/92342

## 0. 문제 요약

어피치가 먼저 `n`발을 쏜 결과 `info`가 주어진다. 라이언도 `n`발을 모두 사용해 어피치보다 높은 점수를 얻어야 한다. 각 점수에서 라이언이 어피치보다 **많이** 맞히면 라이언이, 그렇지 않고 어피치가 한 발 이상 맞혔다면 어피치가 그 점수를 얻는다. 둘 다 0발이면 아무도 얻지 않는다.

라이언이 이기는 배치 중 **점수 차이가 가장 큰 배치**를 반환한다. 차이가 같다면 0점부터 비교해 더 낮은 점수에 화살을 많이 쏜 배치를 고른다. 이길 수 없다면 `[-1]`을 반환한다. `1 ≤ n ≤ 10`이다.

## 사용 알고리즘 / 자료구조

- 부분집합 완전탐색, DFS(재귀), 백트래킹

## 1. 문제 접근

처음에는 10점부터 차례로 살펴보며, 해당 점수를 가져오는 데 필요한 `info[i] + 1`발을 쏘려고 했다. 높은 점수를 먼저 가져오는 방식이다. 하지만 화살이 제한되어 있어 높은 점수 하나에 많이 쓰는 것보다 다른 점수 여러 개를 가져오는 편이 점수 차이를 더 키울 수도 있다. 실제로 문제 예시에서는 10점과 9점을 가져오면 4점 차이지만, 10점을 포기하고 9점·8점·6점을 가져오면 6점 차이다.

따라서 한 번의 배치만 계산해서는 최댓값을 알 수 없다. 10점부터 1점까지 각 칸에서 다음 두 선택을 탐색한다.

- **가져온다:** `info[i] + 1`발을 쓴다. 남은 화살이 부족하면 선택할 수 없다.
- **포기한다:** 0발을 쓴다.

가져오기로 했다면 어피치보다 한 발만 더 쏘면 충분하다. 그보다 많이 쏴도 얻는 점수는 같고, `1`발부터 `info[i]`발까지 쏘면 그 점수를 가져오지 못한다. 0점 칸에 도착하면 남은 화살을 모두 넣어 정확히 `n`발을 사용한다.

완성된 배치마다 점수 차이를 계산한다. 더 큰 차이면 정답을 교체하고, 같은 차이면 0점부터 10점 순서로 화살 수를 비교한다.

## 2. 문제 코드

```java
class Solution {
    int maxDiff = 0;
    int[] answer = new int[11];

    public int[] solution(int n, int[] info) {
        dfs(n, 0, new int[11], info);
        return maxDiff == 0 ? new int[]{-1} : answer;
    }

    void dfs(int n, int idx, int[] ryan, int[] info) {
        if (idx == 10) {
            ryan[10] = n;
            int ryanScore = 0;
            int apeachScore = 0;

            for (int i = 0; i < 11; i++) {
                if (ryan[i] > info[i]) {
                    ryanScore += 10 - i;
                } else if (info[i] > 0) {
                    apeachScore += 10 - i;
                }
            }

            int diff = ryanScore - apeachScore;
            if (diff > maxDiff) {
                maxDiff = diff;
                answer = ryan.clone();
            } else if (diff == maxDiff && diff > 0) {
                for (int i = 10; i >= 0; i--) {
                    if (ryan[i] != answer[i]) {
                        if (ryan[i] > answer[i]) {
                            answer = ryan.clone();
                        }
                        break;
                    }
                }
            }

            ryan[10] = 0;
            return;
        }

        int shoot = info[idx] + 1;
        if (n >= shoot) {
            ryan[idx] = shoot;
            dfs(n - shoot, idx + 1, ryan, info);
        }
        ryan[idx] = 0;

        dfs(n, idx + 1, ryan, info);
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()` | DFS를 시작하고, 이긴 배치가 없다면 `[-1]`을 반환한다. |
| 2 | `dfs()`의 `shoot` 분기 | 현재 점수를 가져오는 데 필요한 화살을 쓰고 다음 점수로 간다. |
| 3 | `dfs()`의 0발 분기 | 현재 점수를 포기하고 다음 점수로 간다. |
| 4 | `dfs()`의 `idx == 10` | 남은 화살을 0점에 넣고 두 사람의 점수 차이를 계산한다. |
| 5 | `diff > maxDiff` | 더 크게 이겼다면 정답을 교체한다. |
| 6 | `diff == maxDiff` | 동점이면 낮은 점수의 화살 수를 우선 비교한다. |

## 3. 새롭게 배운 내용

### 점수를 가져오는 데 필요한 화살

어피치가 한 점수에 `a`발을 쐈다면 라이언이 그 점수를 얻으려면 `a + 1`발이 필요하다. 같은 개수라면 어피치가 가져간다. 한 칸을 가져올지 포기할지의 선택으로 줄일 수 있는 이유다.

### 같은 화살 수여도 0발과 양수는 다르다

`ryan[i] > info[i]`이면 라이언이 점수를 얻는다. 그렇지 않더라도 어피치가 그 점수에 한 발 이상 쐈을 때만 어피치가 점수를 얻는다. 특히 `ryan[i] == info[i] == 0`이라면 아무도 점수를 얻지 않는다.

### 선택을 되돌리는 백트래킹

`ryan` 배열 하나를 모든 재귀 호출이 공유한다. 가져오는 분기를 탐색한 뒤 `ryan[idx] = 0`으로 되돌려야, 포기하는 분기가 이전 선택의 영향을 받지 않는다. 정답으로 저장할 때는 나중의 변경을 막기 위해 `ryan.clone()`으로 복사한다.

### 동점일 때는 왜 뒤에서 비교할까?

배열 인덱스 `0`은 10점, `10`은 0점이다. 그래서 `i = 10`부터 내려오며 **처음으로 화살 수가 다른 칸**을 찾는다. 그 칸에 더 많이 쏜 배치가 정답이다. 한 번 차이가 나면 더 높은 점수 칸은 비교하지 않으므로 `break`한다.

## 4. 처음 보는 문제에서의 사고 흐름

### 높은 점수부터 쏘면 되지 않을까?

처음에는 10점부터 확인하며 가져올 수 있는 점수에 화살을 쓰는 방법이 자연스럽다. 하지만 목표는 라이언의 점수만 높이는 것이 아니라 **어피치와의 점수 차이를 최대화**하는 것이다. 한 점수를 가져오면 라이언의 점수가 늘고, 어피치가 이미 그 칸을 맞혔다면 어피치의 점수도 막을 수 있다. 반면 그 점수를 가져오는 데 드는 화살 수는 칸마다 다르다. 그래서 점수가 높다는 이유만으로 먼저 고르면 최선인지 확신할 수 없다.

### 그럼 어떤 경우를 시험해야 할까?

한 칸에서 필요한 화살을 무작정 `0`발부터 `n`발까지 모두 시험할 필요는 없다. 10점부터 1점까지는 **가져오기(`info[i] + 1`발) / 포기하기(0발)**로 나눈다. 한 선택을 한 뒤 다음 점수에서도 같은 선택을 반복하므로, 재귀 DFS로 부분집합을 만든다. 주사위 고르기에서 면 하나를 고르고 다음 주사위로 갔던 것처럼, 여기서는 한 점수의 선택을 끝내고 다음 점수로 간다.

| DFS를 쓰기 전에 답할 질문 | 이 문제의 답 |
| --- | --- |
| 한 단계에서 무엇을 선택하나? | 현재 점수를 가져올지 포기할지 |
| 다음 단계로 무엇을 전달하나? | 다음 인덱스와 남은 화살 수 |
| 언제 멈추나? | 0점 칸에 도착했을 때 |
| 그때 무엇을 하나? | 남은 화살을 0점에 넣고 점수 차이를 계산 |

### 왜 모든 경우를 확인할 수 있을까?

10점부터 1점까지 각 칸에 두 선택이 있으므로 최대 `2¹⁰ = 1,024`개 배치를 살펴본다. 화살이 부족한 분기는 중간에 건너뛴다. 따라서 이 문제에서는 여러 선택을 비교하며 최댓값을 찾는 완전탐색이 가능하다.

### 최댓값과 동점 우선순위는 어떻게 관리할까?

배치 하나가 완성될 때마다 `diff = 라이언 점수 - 어피치 점수`를 계산한다. `diff <= 0`인 배치는 우승이 아니다. 더 큰 `diff`를 찾으면 정답을 교체한다. 같은 `diff`라면 0점부터 비교해서 처음 다른 칸에 화살을 더 많이 쏜 배치를 고른다. 즉, **점수 차이 비교가 1순위, 낮은 점수 화살 수 비교가 2순위**다.

## 5. 시간복잡도 / 공간복잡도

- 10점부터 1점까지 최대 10번의 이분 선택을 하므로 완성된 배치는 최대 `2¹⁰ = 1,024`개다.
- 배치마다 길이 11의 배열을 돌며 점수를 계산하고, 동점이면 최대 11칸을 비교한다.
- 시간복잡도는 점수 칸 수를 `m`이라 할 때 `O(2^(m-1) × m)`이며, 이 문제에서는 대략 `1,024 × 11 ≈ 1.1 × 10⁴`칸의 점수 계산에 동점 비교 등의 작업이 더해진다. 흔히 참고하는 `10⁸`회보다 훨씬 작은 규모지만, `10⁸`이 통과를 보장하는 절대 기준은 아니다.
- 재귀 깊이는 최대 10이고 `ryan`, `answer`는 각각 길이 11이므로 보조 공간은 `O(m)`이다.

## 6. 엣지 케이스

- 어피치와 라이언이 같은 수의 화살을 쏘면 어피치가 그 점수를 얻는다. 둘 다 0발이면 아무도 얻지 않는다.
- 남은 화살이 필요한 화살 수와 **같아도** 그 점수를 가져올 수 있으므로 `n >= shoot`를 사용한다.
- 0점 칸에 남은 화살을 모두 넣어 반환 배열의 총합이 정확히 `n`이 되게 한다.
- 점수 차이가 0 이하면 라이언이 우승하지 못한다. 모든 배치에서 우승할 수 없다면 `[-1]`이다.
- 같은 최대 점수 차이가 여러 개라면 0점부터 올라가며 처음 다른 칸을 비교한다.

## 7. 한줄평

높은 점수부터 가져오는 방법이 최선인지는 알 수 없었지만, 각 점수에서 **가져오기/포기하기**로 선택을 줄이니 DFS로 모든 배치를 비교할 수 있었다.

## 8. 더 나은 풀이와 코드 개선

현재 코드는 한 번 호출하는 코딩테스트 환경에서 사용 가능하다. 같은 `Solution` 객체의 `solution()`이 다시 호출될 상황까지 고려한다면, `maxDiff`와 `answer`를 메서드 시작에서 초기화하면 이전 결과가 남지 않는다.

```java
public int[] solution(int n, int[] info) {
    maxDiff = 0;
    answer = new int[11];
    dfs(n, 0, new int[11], info);
    return maxDiff == 0 ? new int[]{-1} : answer;
}
```

점수 계산과 동점 비교를 각각 함수로 분리하면 `dfs()`에는 선택과 되돌리기만 남아 읽기 쉬워진다. 이는 성능보다 역할 구분을 위한 개선이다.
