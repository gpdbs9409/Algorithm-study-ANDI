# 멀리 뛰기 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12914

## 0. 문제 요약

한 번에 1칸 또는 2칸씩 뛰어 정확히 `n`칸에 도착하는 방법의 수를 구한다. **뛰는 순서가 다르면 다른 방법**으로 센다. 결과는 `1,234,567`로 나눈 나머지를 반환한다. `n`은 1 이상 2,000 이하이다.

예를 들어 3칸에 도착하는 방법은 `(1, 1, 1)`, `(1, 2)`, `(2, 1)`의 세 가지다.

## 사용 알고리즘 / 핵심 기법 / 자료구조

| 구분 | 이 문제에서 하는 일 |
| --- | --- |
| 알고리즘: 동적 계획법(DP) | 작은 칸의 방법 수를 이용해 더 큰 칸의 방법 수를 구한다. |
| 핵심 기법: 점화식과 바텀업 계산 | `dp[i] = dp[i-1] + dp[i-2]`를 3칸부터 차례로 계산한다. |
| 자료구조: `int[]` 배열 | 각 칸까지 도착하는 방법의 수를 저장한다. |

## 1. 문제 접근

`i`칸에 도착하기 직전의 점프는 **1칸 또는 2칸** 중 하나다.

```text
(i-1)칸까지 온 방법 + 마지막에 1칸 뛰기 ─┐
                                         ├─ i칸까지 오는 모든 방법
(i-2)칸까지 온 방법 + 마지막에 2칸 뛰기 ─┘
```

`i-1`칸까지 오는 **각 방법의 뒤에 1칸 점프를 붙이면** `i`칸에 도착하는 방법이 하나씩 생긴다. 그래서 마지막에 1칸 뛴 방법의 수는 `dp[i-1]`이다. 마찬가지로 `i-2`칸까지 오는 각 방법 뒤에 2칸 점프를 붙이면 마지막에 2칸 뛴 방법이 `dp[i-2]`개 생긴다. 마지막 점프는 이 두 가지 중 하나이므로 `dp[i] = dp[i-1] + dp[i-2]`다.

예를 들어 4칸까지 오는 방법을 마지막 점프로 나누면 다음과 같다.

```text
3칸까지 온 뒤 +1: (1,1,1,1), (1,2,1), (2,1,1) → dp[3] = 3가지
2칸까지 온 뒤 +2: (1,1,2),   (2,2)          → dp[2] = 2가지
                                              합계 dp[4] = 5가지
```

한 방법의 마지막 점프가 동시에 1칸이면서 2칸일 수는 없다. **서로 겹치지 않고 모든 방법을 빠짐없이 포함**하므로 두 수를 더할 수 있다. `dp[1] = 1`, `dp[2] = 2`에서 시작해 작은 칸부터 계산했다.

처음 코드에서는 `dp[1]`과 `dp[2]`를 바로 초기화했다. 하지만 `n = 1`이면 배열 길이는 2라서 사용할 수 있는 인덱스가 `0`, `1`뿐이다. 이때 `dp[2] = 2`에서 런타임 에러가 난다. 최종 코드에서는 `n == 1`을 먼저 반환한다.

## 2. 문제 코드

```java
class Solution {
    public long solution(int n) {

        if (n == 1) return 1;

        int[] dp = new int[n+1];
        dp[1] = 1;
        dp[2] = 2;
        for (int i = 3; i <= n; i++) {
            dp[i] = (dp[i - 1] + dp[i - 2]) % 1234567;
        }
        return dp[n];
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 `n == 1` | 배열에서 `dp[2]`에 접근할 수 없는 입력을 먼저 처리한다. |
| 2 | `dp[1]`, `dp[2]` | 1칸과 2칸까지 오는 방법의 수를 초기값으로 둔다. |
| 3 | `for (int i = 3; i <= n; i++)` | 이미 계산한 두 칸의 결과로 `dp[i]`를 채운다. |
| 4 | `% 1234567` | 문제에서 요구한 나머지를 매번 저장한다. |
| 5 | `return dp[n]` | 정확히 `n`칸에 도착하는 방법의 수를 반환한다. |

예를 들어 `n = 4`라면 `dp[1] = 1`, `dp[2] = 2`, `dp[3] = 3`, `dp[4] = 5` 순서로 채워진다.

## 3. 새롭게 배운 내용

### 왜 DP를 사용할까?

먼저 `dp[i]`를 **`i`칸까지 오는 방법의 수**라고 정했다. 그러면 큰 칸의 답을 작은 칸의 답으로 표현할 수 있다. `dp[4]`에는 `dp[3]`과 `dp[2]`가 필요하고, `dp[3]`에도 `dp[2]`가 필요하다. `dp[2]`처럼 **같은 작은 문제의 답이 여러 계산에서 다시 쓰이므로** 한 번 계산해 배열에 저장한다. 이것이 이 문제에서 DP를 사용하는 이유다.

여기서 두 가지 ‘겹침’을 구별하자.

| 구분 | 뜻 | 이 문제의 예 |
| --- | --- | --- |
| 경우가 겹침 | 같은 점프 순서를 두 경우에서 중복 집계함 | 3칸을 ‘1칸 점프가 있는 경우’와 ‘2칸 점프가 있는 경우’로 나누면 `(1,2)`, `(2,1)`이 양쪽에 들어간다. |
| 작은 문제가 겹침 | 계산할 때 같은 작은 칸의 답이 반복해서 필요함 | `dp[4]`를 구할 때도, `dp[3]`을 구할 때도 `dp[2]`가 필요하다. |

**경우가 겹치면** 단순히 더해서는 안 된다. **작은 문제가 겹치면** 결과를 저장해 재사용하는 DP를 생각할 수 있다.

### 점프가 1·2·3칸으로 늘어나도 DP일까?

그렇다. 마지막 점프가 1칸, 2칸, 3칸인 경우로 나누면 `dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`가 된다. 다만 이 경우에는 1·2칸 점프만 가능한 현재 코드의 초기값과 계산 범위를 그대로 쓰면 안 된다. 예를 들어 `dp[0] = 1`을 ‘아무 점프도 하지 않고 출발점에 있는 한 가지 방법’으로 두면 `dp[1] = 1`, `dp[2] = 2`, `dp[3] = 4`를 계산할 수 있다.

### 나머지를 중간에 계산해도 될까?

`(a + b) % M`과 `((a % M) + (b % M)) % M`의 결과는 같다. 따라서 매 칸에서 나머지만 저장해도 최종 나머지는 동일하다. 저장된 두 값은 각각 `1,234,567`보다 작으므로 두 값을 더해도 `2,469,132` 이하다. 이 코드의 덧셈은 `int` 범위를 넘지 않는다. 반환형이 `long`인 것은 문제의 함수 형식이며, `int`인 `dp[n]`은 반환할 때 `long`으로 자동 변환된다.

## 4. 처음 보는 문제에서의 사고 흐름

| 문제에서 보이는 단서 | 먼저 할 질문 | 코드로 옮기기 |
| --- | --- | --- |
| “한 번에 1칸 또는 2칸” | 마지막 점프 직전에는 어느 칸에 있었을까? | `i-1` 또는 `i-2` |
| “도착하는 방법의 수” | 두 출발 칸의 방법을 합치면 전체인가? | `dp[i-1] + dp[i-2]` |
| 여러 `i`에서 이전 칸의 결과가 필요 | 같은 결과를 다시 계산할 필요가 있을까? | 배열에 저장하는 DP |
| `n`이 1부터 시작 | 초기값을 둘 배열 인덱스가 항상 있을까? | `n == 1` 먼저 처리 |
| 나머지를 반환 | 큰 값을 끝까지 보관해야 할까? | 매 단계 `% 1234567` |

핵심은 **전체 점프 순서를 바로 나열하기보다 마지막 행동을 기준으로 이전 상태를 찾는 것**이다. 마지막 점프의 길이가 두 가지뿐이므로 두 이전 상태의 답을 합하는 점화식으로 연결된다.

비슷한 문제에서 DP를 떠올릴 때는 다음 순서로 확인한다.

1. **상태:** `i`칸의 답처럼, 작은 문제의 답을 한 가지 의미로 정의할 수 있는가?
2. **관계:** 그 답을 더 작은 상태의 답으로 만들 수 있는가? 여기서는 마지막 점프에 따라 `dp[i-1] + dp[i-2]`다.
3. **재사용:** 같은 작은 상태의 답이 여러 번 필요한가? 여기서는 `dp[2]`가 `dp[3]`, `dp[4]` 계산에 쓰인다.

이 세 가지가 보이면 작은 답을 저장하며 계산하는 DP를 검토한다. 경우의 수를 더할 때는 앞서 확인한 것처럼 각 경우가 서로 겹치지 않는지도 따로 확인한다.

## 5. 시간복잡도 / 공간복잡도

- `3`부터 `n`까지 한 번씩 계산하므로 시간복잡도는 **`O(n)`**이다. 최대 `n = 2,000`이면 반복은 약 `2 × 10³`회다.
- 길이 `n + 1`의 배열을 사용하므로 공간복잡도도 **`O(n)`**이다. 최대 2,001개의 `int`를 저장한다.
- `10⁸`회 정도를 흔히 참고 기준으로 삼더라도, 이 문제의 반복 횟수는 그보다 훨씬 작다. 실제 실행 시간은 연산과 환경에도 영향을 받는다.

## 6. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법 |
| --- | --- |
| 마지막 행동의 종류가 적고, 직전 상태에 따라 답이 결정됨 | 마지막 행동별로 이전 상태를 나눠 점화식을 만든다. |
| 여러 큰 문제에서 같은 작은 문제의 답을 사용함 | 작은 결과를 저장하는 DP를 검토한다. |
| `1`칸·`2`칸 이동처럼 이전 두 상태만 필요함 | 배열로 차례로 계산한다. 저장 공간을 줄여야 한다면 최근 두 값만 유지할 수도 있다. |
