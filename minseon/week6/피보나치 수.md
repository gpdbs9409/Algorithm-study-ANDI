# 피보나치 수 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12945

## 0. 문제 요약

`F(0) = 0`, `F(1) = 1`, `F(n) = F(n-1) + F(n-2)`일 때, `F(n)`을 `1,234,567`로 나눈 나머지를 구한다. `n`은 2 이상 100,000 이하이다.

## 사용 알고리즘 / 핵심 기법 / 자료구조

| 구분 | 이 문제에서 하는 일 |
| --- | --- |
| 알고리즘: 동적 계획법(DP) | 앞서 계산한 피보나치 수를 저장하고 다시 사용한다. |
| 핵심 기법: 바텀업 계산 | `F(0)`, `F(1)`에서 시작해 `F(n)`까지 순서대로 채운다. |
| 자료구조: `int[]` 배열 | 각 인덱스에 해당하는 피보나치 수의 나머지를 보관한다. |

## 1. 문제 접근

문제에 `F(n) = F(n-1) + F(n-2)`가 주어져 있다. 즉, `n`번째 값을 계산하려면 **바로 앞의 두 값**이 필요하다. 먼저 `F(0)`과 `F(1)`을 배열에 넣고, `2`부터 `n`까지 차례로 계산하면 현재 필요한 값이 항상 이미 저장되어 있다.

```text
F(0)=0, F(1)=1
F(2)=0+1=1
F(3)=1+1=2
F(4)=1+2=3
F(5)=2+3=5
```

멀리 뛰기 문제도 이전 두 값을 더했지만, **초기값의 뜻이 다르다**. 멀리 뛰기의 `dp[1]=1`, `dp[2]=2`는 각 칸에 도착하는 방법의 수이고, 이 문제의 `answer[0]=0`, `answer[1]=1`은 문제에서 정의한 피보나치 수다. 점화식만 보고 초기값까지 똑같이 옮기면 다른 답이 나온다.

## 2. 문제 코드

```java
class Solution {
    public int solution(int n) {
        int[] answer = new int[n+1];
        answer[0] = 0;
        answer[1] = 1;

        for(int i=2; i<=n; i++){
            answer[i] = (answer[i-1]+answer[i-2])%1234567;
        }

        return answer[n];
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 `new int[n+1]` | `0`번부터 `n`번까지 값을 저장할 공간을 만든다. |
| 2 | `answer[0]`, `answer[1]` | 문제에서 정한 첫 두 값을 넣는다. |
| 3 | `for (int i=2; i<=n; i++)` | 작은 인덱스부터 계산해 필요한 이전 값이 먼저 준비되게 한다. |
| 4 | `answer[i-1]+answer[i-2]` | 점화식으로 현재 값을 만든다. |
| 5 | `%1234567`, `return answer[n]` | 매번 나머지를 저장하고 `n`번째 결과를 반환한다. |

## 3. 새롭게 배운 내용

### 왜 DP일까?

`F(5)`를 구하려면 `F(4)`와 `F(3)`이 필요하다. 그런데 `F(4)`를 구할 때도 `F(3)`이 필요하다. 재귀로 점화식을 그대로 호출하면 `F(3)` 같은 값을 여러 번 계산할 수 있다. 배열에 각 값을 한 번씩 저장하면 다음 계산에서 그대로 가져올 수 있다. 이것이 이 문제의 **작은 문제의 재사용**이다.

```text
F(5) → F(4) + F(3)
        F(4) → F(3) + F(2)
                ↑ F(3)이 다시 필요함
```

이 코드는 작은 값부터 큰 값까지 채우는 **바텀업 DP**다. `n`이 최대 100,000이므로 한 값씩 차례로 계산하면 된다.

### 왜 매번 나머지를 저장할까?

피보나치 수는 빠르게 커지므로 원래 값을 계속 `int`에 담을 수 없다. 하지만 문제는 최종 나머지만 요구한다. `(a+b)%M`은 `((a%M)+(b%M))%M`과 같으므로, 각 단계에서 나머지만 저장해도 최종 답은 같다. 저장한 두 값은 각각 `1,234,567` 미만이어서 더한 값도 `2,469,132` 이하다. 따라서 이 코드의 덧셈은 `int` 범위 안에 있다.

`answer[0] = 0`은 Java의 `int` 배열이 처음부터 `0`으로 채워지므로 생략할 수도 있다. 현재 코드에서는 `F(0)=0`이라는 초기값을 드러내는 역할을 한다.

## 4. 처음 보는 문제에서의 사고 흐름

| 문제에서 보이는 단서 | 먼저 할 질문 | 코드로 옮기기 |
| --- | --- | --- |
| `F(n)=F(n-1)+F(n-2)` | 현재 값을 만드는 데 무엇이 필요한가? | 이전 두 값을 더한다. |
| 이전 값이 다음 계산에 계속 필요함 | 계산한 값을 어디에 보관할까? | `answer[i]`에 저장한다. |
| `F(0)=0`, `F(1)=1` | 점화식을 적용하기 전 무엇을 알아야 하나? | 두 초기값을 넣고 `i=2`부터 시작한다. |
| `n`이 최대 100,000 | 값을 하나씩 계산해도 가능한가? | 배열을 앞에서부터 한 번 순회한다. |
| `1,234,567`로 나눈 나머지 | 큰 원래 값을 저장할 필요가 있는가? | 계산할 때마다 나머지만 저장한다. |

이 문제는 점화식이 이미 주어져 있다. 따라서 먼저 **초기값, 계산 순서, 저장할 값**을 정하면 코드의 대부분이 결정된다. 다른 DP 문제에서 점화식이 보이지 않는다면 멀리 뛰기처럼 마지막 행동을 하나 되돌려 이전 상태를 찾아보면 된다.

## 5. 시간복잡도 / 공간복잡도

- `2`부터 `n`까지 한 번 계산하므로 시간복잡도는 **`O(n)`**이다. `n=100,000`이어도 약 `10⁵`번 반복한다.
- 길이 `n+1`의 배열을 사용하므로 공간복잡도는 **`O(n)`**이다. 최대 100,001개의 `int`를 저장하며, 원소가 차지하는 공간은 약 400KB다.
- 반복 횟수는 흔히 참고하는 `10⁸`회보다 작다. 실제 실행 시간은 연산과 환경에 따라 달라진다.
