# 네트워크 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43162

## 0. 문제 요약

컴퓨터가 `n`개 있고, `computers[i][j] == 1`이면 `i`번과 `j`번 컴퓨터가 직접 연결되어 있다. 직접 연결되지 않았더라도 다른 컴퓨터를 거쳐 닿을 수 있으면 **같은 네트워크**다. 전체 네트워크의 개수를 반환한다. 컴퓨터의 개수는 최대 200개다.

예를 들어 `0—1—2`가 이어져 있고 `3`은 따로 있다면, 직접 연결된 선은 두 개지만 네트워크는 `{0, 1, 2}`와 `{3}`의 **두 개**다.

## 사용 알고리즘 / 자료구조

- BFS, 큐, 방문 배열, 연결 요소 탐색

## 1. 문제 접근

네트워크의 수를 세려면 우선 한 컴퓨터에서 **직접·간접적으로 이어진 컴퓨터 전체**를 찾아 한 묶음으로 처리해야 한다. 방문하지 않은 컴퓨터를 발견할 때마다 그 컴퓨터에서 BFS를 시작한다. BFS가 끝나면 해당 컴퓨터가 속한 네트워크 전체가 방문 처리되므로 `answer`를 한 번 늘린다.

```text
방문하지 않은 컴퓨터 발견
→ BFS로 그 컴퓨터와 이어진 모든 컴퓨터 방문
→ 네트워크 하나 확인: answer++
→ 다음 방문하지 않은 컴퓨터 탐색
```

입력은 연결 정보를 `computers`라는 인접 행렬로 준다. 현재 컴퓨터 `cur`에서 `0`번부터 `n-1`번까지 확인하며, `computers[cur][next] == 1`이고 아직 방문하지 않은 컴퓨터를 큐에 넣는다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int n, int[][] computers) {
        int answer = 0;
        boolean[] visited = new boolean[n];

        for (int i = 0; i < n; i++) {
            if (!visited[i]) {
                bfs(i, n, computers, visited);
                answer++;
            }
        }

        return answer;
    }

    void bfs(int start, int n, int[][] computers, boolean[] visited) {
        Queue<Integer> q = new ArrayDeque<>();
        q.offer(start);
        visited[start] = true;

        while (!q.isEmpty()) {
            int cur = q.poll();

            for (int next = 0; next < n; next++) {
                if (computers[cur][next] == 1 && !visited[next]) {
                    visited[next] = true;
                    q.offer(next);
                }
            }
        }
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 `visited` | 이미 어느 네트워크에 포함된 컴퓨터인지 기록한다. |
| 2 | `solution()`의 `for`문 | 아직 방문하지 않은 컴퓨터를 찾아 새 네트워크의 시작점으로 삼는다. |
| 3 | `bfs()`의 시작 처리 | 시작점을 큐에 넣고 즉시 방문 표시한다. |
| 4 | `bfs()`의 `while`·`for`문 | 현재 컴퓨터에 직접 연결된 컴퓨터를 확인하며 묶음 전체로 퍼져 나간다. |
| 5 | `solution()`의 `answer++` | BFS 한 번으로 묶음 하나를 모두 찾았으므로 네트워크 수를 늘린다. |

## 3. 새롭게 배운 내용

### 네트워크는 연결선이 아니라 연결된 묶음이다

`0—1—2`에서 `0`과 `2` 사이에 직접 연결선이 없어도 `1`을 거쳐 닿으므로 같은 네트워크다. 따라서 행렬에 적힌 `1`의 수를 세는 것이 아니라, **한 출발점에서 닿을 수 있는 컴퓨터 전체**를 찾아야 한다. 그래프에서는 이런 묶음을 *연결 요소*라고 부른다.

### 방문 표시는 왜 큐에 넣을 때 할까?

어떤 컴퓨터가 여러 컴퓨터와 연결되어 있으면, 방문 표시를 큐에서 꺼낼 때까지 미루는 동안 같은 컴퓨터가 큐에 여러 번 들어갈 수 있다. `visited[next] = true`를 **큐에 넣는 순간** 실행하면 중복 삽입을 막는다.

### 이 BFS에는 왜 별도의 종료 조건이 없을까?

현재 컴퓨터에서 다음에 갈 수 있는 미방문 컴퓨터가 없으면 큐에 새 항목을 넣지 않는다. 큐에 남아 있던 컴퓨터까지 모두 처리하면 `while (!q.isEmpty())`가 끝나고 함수가 자연스럽게 종료된다. 타겟 넘버의 DFS처럼 완료 상태 아래에 무조건 실행되는 재귀 호출이 있는 구조가 아니므로 `return;`을 따로 둘 필요가 없다.

## 4. 처음 보는 문제에서의 사고 흐름

### “연결되어 있다”를 어떻게 세야 할까?

처음에는 직접 연결된 선을 세고 싶을 수 있다. 그러나 `A—B—C`에서는 선이 두 개여도 세 컴퓨터는 같은 네트워크다. 문제의 **간접 연결도 같은 네트워크**라는 문장을 보면, 선 하나씩이 아니라 *도달 가능한 컴퓨터의 묶음*을 세어야 한다는 걸 알 수 있다.

### 묶음 하나를 어떻게 찾을까?

시작 컴퓨터 하나를 정하고 연결된 이웃을 확인한다. 그 이웃에 연결된 컴퓨터도 계속 확인해야 간접 연결까지 찾을 수 있다. 이렇게 **새로 찾은 컴퓨터에서도 같은 일을 반복**하므로 그래프 탐색을 떠올릴 수 있다. 현재 코드는 발견한 컴퓨터를 큐에 넣어 차례대로 확장하는 BFS를 선택했다. DFS로 끝까지 따라가도 같은 묶음을 찾을 수 있다.

### 언제 개수를 늘릴까?

방문하지 않은 시작점에서 BFS를 한 번 실행하면 그 네트워크의 모든 컴퓨터가 `visited`에 표시된다. 그 뒤 같은 네트워크의 다른 컴퓨터에서는 BFS를 다시 시작하지 않는다. 따라서 **새 BFS를 시작할 때마다 네트워크 하나**라고 생각하고 `answer++`를 한 번 한다.

| 문제를 읽으며 던질 질문 | 이 문제의 답 | 코드에서의 역할 |
| --- | --- | --- |
| 무엇을 세나? | 연결된 컴퓨터 묶음의 수 | `answer` |
| 묶음 하나는 어떻게 찾나? | 한 컴퓨터에서 닿을 수 있는 컴퓨터를 모두 탐색 | `bfs()` |
| 같은 묶음을 다시 세지 않으려면? | 한 번 찾은 컴퓨터를 표시 | `visited` |
| 언제 새 묶음인가? | 아직 방문하지 않은 컴퓨터를 발견했을 때 | `solution()`의 `if (!visited[i])` |

## 5. 시간복잡도 / 공간복잡도

- 각 컴퓨터는 큐에서 최대 한 번 꺼내진다. 꺼낼 때마다 길이 `n`인 인접 행렬의 한 행을 확인하므로 시간복잡도는 **`O(n²)`**이다.
- `visited`와 큐는 각각 최대 `n`개 항목을 저장하므로 추가 공간복잡도는 **`O(n)`**이다. 입력 행렬의 공간은 제외한다.
- 최대 `n = 200`일 때 행렬 검사 규모는 `200² = 40,000`칸이다. 흔히 참고하는 `10⁸`회보다 훨씬 작은 규모다.

## 6. 엣지 케이스

- 다른 컴퓨터와 연결되지 않은 컴퓨터도 자기 혼자 **네트워크 하나**를 이룬다.
- 모든 컴퓨터가 간접적으로 이어져 있다면 네트워크는 하나다.
- `computers[i][i] == 1`이더라도 시작점은 이미 방문 표시되어 있으므로 자신을 다시 큐에 넣지 않는다.
- 한 컴퓨터로 여러 경로가 이어져 있어도 큐에 넣을 때 방문 표시하므로 중복 탐색하지 않는다.

## 7. 한줄평

연결선의 개수가 아니라 **연결된 묶음의 개수**를 묻는다는 점을 잡으니, 미방문 컴퓨터마다 BFS를 한 번 실행하는 풀이로 이어졌다.

## 8. 더 나은 풀이와 코드 개선

현재 BFS 코드는 문제 크기에 충분히 적절하다. `n`은 `computers.length`로도 알 수 있으므로 `bfs()`에 따로 전달하지 않고, 외부에서 사용할 필요가 없는 `bfs()`를 `private`으로 선언하면 함수의 역할이 조금 더 분명해진다. 성능상의 필수 수정은 아니다.

DFS로도 묶음 하나를 찾을 수 있다. 탐색 방식만 다르고, 바깥쪽에서 **미방문 시작점마다 `answer++`**하는 구조는 그대로다.

```java
void dfs(int cur, int[][] computers, boolean[] visited) {
    visited[cur] = true;
    for (int next = 0; next < computers.length; next++) {
        if (computers[cur][next] == 1 && !visited[next]) {
            dfs(next, computers, visited);
        }
    }
}
```

## 9. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 이유 |
| --- | --- |
| 직접·간접 연결을 모두 같은 묶음으로 취급 | 한 시작점에서 닿는 정점을 모두 찾는 BFS/DFS |
| 전체 묶음의 개수를 구함 | 미방문 정점마다 탐색을 시작하고 탐색 횟수 세기 |
| 입력이 연결 여부를 `n × n` 표로 줌 | 현재 정점의 행을 훑어 이웃 찾기 |
| 같은 정점으로 여러 경로가 이어질 수 있음 | 방문 표시로 중복 탐색 방지 |
