# 타겟 넘버 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43165

## 0. 문제 요약

주어진 숫자의 순서를 바꾸지 않고 각 숫자 앞에 `+` 또는 `-`를 붙인다. 모든 숫자를 사용한 결과가 `target`이 되는 **방법의 수**를 반환한다. 숫자는 2개 이상 20개 이하이고, 각 숫자는 1 이상 50 이하이다.

예를 들어 `[1, 1, 1, 1, 1]`로 `3`을 만드는 방법은 다섯 가지다. 숫자 값이 같더라도 **어느 위치의 숫자에 `-`를 붙였는지**가 다르면 서로 다른 방법으로 센다.

## 사용 알고리즘 / 자료구조

- DFS(재귀), 완전탐색

## 1. 문제 접근

숫자 하나를 처리할 때 가능한 선택은 **더하기 또는 빼기** 두 가지다. 현재까지의 합 `sum`과 다음에 처리할 위치 `idx`를 가지고, 두 선택을 각각 재귀 호출로 이어 간다.

```text
현재 숫자를 더한다 → dfs(sum + numbers[idx], idx + 1)
현재 숫자를 뺀다  → dfs(sum - numbers[idx], idx + 1)
```

`idx == numbers.length`가 되면 모든 숫자에 부호를 붙인 상태다. 이때 완성된 `sum`이 `target`과 같다면 정답을 1 늘리고, 해당 경로의 탐색을 끝낸다. 숫자마다 두 갈래로 나누므로 가능한 모든 부호 배치를 확인할 수 있다.

## 2. 문제 코드

```java
class Solution {
    int answer = 0;

    public int solution(int[] numbers, int target) {
        dfs(numbers, target, 0, 0);
        return answer;
    }

    void dfs(int[] numbers, int target, int sum, int idx) {
        if (idx == numbers.length) {
            if (sum == target) {
                answer++;
            }
            return;
        }

        dfs(numbers, target, sum + numbers[idx], idx + 1);
        dfs(numbers, target, sum - numbers[idx], idx + 1);
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()` | `sum = 0`, `idx = 0`에서 DFS를 시작한다. |
| 2 | `dfs()`의 `idx == numbers.length` | 모든 숫자를 사용했는지 확인한다. |
| 3 | `dfs()`의 `sum == target` | 완성된 계산 결과가 목표와 같을 때만 `answer`를 늘린다. |
| 4 | `dfs()`의 `return` | 완성된 경로가 아래의 재귀 호출로 내려가지 않도록 끝낸다. |
| 5 | 두 번의 `dfs()` 호출 | 현재 숫자에 `+`와 `-`를 붙인 경우를 각각 탐색한다. |

## 3. 새롭게 배운 내용

### `return;`은 왜 필요할까?

`dfs()`가 `void`여도 `return;`으로 **이번 호출을 여기서 끝낼 수 있다**. `idx == numbers.length`에서 결과를 평가한 뒤 `return;`하지 않으면 아래 재귀 호출이 실행되어 `numbers[idx]`에 접근한다. 이때 `idx`는 배열 길이와 같으므로 범위를 벗어난다.

피로도 문제처럼 다음 후보를 확인하는 `for`문만 남아 있고 후보가 없으면 함수가 자연스럽게 끝나는 DFS도 있다. 이 코드에서는 종료 조건 아래에 **무조건 실행되는 재귀 호출**이 있으므로 명시적으로 멈춰야 한다.

### 왜 `visited`나 원상복구가 없을까?

각 호출에서 `idx + 1`로 다음 숫자로 이동하므로 한 경로에서 같은 숫자를 다시 선택하지 않는다. 따라서 `visited`가 필요 없다. `sum`은 `int` 값을 다음 호출에 전달한다. `sum + numbers[idx]`를 전달한 호출이 끝나도 현재 호출의 `sum`은 바뀌지 않으므로, 배열을 직접 수정하는 백트래킹처럼 원상복구할 값도 없다.

### 같은 숫자가 반복되어도 두 가지 선택을 모두 세는 이유

문제는 서로 다른 숫자 값의 조합이 아니라 **각 위치에 어떤 부호를 붙였는지**를 센다. `[1, 1]`의 첫 번째 `1`을 더하고 두 번째 `1`을 빼는 선택과, 첫 번째를 빼고 두 번째를 더하는 선택은 합이 같아도 다른 경로다. 그러므로 두 분기를 합치거나 중복 제거하지 않는다.

## 4. 처음 보는 문제에서의 사고 흐름

### 한 숫자라면 어떻게 풀까?

숫자가 하나라면 `+numbers[0]`과 `-numbers[0]`을 직접 비교하면 된다. 두 숫자라면 첫 번째에서 `+/-`를 고른 뒤, 각 경우마다 두 번째에서도 `+/-`를 골라 네 가지를 확인한다.

```text
숫자 [1, 2]
             +1 ┬─ +2 →  3
                └─ -2 → -1
시작 0
             -1 ┬─ +2 →  1
                └─ -2 → -3
```

숫자가 늘 때마다 **같은 두 선택을 한 단계 더 반복**해야 한다. 숫자 개수에 맞춰 중첩 반복문을 계속 작성할 수는 없으므로, 한 단계의 선택을 함수로 표현한다. 한 경로를 끝까지 따라간 뒤 다른 부호 선택을 확인하므로 DFS가 된다.

### DFS 코드를 쓰기 전에 무엇을 정할까?

| 먼저 답할 질문 | 이 문제의 답 | 코드에 나타나는 부분 |
| --- | --- | --- |
| 한 단계에서 무엇을 선택하나? | 현재 숫자를 더할지 뺄지 | 두 번의 `dfs()` 호출 |
| 다음 단계에서 무엇이 달라지나? | 합과 처리할 숫자의 위치 | `sum ± numbers[idx]`, `idx + 1` |
| 언제 경로가 완성되나? | 모든 숫자에 부호를 붙였을 때 | `idx == numbers.length` |
| 완성된 경로에서 무엇을 확인하나? | 결과가 `target`인지 | `sum == target`이면 `answer++` |

모든 경우를 보는 방법이 가능한지도 확인한다. 숫자가 `n`개면 부호 배치는 `2ⁿ`가지이고, 최대 `n = 20`일 때 `2²⁰ = 1,048,576`가지다. 이 문제에서는 모든 부호 선택을 탐색할 수 있는 규모다.

## 5. 시간복잡도 / 공간복잡도

- 숫자마다 두 갈래로 나뉘므로 시간복잡도는 **`O(2ⁿ)`**이다. 모든 호출까지 세면 최대 `2^(n+1) - 1`개이며, `n = 20`에서 약 210만 번이다.
- 재귀 깊이는 숫자의 개수만큼이므로 보조 공간복잡도는 **`O(n)`**이다.
- 최대 경우의 수는 약 `10⁶`, 전체 호출은 약 `2 × 10⁶` 규모다. 흔히 참고하는 `10⁸`회보다 작지만 실제 통과 여부는 연산 내용과 환경에도 영향을 받는다.

## 6. 엣지 케이스

- 목표값에 도달하지 못하는 경로는 세지 않는다. 모든 경로가 실패하면 `0`을 반환한다.
- 중간 합이 `target`과 같아도 남은 숫자를 모두 사용해야 하므로 탐색을 끝내면 안 된다.
- 숫자 값이 같아도 서로 다른 위치에서 `+/-`를 선택한 경로는 각각 센다.
- 종료 조건에서 `return;`하지 않으면 `numbers[numbers.length]`에 접근하게 된다.

## 7. 한줄평

한 숫자에 `+/-`를 선택하는 일을 모든 숫자에 반복한다고 생각하니, DFS의 분기·상태·종료 조건을 직접 정할 수 있었다.

## 8. 더 나은 풀이와 코드 개선

현재 코드는 문제를 푸는 데 충분하다. 다만 같은 `Solution` 객체로 `solution()`을 다시 호출할 가능성까지 고려하면 메서드 시작에서 `answer = 0;`으로 초기화하는 편이 안전하다. 사용하지 않는 `import java.util.*;`도 생략할 수 있다.

```java
public int solution(int[] numbers, int target) {
    answer = 0;
    dfs(numbers, target, 0, 0);
    return answer;
}
```

## 9. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 이유 |
| --- | --- |
| 각 원소마다 두 가지 선택을 하고 가능한 모든 결과를 세어야 함 | 선택/비선택 또는 `+/-` 분기로 완전탐색 검토 |
| 선택을 여러 단계 반복하고 단계 수가 입력에 따라 달라짐 | 한 단계의 규칙을 재귀 DFS로 표현 |
| 상태가 숫자처럼 값으로 전달됨 | 다음 호출에 새 값을 전달하고 별도 원상복구는 생략 가능 |
| 배열 등을 직접 바꾸며 분기를 탐색함 | 다른 분기로 가기 전에 상태를 원상복구해야 하는지 확인 |
