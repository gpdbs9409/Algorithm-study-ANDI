# n + 1 카드게임 (프로그래머스 Lv.3)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/258707

## 0. 문제 요약

`1`부터 `n`까지 적힌 카드가 한 장씩 있다. 처음에는 앞의 `n/3`장을 동전 없이 가지고 시작한다. 이후 매 라운드에 카드 두 장을 뽑으며, 새 카드는 장당 동전 1개를 써서 가지거나 버릴 수 있다.

매 라운드 **합이 `n+1`인 카드 두 장**을 내야 다음 라운드로 넘어간다. 도달할 수 있는 최대 라운드를 구한다. 카드 수 `n`은 6의 배수이며 `6 ≤ n < 1,000`이다.

예를 들어 `n=12`라면 카드 `3`의 짝은 `10`, 카드 `6`의 짝은 `7`이다. 각 카드의 짝은 항상 **`n+1-카드` 한 장으로 정해진다.**

## 사용 알고리즘 / 자료구조

- 제출용 풀이: 그리디, `HashSet`
- 다른 접근: DFS, 백트래킹, 비트마스크

## 1. 문제 접근

처음에는 가진 카드 목록에서 합이 `n+1`인 두 장을 찾아 제거하고, 다음 라운드로 넘어가는 DFS를 생각했다. 한 라운드에는 다음 선택이 있다.

```text
새 카드 두 장을 각각 살지 버릴지 선택
→ 현재 가진 카드 중 낼 쌍 선택
→ 다음 라운드 탐색
```

하지만 새 카드 두 장의 구매 방법만 해도 매 라운드 최대 4가지다. 낼 수 있는 쌍이 여러 개면 그 선택도 갈라진다. 최대 입력에서는 모든 경우를 DFS로 탐색하기 어렵다.

그래서 **두 카드를 내는 데 드는 동전 수**를 기준으로 생각했다.

| 사용할 카드 | 필요한 동전 |
| --- | ---: |
| 처음부터 가진 카드 + 처음부터 가진 카드 | 0개 |
| 처음부터 가진 카드 + 새로 나온 카드 | 1개 |
| 새로 나온 카드 + 새로 나온 카드 | 2개 |

합이 `n+1`인 서로 다른 쌍은 카드를 공유하지 않는다. 카드 `x`의 짝이 `n+1-x`로 하나뿐이기 때문이다. 따라서 한 라운드에서는 **사용 가능한 쌍 중 동전이 가장 적게 드는 쌍**을 먼저 낸다. 남은 쌍은 이후 라운드에도 사용할 수 있다.

이를 위해 카드를 두 집합으로 관리한다.

- `hand`: 처음부터 동전 없이 가지고 있던 카드 중 아직 내지 않은 카드
- `opened`: 라운드에서 새로 공개됐고 아직 내지 않은 카드

`opened`에 넣는 순간 동전을 차감하지 않는다. 그 카드를 실제로 쌍에 사용할 때 비용을 계산한다. 새 카드를 언제 사용할지 나중에 결정해도, 동전을 쓰는 전체 횟수는 같다.

매 라운드 다음 순서로 쌍을 찾는다.

```text
hand + hand 쌍이 있나?                → 있으면 사용 (동전 0개)
없다면 hand + opened 쌍이 있나?      → 있으면 사용 (동전 1개)
없다면 opened + opened 쌍이 있나?    → 있으면 사용 (동전 2개)
모두 없다면 게임 종료
```

문제의 예시에서 처음 가진 카드가 `3, 6, 7, 2`이고 첫 라운드에 `1, 10`이 나왔다고 하자. 문제 설명에서는 동전 2개로 `1, 10`을 모두 가진 뒤 `3+10`을 낸다. **그것은 가능한 진행 방법 중 하나**다. 이 풀이에서는 첫 라운드에 동전이 필요 없는 `6+7`을 먼저 내고, `1, 10`은 이후에 필요한 쌍을 만들 때 사용한다. 어느 방법이든 최대 5라운드에 도달할 수 있다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int coin, int[] cards) {
        int n = cards.length;
        int target = n + 1;

        Set<Integer> hand = new HashSet<>();
        Set<Integer> opened = new HashSet<>();

        for (int i = 0; i < n / 3; i++) {
            hand.add(cards[i]);
        }

        int idx = n / 3;
        int round = 1;

        while (idx + 1 < n) {
            opened.add(cards[idx++]);
            opened.add(cards[idx++]);

            if (usePair(hand, hand, target)) {
                round++;
            } else if (coin >= 1 && usePair(hand, opened, target)) {
                coin--;
                round++;
            } else if (coin >= 2 && usePair(opened, opened, target)) {
                coin -= 2;
                round++;
            } else {
                break;
            }
        }

        return round;
    }

    private boolean usePair(Set<Integer> first, Set<Integer> second, int target) {
        int chosen = -1;
        int partner = -1;

        for (int card : first) {
            int needed = target - card;

            if (second.contains(needed)) {
                chosen = card;
                partner = needed;
                break;
            }
        }

        if (chosen == -1) {
            return false;
        }

        first.remove(chosen);
        second.remove(partner);
        return true;
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 첫 `for`문 | 처음 받는 `n/3`장의 카드를 `hand`에 저장한다. |
| 2 | `solution()`의 `while`문 | 매 라운드 새 카드 두 장을 `opened`에 추가한다. |
| 3 | `usePair(hand, hand, target)` | 동전 없이 낼 수 있는 쌍을 먼저 찾는다. |
| 4 | `usePair(hand, opened, target)` | 없으면 동전 1개로 낼 수 있는 쌍을 찾는다. |
| 5 | `usePair(opened, opened, target)` | 그래도 없으면 동전 2개로 낼 수 있는 쌍을 찾는다. |
| 6 | `usePair()`의 `remove()` | 낸 카드 두 장을 제거해 다음 라운드에서 다시 쓰지 못하게 한다. |
| 7 | `round++` 또는 `break` | 쌍을 냈으면 다음 라운드로, 낼 수 없으면 게임을 종료한다. |

`usePair()`는 첫 집합의 카드 `x`를 보며 두 번째 집합에 `n+1-x`가 있는지 확인한다. `hand`를 두 번 넘기면 처음 가진 카드끼리의 쌍을 찾고, `hand`와 `opened`를 넘기면 서로 다른 출처의 카드를 한 장씩 찾는다. 카드를 찾는 `for`문이 끝난 **뒤에** 두 집합에서 제거하므로, 집합을 순회하는 도중 수정하지 않는다.

## 3. 새롭게 배운 내용

### 각 카드의 짝은 하나뿐이다

처음에는 “여러 쌍 중 무엇을 먼저 내야 하지?”라는 고민이 생길 수 있다. 하지만 목표 합이 고정되어 있으므로 카드 `x`의 짝은 `n+1-x`로 정해진다.

```text
n = 12 → 목표 합 13

3 ↔ 10
6 ↔ 7
1 ↔ 12
2 ↔ 11
```

`3+10`과 `6+7`은 카드를 공유하지 않는다. 따라서 `6+7`을 먼저 낸다고 해서 `3+10`을 낼 가능성이 사라지지 않는다. 이 성질을 알면 모든 쌍의 사용 순서를 DFS로 탐색할 필요가 있는지 다시 생각할 수 있다.

### `opened`에 카드를 보관하면서 동전을 바로 쓰지 않아도 될까?

코드에서는 새 카드를 `opened`에 추가할 때 동전을 차감하지 않는다. 이는 **새 카드를 실제로 사용할 때 구매 비용을 계산하는 표현**이다.

예를 들어 새로 나온 `10`이 나중에 처음 가진 `3`과 함께 쓰이면 그때 동전 1개를 차감한다. 끝까지 사용하지 않는 카드는 동전을 쓰지 않고 버린 것과 같다. 동전은 중간에 새로 생기지 않으므로, 사용할 카드를 공개 시점에 미리 사 두는 경우와 사용 시점에 비용을 계산하는 경우의 동전 총량은 같다.

### 왜 라운드를 1부터 셀까?

게임은 **1라운드부터 시작**한다. 첫 라운드에서 낼 쌍이 없어도 도달한 최대 라운드는 `1`이다. 쌍을 내는 데 성공하면 *다음 라운드에 도달*하므로 `round++` 한다.

마지막 카드 두 장을 뽑은 라운드에서 쌍을 내는 데 성공했다면, 다음 라운드에 도달한 뒤 카드 뭉치가 비어 종료된다. 이때도 증가한 라운드가 답이다.

## 4. 처음 보는 문제에서의 사고 흐름

### “매 라운드 카드를 사고 버리고 쌍도 고른다” → 왜 DFS가 먼저 떠오를까?

한 라운드에 선택이 여러 번 일어나고, 그 선택에 따라 다음 라운드의 카드와 동전 상태가 달라진다. 처음에는 **현재 가능한 선택을 모두 해 보고 다음 라운드로 들어가는 DFS**를 떠올릴 수 있다. 실제로 작은 입력에서는 DFS로 답을 구할 수 있다.

이때 DFS의 한 단계는 “한 라운드 진행하기”다. 재귀 함수에는 현재 카드 위치, 남은 동전, 현재 라운드와 보유 카드 상태가 필요하다.

### “카드가 최대 1,000장 가까이 있다” → 왜 DFS를 그대로 제출하기 어려울까?

새 카드 두 장을 각각 살지 버릴지만 따져도 매 라운드 최대 4갈래다. 이런 선택이 수백 라운드 이어지면 경우의 수가 급격히 늘어난다. **모든 경우를 구분해야 하는지** 확인해야 한다.

여기서 카드의 짝이 하나뿐이라는 점을 발견한다. 서로 다른 완성된 쌍은 카드를 공유하지 않는다. 따라서 중요한 것은 모든 순서를 나열하는 일이 아니라, **매 라운드에 동전을 얼마나 쓰고 쌍 하나를 낼 수 있는가**다.

### “동전을 아끼면서 다음 라운드로 가야 한다” → 왜 그리디일까?

지금 사용할 수 있는 쌍을 동전 비용 0개, 1개, 2개로 나눈다. 0개짜리 쌍을 먼저 사용하면 다른 쌍을 없애지 않으면서 동전을 보존할 수 있다. 0개짜리가 없을 때만 1개짜리를, 그것도 없을 때만 2개짜리를 쓴다.

즉, **한 라운드에서 당장 동전이 가장 적게 드는 선택**을 한다. 이 선택이 가능한 이유를 카드의 고유한 짝 관계로 확인했으므로 그리디 풀이로 이어진다.

| 문제를 읽으며 던질 질문 | 이 문제에서 확인한 것 |
| --- | --- |
| 한 단계에서 선택이 갈라지나? | 새 카드의 구매 여부와 낼 쌍이 달라진다. DFS를 생각할 수 있다. |
| 모든 선택을 탐색할 수 있나? | 최대 수백 라운드이므로 어렵다. |
| 선택들 사이에 어떤 관계가 있나? | 한 카드의 짝은 하나뿐이고, 서로 다른 쌍은 카드를 공유하지 않는다. |
| 무엇을 우선해야 하나? | 다음 라운드로 진행하면서 동전을 가장 적게 쓰는 쌍이다. |

## 5. 시간복잡도 / 공간복잡도

### 제출용 풀이

- 한 라운드에서 `usePair()`를 최대 세 번 호출하고, 각 호출은 집합의 카드를 최대 `O(n)`개 확인한다. `HashSet.contains()`는 평균적으로 `O(1)`이다.
- 라운드는 최대 `n/3`번 진행하므로 **시간복잡도는 평균 `O(n²)`**이다.
- 두 집합이 저장하는 카드는 전체 `n`장을 넘지 않으므로 **추가 공간복잡도는 `O(n)`**이다.

최대 조건에서 6의 배수인 가장 큰 `n`은 `996`이다. 확인 가능한 라운드는 `996/3 = 332`번이며, 라운드마다 최대 세 차례 집합을 훑는다고 넉넉히 잡아도 약 `332 × 3 × 996 ≈ 9.9 × 10⁵`번의 카드 확인 규모다. 흔히 참고하는 `10⁸`회보다 작지만, `10⁸`은 실행 시간을 보장하는 절대 기준은 아니다.

### DFS 풀이

매 라운드 카드 구매 방법이 최대 4가지이고, 낼 수 있는 쌍에 따라 탐색이 더 갈라진다. 라운드가 늘어날수록 경우의 수가 **지수적으로 증가**하므로 최대 입력에서 제출용으로 적합하지 않다.

## 6. 엣지 케이스

- 처음 가진 카드에 낼 수 있는 쌍이 없다면, 새로 뽑은 카드가 필요할 수 있다.
- 동전이 0개여도 `hand + hand` 쌍이 있으면 다음 라운드로 갈 수 있다.
- 동전이 1개뿐이면 `opened + opened` 쌍이 있어도 두 장을 살 수 없다.
- 쌍을 냈다면 두 카드 모두 제거해야 한다. 하나라도 남겨 두면 같은 카드를 다시 사용할 수 있다.
- 쓸 수 있는 쌍이 없으면 남은 카드가 있더라도 바로 게임이 끝난다.
- 카드 뭉치가 비어도 마지막에 성공적으로 넘어온 라운드는 답에 포함한다.

## 7. 한줄평

처음에는 선택이 많아 DFS를 떠올렸지만, **각 카드의 짝은 하나뿐이라는 점**을 확인하니 동전을 적게 쓰는 쌍부터 선택할 수 있었다.

## 8. 다른 풀이: DFS로 모든 선택 탐색하기

DFS는 이 문제의 선택 구조를 이해하는 데 도움이 된다. 아래 코드는 **작은 입력에서 모든 경우를 확인하는 학습용 풀이**다. 최대 입력에서는 시간 초과가 날 수 있다.

```java
class Solution {
    private int maxRound;
    private int[] cards;
    private boolean[] hand;
    private int n;

    public int solution(int coin, int[] cards) {
        this.cards = cards;
        this.n = cards.length;
        this.hand = new boolean[n + 1];
        this.maxRound = 1;

        for (int i = 0; i < n / 3; i++) {
            hand[cards[i]] = true;
        }

        dfs(n / 3, coin, 1);
        return maxRound;
    }

    private void dfs(int idx, int coin, int round) {
        maxRound = Math.max(maxRound, round);

        if (idx + 1 >= n) {
            return;
        }

        int first = cards[idx];
        int second = cards[idx + 1];

        for (int choice = 0; choice < 4; choice++) {
            int cost = Integer.bitCount(choice);
            if (cost > coin) {
                continue;
            }

            if ((choice & 1) != 0) hand[first] = true;
            if ((choice & 2) != 0) hand[second] = true;

            for (int card = 1; card <= n / 2; card++) {
                int partner = n + 1 - card;

                if (!hand[card] || !hand[partner]) {
                    continue;
                }

                hand[card] = false;
                hand[partner] = false;

                dfs(idx + 2, coin - cost, round + 1);

                hand[card] = true;
                hand[partner] = true;
            }

            if ((choice & 1) != 0) hand[first] = false;
            if ((choice & 2) != 0) hand[second] = false;
        }
    }
}
```

### DFS 코드 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()` | 처음 받는 카드의 `hand[카드 번호]`를 `true`로 표시한다. |
| 2 | `dfs(idx, coin, round)` 시작 | 현재 라운드에 도달했으므로 `maxRound`를 갱신한다. |
| 3 | `choice` 반복문 | 이번에 나온 카드 두 장을 각각 살지 버릴지 네 방법을 시도한다. |
| 4 | `Integer.bitCount(choice)` | 이번 선택에서 구매한 카드 수, 즉 필요한 동전 수를 센다. |
| 5 | 카드 쌍 탐색 `for`문 | 현재 가진 카드 중 합이 `n+1`인 쌍을 찾아 낸다. |
| 6 | `dfs(idx + 2, ...)` | 낸 쌍을 제외한 상태로 다음 라운드를 탐색한다. |
| 7 | 재귀 호출 뒤의 `hand[...] = true/false` | 다른 선택을 시도하기 위해 카드 상태를 원상복구한다. |

### `Integer.bitCount()`는 무엇인가?

`Integer.bitCount(x)`는 정수 `x`를 이진수로 나타냈을 때 **1의 개수**를 반환한다. 이 코드에서는 비트 두 개가 각각 새 카드 한 장의 구매 여부를 나타낸다.

| `choice` | 이진수 | 첫 카드 | 둘째 카드 | `Integer.bitCount(choice)` |
| ---: | :---: | :---: | :---: | ---: |
| 0 | `00` | 버림 | 버림 | 0 |
| 1 | `01` | 삼 | 버림 | 1 |
| 2 | `10` | 버림 | 삼 | 1 |
| 3 | `11` | 삼 | 삼 | 2 |

예를 들어 `choice=3`은 이진수 `11`이다. `1`이 두 개이므로 카드 두 장을 사고 동전 2개를 사용한다. `choice=2`는 `10`이라 둘째 카드만 사고 동전 1개를 사용한다.

`(choice & 1) != 0`은 첫 번째 비트가 켜져 있는지, `(choice & 2) != 0`은 두 번째 비트가 켜져 있는지 확인한다. 비트 연산이 낯설다면 `choice`의 네 경우를 각각 `if`문으로 작성해도 같은 DFS를 만들 수 있다. 여기서는 **두 카드의 구매 조합 네 가지를 짧게 표현**하려고 사용했다.

### 왜 상태를 되돌릴까?

`hand` 배열 하나를 여러 DFS 분기가 함께 사용한다. 한 분기에서 카드를 샀거나 쌍을 냈다면, 다음 분기를 시작하기 전에 그 변경을 취소해야 한다.

```text
카드 두 장 구매 여부 표시
→ 가능한 쌍 하나를 제거
→ 다음 라운드 DFS
→ 제거한 쌍 복구
→ 이번 선택에서 구매한 카드 복구
→ 다음 선택 시도
```

복구하지 않으면 **이전 분기의 선택이 다음 분기에 남아**, 실제로는 불가능한 카드 상태를 탐색하게 된다.

쌍을 찾는 반복문에서 `card <= n/2`까지만 보는 이유는 `3+10`을 확인한 뒤 `10+3`을 같은 쌍으로 다시 확인하지 않기 위해서다.

| 문제에서 보이는 특징 | 떠올릴 접근과 확인할 점 |
| --- | --- |
| 매 단계 여러 선택을 하고, 선택에 따라 다음 상태가 달라짐 | 먼저 DFS·백트래킹으로 선택을 표현할 수 있는지 생각한다. |
| 단계 수가 많아 모든 선택을 탐색하기 어려움 | 선택들 사이의 중복이나 독립 관계를 찾아 경우의 수를 줄인다. |
