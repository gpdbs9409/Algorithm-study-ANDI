# 전화번호 목록 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42577

## 0. 문제 요약

전화번호 목록에서 **어떤 번호가 다른 번호의 접두사인지** 확인한다. 그런 관계가 하나라도 있으면 `false`, 없으면 `true`를 반환한다.

예를 들어 `"119"`는 `"1195524421"`의 접두사다. 전화번호는 최대 `10⁶`개이고, 각 번호의 길이는 최대 20자다. 같은 전화번호가 중복되어 주어지지는 않는다.

## 사용 알고리즘 / 자료구조

- 해시 (`HashMap`)

## 1. 문제 접근

먼저 모든 전화번호를 `HashMap`에 저장했다. 그다음 각 번호에서 가능한 **자기 자신보다 짧은 접두사**를 하나씩 만들어, 그 접두사가 전화번호 목록에 있는지 확인했다.

```text
전화번호 "1195524421"의 접두사:
"1", "11", "119", "1195", ...

목록에 "119"가 있으면 다른 번호의 접두사이므로 false를 반환한다.
```

이 방법에서는 각 번호의 모든 접두사를 확인하지만, 목록 전체를 매번 순회하지 않는다. 만들어진 접두사가 실제 전화번호인지 `map.containsKey()`로 바로 확인한다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public boolean solution(String[] phone_book) {
        Map<String, Integer> map = new HashMap<>();

        for (String s : phone_book) {
            map.put(s, 1);
        }

        for (String key : map.keySet()) {
            for (int i = 1; i < key.length(); i++) {
                String prefix = key.substring(0, i);

                if (map.containsKey(prefix)) {
                    return false;
                }
            }
        }

        return true;
    }
}
```

### 코드 구현 흐름

1. **전화번호 저장 — 첫 번째 `for`문**: 모든 번호를 `HashMap`의 키로 저장했다. 값 `1`은 실제 판단에 사용하지 않는다.
2. **번호별 접두사 생성 — 두 번째 `for`문과 `substring()`**: 길이 1부터 `key.length() - 1`까지 접두사를 만들었다.
3. **접두사 확인 — `containsKey()`**: 만든 접두사와 정확히 일치하는 전화번호가 있으면 즉시 `false`를 반환했다.
4. **검사 완료 — 마지막 `return`**: 끝까지 그런 번호를 찾지 못했으면 `true`를 반환했다.

## 3. 새롭게 배운 내용

### `substring(0, i)`의 끝 인덱스

Java의 `substring(begin, end)`는 `begin` 위치부터 **`end` 바로 앞까지** 가져온다. `end` 위치의 문자는 포함하지 않는다.

```text
key = "119"

i = 1 → key.substring(0, 1) = "1"
i = 2 → key.substring(0, 2) = "11"
```

반복 조건이 `i < key.length()`이므로 `i = 3`은 실행되지 않는다. 따라서 `"119"`를 자기 자신의 접두사로 검사하지 않는다. 대신 더 긴 번호 `"1195524421"`을 검사할 때 `i = 3`에서 `"119"`가 만들어진다.

### 해시는 접두사를 찾아주는가?

해시가 접두사를 자동으로 찾는 것은 아니다. 코드는 먼저 `substring()`으로 접두사를 만들고, 해시 자료구조로 **그 문자열이 전화번호 목록에 정확히 존재하는지** 확인한다.

```text
접두사 만들기: substring()
목록에 있는지 확인하기: containsKey()
```

`HashMap`이나 `HashSet`의 존재 여부 확인은 평균적으로 빠르다. 다만 문자열을 만드는 시간과 문자열의 해시를 계산하는 시간도 있으므로, 문자열 길이까지 포함한 분석에서는 한 번의 검사를 무조건 `O(1)`이라고만 보지는 않는다.

## 4. 처음 보는 문제에서의 사고 흐름

1. **무엇을 찾아야 하는지 바꿔 말한다.** 어느 한 번호가 다른 번호의 *시작 부분*과 일치하는지 확인하는 문제다.
2. **모든 쌍을 비교해도 되는지 입력 크기를 본다.** 전화번호가 최대 `10⁶`개라서 두 번호씩 모두 비교하면 최대 약 `10¹²`쌍이다. 이 방법은 피해야 한다.
3. **비교 방향을 뒤집는다.** 다른 번호들을 하나씩 찾기보다, 현재 번호에서 가능한 접두사를 만든다. 번호 길이가 최대 20자이므로 자기 자신을 제외한 접두사는 최대 19개뿐이다.
4. **필요한 연산에 맞는 자료구조를 고른다.** 만든 접두사와 *정확히 같은 번호*가 목록에 있는지만 확인하면 된다. 그래서 빠른 존재 여부 확인이 가능한 해시를 사용한다.
5. **자기 자신을 검사하지 않는지 확인한다.** 접두사 길이를 `1`부터 `key.length() - 1`까지만 늘린다.

핵심은 “번호끼리 전부 비교”에서 “각 번호가 만들 수 있는 짧은 접두사만 확인”으로 관점을 바꾸는 것이다.

## 5. 시간복잡도 / 공간복잡도

전화번호 개수를 `n`, 번호의 최대 길이를 `L`이라고 하자. 이 문제에서 `n ≤ 10⁶`, `L ≤ 20`이다.

- 해시에 전화번호 저장: 평균적으로 `O(nL)`.
- 접두사 검사: 번호마다 최대 `L - 1`개를 만들고, 각 접두사의 생성·해시 계산에 길이만큼 시간이 들 수 있어 `O(nL²)`.
- 전체 시간복잡도: 평균적인 해시 동작을 가정하면 `O(nL²)`.
- 공간복잡도: 전화번호를 해시에 보관하므로 `O(nL)`.

최대 입력에서 접두사 존재 여부를 확인하는 횟수는 `10⁶ × 19 = 1.9 × 10⁷`회 이하이고, 각 접두사는 최대 19자로 짧다. 반면 모든 전화번호 쌍을 비교하면 약 `(10⁶)² = 10¹²`쌍까지 늘어날 수 있다. 따라서 이 문제에서는 모든 쌍을 비교하는 방식보다 해시 조회 방식이 훨씬 적합하다.

`10⁸`회는 대략적인 감을 잡는 기준이다. 문자열 생성·해시 계산의 비용과 실행 환경에 따라 실제 시간은 달라지므로, 이 숫자만으로 통과 여부를 단정하지 않는다.

## 6. 엣지 케이스

- 전화번호가 하나뿐이면 다른 번호의 접두사가 될 수 없으므로 `true`다.
- 길이가 1인 번호는 자기보다 짧은 접두사가 없어 안쪽 반복문이 실행되지 않는다. 더 긴 번호에서 이 한 글자가 접두사인지 검사한다.
- `"12"`와 `"123"`이 함께 있으면 `"12"`가 접두사이므로 `false`다.
- `"12"`와 `"312"`는 일부 글자가 같아도 시작 부분이 같지 않으므로 접두사 관계가 아니다.
- 같은 전화번호는 중복되지 않지만, 자기 자신을 검사하지 않도록 반복 범위를 `i < key.length()`로 둔다.

## 7. 한줄평

접두사를 직접 만든 뒤 해시에서 존재 여부를 확인하면, 모든 전화번호 쌍을 비교하지 않아도 된다.

## 8. 더 나은 풀이와 코드 개선

현재 코드는 정답을 구하는 데 필요한 판단이 모두 들어 있다. 다만 `Map<String, Integer>`의 값 `1`은 사용하지 않으므로, **문자열이 있는지만 관리하는 `HashSet`**이 의도를 더 분명하게 나타낸다.

```java
import java.util.*;

class Solution {
    public boolean solution(String[] phone_book) {
        Set<String> numbers = new HashSet<>(Arrays.asList(phone_book));

        for (String number : phone_book) {
            for (int length = 1; length < number.length(); length++) {
                String prefix = number.substring(0, length);
                if (numbers.contains(prefix)) {
                    return false;
                }
            }
        }

        return true;
    }
}
```

알고리즘은 원래 코드와 같고, `numbers`와 `length`라는 이름으로 변수의 뜻을 드러냈다. `HashSet`으로 바꾸어도 시간복잡도의 큰 틀은 같다.

## 9. 비슷한 문제에 적용하기

| 필요한 작업 | 떠올릴 방법 |
| --- | --- |
| 만든 문자열이 목록에 **정확히 있는지** 반복 확인 | `HashSet` 또는 `HashMap` |
| 문자열을 정렬했을 때 가까운 것끼리 비교 가능 | 정렬 후 `startsWith()` |
| 접두사를 문자별로 따라가며 조회·삽입을 반복 | 트라이(Trie) |

접두사 문제라고 항상 해시를 쓰는 것은 아니다. 이 문제는 만든 접두사와 **정확히 같은 번호가 있는지** 확인하므로 해시가 잘 맞는다. 반면 정렬 후 이웃한 번호를 `startsWith()`로 비교할 수도 있고, 접두사를 문자별로 따라가는 조회가 많다면 트라이(Trie)를 고려할 수 있다. 먼저 필요한 작업을 구분하고 방법을 선택하자.
