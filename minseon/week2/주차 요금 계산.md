# 주차 요금 계산 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/92341?language=java

## 0. 문제 요약

차량별 입·출차 기록으로 **하루 동안의 누적 주차 시간**을 구하고, 그 시간에 대한 요금을 계산한다. 출차 기록 없이 주차장에 남은 차량은 `23:59`에 출차한 것으로 본다. 결과는 **차량 번호 오름차순**으로 반환한다.

- 누적 시간이 기본 시간 이하라면 기본 요금만 낸다.
- 기본 시간을 넘으면 초과 시간을 단위 시간으로 나누어 **올림**한 횟수만큼 단위 요금을 더한다.

## 사용 알고리즘 / 자료구조

- 해시맵 (`HashMap`), 정렬

## 1. 문제 접근

처음에는 `IN`일 때 입차 시간을 저장하고, `OUT`일 때 두 시각의 차이로 **그 구간의 요금**을 바로 계산하려 했다. 하지만 요금은 출차할 때마다 매기는 것이 아니라, **같은 차량의 주차 시간을 모두 합한 뒤 한 번** 계산해야 한다.

예를 들어 기본 시간이 60분인 차량이 30분씩 두 번 주차했다면, 기본 요금 두 번이 아니라 **누적 60분에 대한 기본 요금 한 번**을 낸다. 그래서 두 맵의 역할을 다음처럼 나눴다.

```text
carMap      : 현재 주차 중인 차량 → 입차 시각(분)
totalMinutes: 차량 → 하루 동안 누적된 주차 시간(분)
```

기록을 순서대로 읽으며 `IN`이면 입차 시각을 저장하고, `OUT`이면 `출차 시각 - 입차 시각`을 누적한다. 기록을 다 읽은 뒤에도 `carMap`에 남은 차량은 `23:59`까지의 시간을 더한다. 마지막으로 차량 번호를 정렬하고, 누적 시간으로 요금을 계산한다.

시간은 `HH:MM` 문자열 그대로 빼지 않고 `시 × 60 + 분`으로 바꿔 계산한다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int[] solution(int[] fees, String[] records) {
        Map<String, Integer> carMap = new HashMap<>();
        Map<String, Integer> totalMinutes = new HashMap<>();

        for (String cmd : records) {
            String[] s = cmd.split(" ");

            String time = s[0];
            String car = s[1];
            String type = s[2];

            if (type.equals("IN")) {
                int inMinute = calculateTime(time);
                carMap.put(car, inMinute);
            } else {
                int inMinute = carMap.get(car);
                int outMinute = calculateTime(time);
                int parkingTime = outMinute - inMinute;
                totalMinutes.put(car, totalMinutes.getOrDefault(car, 0) + parkingTime);
                carMap.remove(car);
            }
        }

        for (String car : carMap.keySet()) {
            int inMinute = carMap.get(car);
            int outMinute = calculateTime("23:59");
            int parkingTime = outMinute - inMinute;
            totalMinutes.put(car, totalMinutes.getOrDefault(car, 0) + parkingTime);
        }

        List<String> cars = new ArrayList<>(totalMinutes.keySet());
        Collections.sort(cars);

        int[] answer = new int[cars.size()];
        int i = 0;
        for (String car : cars) {
            answer[i++] = calculateFee(fees, totalMinutes.get(car));
        }

        return answer;
    }

    int calculateTime(String time) {
        String[] t = time.split(":");
        int hour = Integer.parseInt(t[0]);
        int minute = Integer.parseInt(t[1]);

        return hour * 60 + minute;
    }

    int calculateFee(int[] fees, int parkingTime) {
        int basicTime = fees[0];
        int basicFee = fees[1];
        int unitTime = fees[2];
        int unitFee = fees[3];

        if (parkingTime <= basicTime) return basicFee;

        return basicFee
                + ((parkingTime - basicTime + unitTime - 1) / unitTime) * unitFee;
    }
}
```

### 코드 구현 흐름

1. **입차 기록 — `solution()`의 `IN` 분기**: `calculateTime()`으로 시각을 분으로 바꿔 `carMap`에 저장한다.
2. **출차 기록 — `solution()`의 `OUT` 분기**: 입차 시각과 출차 시각의 차이를 `totalMinutes`에 더하고, 출차한 차량을 `carMap`에서 제거한다.
3. **미출차 차량 처리 — 두 번째 `for`문**: `carMap`에 남은 차량의 시간을 `23:59`까지 계산해 누적한다.
4. **차량 번호 정렬 — `Collections.sort()`**: `HashMap`의 순회 순서는 차량 번호순이 아니므로 키를 따로 정렬한다.
5. **요금 계산 — 마지막 `for`문과 `calculateFee()`**: 정렬한 차량 번호 순서대로 누적 시간에 대한 요금을 한 번씩 계산한다.

## 3. 새롭게 배운 내용

### 구간별 요금과 누적 시간에 대한 요금은 다르다

같은 차량이 여러 번 입·출차할 수 있다. 이 문제에서는 **각 주차 구간의 시간**을 누적한 뒤, **누적 시간 전체에 요금표를 한 번 적용**한다. `totalMinutes`라는 이름도 이 맵에 요금이 아닌 시간이 저장된다는 뜻을 드러낸다.

### 나누어떨어지지 않는 초과 시간은 올림한다

정수끼리 `/`로 나누면 소수점 아래는 버려진다. 초과 시간이 11분이고 단위 시간이 10분이라면 2회분의 단위 요금이 필요하지만, `11 / 10`은 1이다.

```text
초과 시간 = parkingTime - basicTime
추가 요금 횟수 = (초과 시간 + unitTime - 1) / unitTime

예: (11 + 10 - 1) / 10 = 20 / 10 = 2
```

단, `parkingTime <= basicTime`일 때는 먼저 기본 요금만 반환한다.

### 맵을 순회하는 중에는 원소를 제거하지 않는다

처음에는 `carMap.keySet()`을 순회하면서 `carMap.remove(car)`도 호출했다. 순회 도중 맵의 구조를 변경하면 `ConcurrentModificationException`이 발생할 수 있다. 미출차 차량을 모두 처리한 뒤에는 `carMap`이 더 필요하지 않으므로 이 반복문에서는 제거 자체를 하지 않았다. 반면 `OUT` 기록을 처리할 때는 맵을 순회 중인 것이 아니므로 제거해도 된다.

### `HashMap`에 저장했다고 차량 번호순으로 나오지는 않는다

처음에는 `totalMinutes.keySet()`을 바로 순회해 답을 채웠지만, `HashMap`은 키의 정렬 순서를 보장하지 않는다. 키를 리스트로 옮겨 `Collections.sort()`한 뒤 순회해야 한다. 차량 번호가 모두 네 자리 문자열이므로 문자열 오름차순이 차량 번호의 숫자 오름차순과 같다.

## 4. 처음 보는 문제에서의 사고 흐름

1. **최종 결과의 기준을 먼저 확인한다.** 기록마다 요금을 내는지, 차량별 누적 시간에 한 번 요금을 내는지 구분한다.
2. **차량별로 기억해야 할 정보를 나눈다.** 아직 출차하지 않은 차량의 입차 시각과, 출차까지 마친 주차 시간의 누적값이 필요하다.
3. **기록을 처리하는 규칙을 만든다.** `IN`은 입차 시각 저장, `OUT`은 시간 차이 누적 후 입차 기록 제거다.
4. **기록이 끝난 뒤 남을 상태를 확인한다.** 출차하지 않은 차량은 `23:59`를 출차 시각으로 사용한다.
5. **출력 조건을 마지막에 확인한다.** 누적 시간에 요금을 한 번 적용하고 차량 번호순으로 답을 만든다.

시뮬레이션 문제에서는 기록을 읽는 동안 필요한 **현재 상태**와, 끝까지 누적해야 하는 **결과 상태**를 구분하면 흐름이 명확해진다.

## 5. 시간복잡도 / 공간복잡도

기록 수를 `r`, 차량 수를 `c`라고 하면 `r ≤ 1,000`, `c ≤ r`이다.

- 기록 처리와 미출차 차량 처리: 평균적인 해시 조회를 가정하면 `O(r + c)`.
- 차량 번호 정렬: `O(c log c)`.
- 차량별 요금 계산: `O(c)`.
- **전체 시간복잡도: `O(r + c log c)`**.
- **공간복잡도: `O(c)`** — 두 맵, 차량 번호 목록, 결과 배열에 비례한다.

최대 `c = 1,000`이어도 정렬 규모는 대략 `10³ × log₂(10³) ≈ 10⁴`이므로 충분하다. `10⁸`은 대략적인 연산 규모를 가늠하는 기준일 뿐, 실제 실행 시간은 연산의 종류와 환경에 따라 달라진다.

## 6. 엣지 케이스

- 출차 기록이 없는 차량은 `23:59`까지 주차한 것으로 계산한다.
- 같은 차량이 여러 번 입·출차해도 시간을 먼저 모두 더한 뒤 요금은 한 번만 계산한다.
- 누적 시간이 기본 시간과 같으면 기본 요금만 낸다.
- 초과 시간이 단위 시간으로 나누어떨어지지 않으면 올림한다.
- 차량 번호 `"0000"`처럼 앞에 0이 있어도 문자열 그대로 관리하고 정렬한다.

## 7. 한줄평

기록마다 요금을 계산하는 대신 **차량별 주차 시간을 먼저 누적**하니 입·출차 처리와 요금 계산이 분리되어 명확해졌다.

## 8. 더 간결한 풀이와 코드 개선: `TreeMap`

최종 코드의 `HashMap`과 정렬 목록 대신, 누적 시간을 `TreeMap`에 저장하면 키인 **차량 번호가 자동으로 오름차순**으로 관리된다. 그러면 `cars` 리스트와 `Collections.sort()`가 필요 없다. 입차 중인 차량은 순서가 필요 없으므로 그대로 `HashMap`을 쓴다.

```java
import java.util.*;

class Solution {
    public int[] solution(int[] fees, String[] records) {
        Map<String, Integer> parked = new HashMap<>();
        Map<String, Integer> totalMinutes = new TreeMap<>();

        for (String record : records) {
            String[] parts = record.split(" ");
            String car = parts[1];
            int minute = toMinutes(parts[0]);

            if (parts[2].equals("IN")) {
                parked.put(car, minute);
            } else {
                totalMinutes.merge(car, minute - parked.remove(car), Integer::sum);
            }
        }

        for (Map.Entry<String, Integer> entry : parked.entrySet()) {
            totalMinutes.merge(entry.getKey(),
                    23 * 60 + 59 - entry.getValue(), Integer::sum);
        }

        int[] answer = new int[totalMinutes.size()];
        int i = 0;
        for (int minutes : totalMinutes.values()) {
            int extra = Math.max(0, minutes - fees[0]);
            answer[i++] = fees[1] + ((extra + fees[2] - 1) / fees[2]) * fees[3];
        }
        return answer;
    }

    private int toMinutes(String time) {
        String[] parts = time.split(":");
        return Integer.parseInt(parts[0]) * 60 + Integer.parseInt(parts[1]);
    }
}
```

### `Map.merge()`는 무엇을 할까?

`merge()`는 `Map`에 있는 메서드로, **키에 값이 없으면 새로 저장하고, 값이 있으면 기존 값과 새 값을 합쳐 갱신**한다. 기본 사용법은 다음과 같다. [Java `Map.merge()` 공식 문서](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/Map.html#merge(K,V,java.util.function.BiFunction))

```java
map.merge(key, value, (oldValue, newValue) -> oldValue + newValue);
```

| 매개변수 | 뜻 | 이 문제에서 전달한 값 |
| --- | --- | --- |
| 첫 번째 `key` | 저장하거나 갱신할 키 | 차량 번호 `car` |
| 두 번째 `value` | 새로 넣을 값 | 이번 주차 시간 `parkingTime` |
| 세 번째 `remappingFunction` | 키에 기존 값이 **있을 때만** 기존 값과 새 값을 어떻게 합칠지 정하는 함수 | `Integer::sum` |

실제 코드는 `totalMinutes.merge(car, parkingTime, Integer::sum)` 형태다. `Integer::sum`은 `(oldValue, newValue) -> oldValue + newValue`를 짧게 쓴 **메서드 참조**다. 함수의 첫 인자는 맵에 있던 누적 시간, 두 번째 인자는 이번에 전달한 주차 시간이다.

| `car`의 기존 값 | 실행 결과 |
| --- | --- |
| 없음 | 세 번째 함수를 호출하지 않고 `parkingTime`을 그대로 저장 |
| 40분 있음, 새 주차 시간이 50분 | 세 번째 함수가 `40 + 50`을 계산해 90분으로 갱신 |

이 문제에서는 다음 코드와 같은 의도로 사용했다.

```java
totalMinutes.put(car, totalMinutes.getOrDefault(car, 0) + parkingTime);
```

`merge()`는 갱신된 값을 반환한다. 기존 값이 `null`인 경우도 값이 없는 경우처럼 처리하고, 세 번째 함수의 결과가 `null`이면 해당 키를 삭제한다. 다만 이 풀이의 누적 시간은 `null`을 사용하지 않으므로, 여기서는 **없으면 저장 / 있으면 더하기**만 기억해도 된다.

출차 처리의 `minute - parked.remove(car)`에서는 `remove(car)`가 **저장된 입차 시각을 반환하면서 맵에서 제거**하므로, 그 차이가 이번 주차 시간이 된다. 문제에서 잘못된 출차 기록은 주어지지 않아 해당 차량의 입차 시각이 항상 있다.

`TreeMap`의 `values()`는 키가 정렬된 순서로 순회되므로 차량 번호순 결과를 만들 수 있다.

이 코드는 별도 정렬 단계가 없어 짧지만, `TreeMap`의 삽입·조회는 `O(log c)`이고 `merge()` 문법을 알아야 이해할 수 있다. 설명하기 쉬운 코드를 우선한다면 기존의 `HashMap` + 정렬 방식도 충분히 좋다.

## 9. 비슷한 문제에 적용하기

| 문제의 특징 | 떠올릴 방법 |
| --- | --- |
| 여러 기록을 같은 대상별로 누적 | `Map<대상, 누적값>` |
| `IN`/`OUT`처럼 시작과 끝이 따로 주어짐 | 진행 중인 상태를 별도 맵에 저장 |
| 결과를 키의 오름차순으로 출력 | 키를 정렬하거나 `TreeMap` 사용 |
| 정수 나눗셈 결과를 올림해야 함 | 양수에 대해 `(값 + 나누는 수 - 1) / 나누는 수` |

핵심은 **기록 처리 → 남은 상태 마무리 → 결과 계산·정렬**의 순서를 분리하는 것이다.
