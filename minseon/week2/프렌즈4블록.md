# 프렌즈4블록 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/17679?language=java

## 0. 문제 요약

같은 문자로 이루어진 **2×2 블록**을 찾아 한꺼번에 지운다. 빈칸이 생기면 위의 블록들이 아래로 떨어진다. 새로운 2×2가 생길 수 있으므로 더 이상 지울 블록이 없을 때까지 반복하고, **지워진 칸의 총개수**를 반환한다.

판의 높이 `m`과 너비 `n`은 각각 최대 30이다. 한 칸이 여러 2×2에 동시에 포함될 수 있지만, 그 칸은 한 번만 지운다.

## 사용 알고리즘 / 자료구조

- 2차원 배열, 구현·시뮬레이션, 표시 배열, 열별 압축

## 1. 문제 접근

처음에는 같은 블록을 찾으려면 DFS나 BFS가 필요할지 고민했다. 하지만 이 문제는 같은 문자가 **어디까지 연결되어 있는지** 찾는 문제가 아니다. 지워지는 조건이 정확히 **인접한 네 칸이 같은 2×2**로 정해져 있다. 따라서 모든 칸을 2×2의 왼쪽 위 모서리라고 생각하고 네 칸만 검사하면 된다.

```text
(r, c)       (r, c+1)
(r+1, c)     (r+1, c+1)
```

여러 2×2가 겹칠 수 있으므로 발견 즉시 블록을 지우면 안 된다. 먼저 `boolean[][] check`에 **이번 라운드에 지울 칸**을 모두 표시하고, 판 전체를 검사한 다음 표시된 칸의 개수를 센다. 이렇게 하면 겹친 칸은 여러 번 표시되더라도 한 번만 센다.

그다음 각 열에서 지워지지 않은 블록을 **아래에서부터 다시 쌓는다**. 열마다 `write`를 맨 아래 행으로 시작하고, 아래에서 위로 읽으며 살아 있는 블록을 `grid[write][c]`에 놓는다. 다 옮긴 후 남은 위쪽 칸은 `'.'`으로 채운다.

```text
한 열의 위쪽                    낙하 후
A                               .
.                               .
B              →                A
D (이번에 지움)                 B
C                               C
한 열의 아래쪽
```

한 라운드에서 지울 칸이 0개였다면 판이 더는 변하지 않으므로 반복을 끝낸다.

## 2. 문제 코드

```java
class Solution {
    public int solution(int m, int n, String[] board) {
        char[][] grid = new char[m][n];

        for (int r = 0; r < m; r++) {
            grid[r] = board[r].toCharArray();
        }

        int answer = 0;
        while (true) {
            boolean[][] check = new boolean[m][n];

            for (int r = 0; r < m - 1; r++) {
                for (int c = 0; c < n - 1; c++) {
                    char ch = grid[r][c];

                    if (ch != '.' && grid[r + 1][c] == ch
                            && grid[r][c + 1] == ch
                            && grid[r + 1][c + 1] == ch) {
                        check[r][c] = true;
                        check[r + 1][c] = true;
                        check[r][c + 1] = true;
                        check[r + 1][c + 1] = true;
                    }
                }
            }

            int remove = 0;
            for (int r = 0; r < m; r++) {
                for (int c = 0; c < n; c++) {
                    if (check[r][c]) remove++;
                }
            }

            if (remove == 0) break;
            answer += remove;

            for (int c = 0; c < n; c++) {
                int write = m - 1;

                for (int r = m - 1; r >= 0; r--) {
                    if (grid[r][c] != '.' && !check[r][c]) {
                        grid[write--][c] = grid[r][c];
                    }
                }

                while (write >= 0) {
                    grid[write--][c] = '.';
                }
            }
        }

        return answer;
    }
}
```

### 코드 구현 흐름

| 순서 | 코드 | 하는 일 |
| --- | --- | --- |
| 1 | `board[r].toCharArray()` | 문자열로 받은 판을 수정 가능한 `char[][]`로 바꾼다. |
| 2 | `while (true)` | 제거할 블록이 없어질 때까지 라운드를 반복한다. |
| 3 | `check`와 2×2 검사 | 이번 라운드에 지울 네 칸을 표시한다. |
| 4 | `remove` 계산 | `true`인 칸만 세어 실제 제거 칸 수를 구한다. 0이면 종료한다. |
| 5 | 열별 `write` 이동 | 살아 있는 블록을 아래부터 쌓고 위쪽을 `'.'`으로 채운다. |

## 3. 새롭게 배운 내용

### 왜 `Boolean[][]`이 아니라 `boolean[][]`일까?

처음에는 `Boolean[][] check`를 만들고 `!check[r][c]`를 검사했다. 하지만 `Boolean`은 객체형이라 초기화하지 않은 칸의 값이 `null`이다. `!`나 `if`에서 이를 `boolean`으로 사용하려 하면 `NullPointerException`이 난다.

`boolean[][]`의 각 칸은 기본값이 `false`다. 이 문제에서는 “이번 라운드에 지울 칸인가?”만 표시하므로 기본형 `boolean`이 알맞다.

### 왜 이미 표시된 칸에서도 2×2를 검사할까?

한 칸이 여러 2×2에 포함될 수 있다. 검사 조건에 `!check[r][c]`를 넣으면, 앞에서 표시한 칸을 왼쪽 위로 쓰는 **다른 2×2를 놓칠 수 있다**.

검사는 `grid`의 네 문자가 같은지만 확인한다. `check`는 이번 라운드가 끝난 뒤 **어떤 칸을 한꺼번에 지울지** 기록하는 용도로만 사용한다. 겹치는 칸은 `true`가 여러 번 대입되어도 개수를 셀 때 한 번만 센다.

### 2×2 검사 범위는 왜 `m - 1`, `n - 1`까지만 갈까?

`(r, c)`에서 `r + 1`행과 `c + 1`열을 함께 확인한다. 마지막 행이나 열을 왼쪽 위 칸으로 삼으면 배열 밖을 읽으므로 반복 조건을 `r < m - 1`, `c < n - 1`로 둔다.

### 떨어지는 블록은 어떻게 재배치할까?

한 열에서 `r`은 **원래 블록을 읽는 위치**, `write`는 **살아 있는 블록을 내려놓을 위치**다. 둘 다 아래에서 시작하지만, `write`는 블록을 하나 놓았을 때만 위로 이동한다.

```text
원래 열(위→아래): [A, ., B, D*, C]   (*: 이번 라운드에 제거)
읽는 순서(아래→위): C → D* → B → . → A

C를 맨 아래에 놓기
D*는 건너뛰기
B를 C 바로 위에 놓기
빈칸은 건너뛰기
A를 B 바로 위에 놓기
남은 위쪽 칸을 '.'으로 채우기

결과: [., ., A, B, C]
```

`write`는 **열마다 새로 `m - 1`로 설정**해야 한다. 다른 열에서 사용한 `write`를 이어 쓰면 그 열의 블록을 잘못된 행에 놓는다. 이미 비어 있는 `'.'`도 블록처럼 복사하지 않도록 건너뛴다.

## 4. 처음 보는 문제에서의 사고 흐름

### “같은 블록 4개가 2×2를 이룬다” → 왜 DFS/BFS가 아닐까?

먼저 **찾아야 하는 범위**를 확인한다. DFS/BFS는 연결된 같은 블록이 어디까지 퍼져 있는지 알아야 할 때 유용하다. 여기서는 크기와 모양이 정해진 **네 칸의 패턴**만 찾으면 된다. 따라서 각 칸을 2×2의 왼쪽 위로 놓고 네 칸을 비교하는 전체 탐색이 더 직접적이다.

### “여러 2×2가 있으면 한꺼번에 지운다” → 왜 표시 배열이 필요할까?

발견 즉시 `grid`를 바꾸면, 같은 라운드에 검사해야 할 다른 2×2의 원래 문자가 사라질 수 있다. **검사 중에는 판을 그대로 두어야** 모든 후보를 같은 상태에서 판단할 수 있다.

그래서 `check`에 제거 여부만 기록한다. 지울 블록이 서로 겹쳐도 표시된 *칸*의 개수를 세므로 중복 계산하지 않는다. 이 문장에서 필요한 핵심은 **탐색과 실제 변경을 분리하기**다.

### “위 블록이 아래로 떨어진다” → 왜 열마다 `write`를 둘까?

블록은 좌우로 이동하지 않고 **같은 열 안에서만 아래로** 내려간다. 따라서 열 하나씩 독립적으로 처리할 수 있다.

열의 맨 아래부터 살아 있는 블록을 읽고 `write` 위치부터 채우면, 블록들의 위아래 순서를 유지하면서 빈칸 없이 아래쪽에 모을 수 있다. `write`는 “다음 블록을 놓을 빈 자리”이고, 열이 바뀌면 다시 맨 아래로 초기화한다.

### “다시 2×2가 생기면 반복한다” → 언제 멈출까?

한 번 제거·낙하한 뒤 판이 바뀌므로 처음부터 다시 검사해야 한다. 이번 라운드에 표시된 칸이 **0개**라면 지울 수 있는 블록이 없고 판도 더는 바뀌지 않는다. 그래서 `remove == 0`을 반복 종료 조건으로 둔다.

```text
2×2 검사 → 제거할 칸 표시 → 칸 수 세기
                         ├─ 0개: 종료
                         └─ 1개 이상: 열별 낙하 → 다시 검사
```

## 5. 시간복잡도 / 공간복잡도

한 라운드마다 2×2 검사, 표시된 칸 세기, 열별 낙하가 각각 판의 크기에 비례하므로 `O(mn)`이다. 블록을 제거하는 라운드 수를 `R`이라고 하면, 마지막으로 “더 지울 것이 없다”고 확인하는 라운드까지 포함해 **전체 시간복잡도는 `O((R + 1)mn)`**이다.

한 번 제거할 때 적어도 2×2의 네 칸이 지워진다. `m, n ≤ 30`이므로 칸은 최대 `30 × 30 = 900`개이고, 제거가 일어나는 라운드는 최대 `900 / 4 = 225`번이다. 실제로는 한 라운드에 여러 칸이 함께 지워질 수 있다. 판과 표시 배열에 필요한 **공간복잡도는 `O(mn)`**이다.

최대 크기를 단순히 대입해도 라운드당 약 900칸을 몇 차례 훑는 규모이므로 이 문제에서는 충분하다. `10⁸` 같은 기준은 대략적인 감을 잡는 용도이며, 실제 실행 시간은 연산의 종류와 환경에 따라 다르다.

## 6. 엣지 케이스

- 2×2 두 개가 한 칸 이상 겹쳐도 **칸마다 한 번씩만** 제거 개수를 센다.
- 처음부터 지울 2×2가 없으면 `0`을 반환한다.
- 제거 후 생긴 빈칸 `'.'`은 블록으로 검사하거나 아래로 쌓지 않는다.
- 한 열의 블록을 전부 지웠다면 해당 열 전체가 `'.'`이 된다.
- 검사할 때 마지막 행과 마지막 열을 2×2의 왼쪽 위로 사용하지 않는다.

## 7. 한줄평

DFS/BFS로 연결된 영역을 찾는 문제가 아니라, **정해진 2×2 패턴을 표시해 동시에 제거하고 열별로 압축하는 시뮬레이션** 문제였다.

## 8. 더 나은 풀이와 코드 개선

현재 코드는 판을 검사하는 단계, 제거 수를 세는 단계, 떨어뜨리는 단계가 순서대로 보여 코딩테스트용으로 충분히 좋다. 여러 번 등장하는 `'.'`을 상수 `EMPTY`로 이름 붙이거나, 코드가 더 길어질 경우 **2×2 표시**와 **열별 낙하**를 각각 함수로 분리하면 역할을 더 쉽게 설명할 수 있다.

`remove`를 `removedCount`, `check`를 `marked`처럼 바꾸면 변수의 의미가 조금 더 분명해진다. 이는 가독성을 위한 제안이며, 현재 알고리즘을 바꿀 필요는 없다.

## 9. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 이유 |
| --- | --- |
| 크기가 정해진 작은 모양을 찾음 | 각 칸을 기준으로 주변의 정해진 위치만 검사 |
| 여러 대상을 동시에 제거·변경 | 먼저 별도 배열에 표시해 원래 상태로 모두 판정 |
| 제거된 칸 위의 값이 아래로 이동 | 열별 `write` 포인터로 살아 있는 값 압축 |
| 변경 후 같은 규칙을 다시 적용 | 변화가 없을 때까지 시뮬레이션 반복 |

문제를 읽을 때 **“연결된 전체 영역을 찾는가, 정해진 작은 패턴을 찾는가?”**를 먼저 구분하면 DFS/BFS가 필요한지, 단순한 격자 검사가 적절한지 결정하기 쉽다.
