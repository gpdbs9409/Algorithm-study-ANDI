# 구명보트 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42885

## 사용 알고리즘 / 자료구조

- 그리디, 정렬, 투 포인터

## 1. 문제 접근

처음에는 사람들을 무거운 순서대로 보고, 가장 무거운 사람을 가장 가벼운 사람과 함께 태울 수 있는지 확인하는 방법을 생각했다.

구명보트에는 최대 2명만 탈 수 있다. 현재 가장 무거운 사람을 기준으로 보면 다음 두 경우만 판단하면 된다.

1. **가장 가벼운 사람과 함께 탈 수 있다:** 두 사람을 한 보트에 태운다.
2. **가장 가벼운 사람과도 함께 탈 수 없다:** 다른 사람들은 모두 그보다 무거우므로 가장 무거운 사람을 혼자 태운다.

몸무게를 오름차순으로 정렬한 뒤 `left`로 가장 가벼운 사람을, `right`로 가장 무거운 사람을 가리키게 했다.

```text
people = [50, 50, 70, 80], limit = 100

50 + 80 > 100 → 80 혼자 탑승
50 + 70 > 100 → 70 혼자 탑승
50 + 50 = 100 → 두 사람 함께 탑승

필요한 보트: 3대
```

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int[] people, int limit) {
        int answer = 0;
        Arrays.sort(people);
        int left = 0;
        int right = people.length - 1;

        while (left <= right) {
            if (people[left] + people[right] <= limit) {
                left++;
                right--;
            } else {
                right--;
            }
            answer++;
        }

        return answer;
    }
}
```

### 코드 구현 흐름

1. **몸무게 정렬 — `Arrays.sort()`**: 양 끝에서 가장 가벼운 사람과 가장 무거운 사람을 바로 찾을 수 있게 했다.
2. **두 사람 확인 — `left`, `right`**: 두 사람의 무게 합이 `limit` 이하인지 확인했다.
3. **함께 탈 수 있을 때 — `if`문**: 두 사람 모두 보트에 탔으므로 양쪽 포인터를 이동했다.
4. **함께 탈 수 없을 때 — `else`문**: 가장 무거운 사람만 혼자 탔으므로 `right`만 이동했다.
5. **보트 수 세기 — `answer++`**: 두 경우 모두 보트 한 대를 사용하므로 반복할 때마다 한 번 증가시켰다.

## 3. 새롭게 배운 내용

### 그리디 선택은 어떻게 찾았나?

그리디 문제에서는 **지금 확실하게 처리할 수 있는 대상**을 찾아보면 도움이 된다. 이 문제에서는 가장 무거운 사람이다.

```text
가장 가벼운 사람 + 가장 무거운 사람 > limit
→ 가장 무거운 사람은 누구와도 함께 탈 수 없다.
```

이 경우 가장 무거운 사람을 혼자 태우는 선택은 확정이다. 함께 탈 수 있다면 둘을 짝지어 보낸다. 가장 무거운 사람에게 가장 가벼운 사람을 붙여도 보트 수가 늘어나지 않는다. 다른 사람과 짝짓는 배치가 있었다면, 그 짝을 가벼운 사람과 바꾸어도 기존 보트 수 안에서 배치할 수 있기 때문이다.

### 왜 양 끝에서 확인할까?

정렬하면 현재 남은 사람 중 가장 가벼운 사람과 가장 무거운 사람이 양 끝에 놓인다.

```text
가벼움                         무거움
left → [50, 50, 70, 80] ← right
```

가장 무거운 사람은 매 반복에서 보트에 타므로 `right`는 항상 왼쪽으로 이동한다. 함께 탄 경우에만 `left`도 오른쪽으로 이동한다. 두 포인터는 뒤로 돌아가지 않는다.

## 4. 시간복잡도 / 공간복잡도

사람 수를 `n`이라고 하면 이 문제는 `n ≤ 5 × 10⁴`이다.

| 방법 | 최대 입력을 대입한 연산 규모 | 판단 |
| --- | --- | --- |
| 정렬 `O(n log n)` | `(5 × 10⁴) × log₂(5 × 10⁴) ≈ (5 × 10⁴) × 16 = 8 × 10⁵` | 충분히 가능 |
| 투 포인터 `O(n)` | 최대 `5 × 10⁴`번 이동 | 충분히 가능 |
| 모든 두 사람 확인 `O(n²)` | `(5 × 10⁴)² = 2.5 × 10⁹` | 부담이 큼 |

따라서 전체 시간복잡도는 정렬이 지배하는 `O(n log n)`이다. 흔히 말하는 `10⁸`번은 빠르게 가늠하는 기준일 뿐, 실제 실행 시간은 언어·연산 종류·제한 시간에 따라 달라진다.

포인터와 보트 수를 저장하는 **추가 변수**는 `O(1)` 공간을 사용한다. 정렬 자체가 사용하는 추가 공간은 Java의 정렬 구현에 따른다.

## 5. 엣지 케이스

- 사람이 한 명뿐이면 보트 한 대가 필요하다.
- 두 사람의 무게 합이 정확히 `limit`이면 함께 탈 수 있다.
- 어떤 두 사람도 함께 탈 수 없다면 각자 보트 한 대씩 탄다.
- `left == right`이면 마지막 한 명이 남은 상태다. 현재 코드는 어느 분기로 가든 보트를 한 대 세고 반복이 끝나므로 결과가 맞다.

## 6. 한줄평

가장 무거운 사람을 기준으로 혼자 타야 하는지, 가장 가벼운 사람과 함께 탈 수 있는지를 결정하면 간단해지는 문제였다.

## 7. 더 나은 풀이와 코드 개선

현재 코드는 짧고 판단 기준도 명확해 코딩테스트용으로 충분히 좋다. `left == right`일 때 자기 몸무게를 두 번 더해 비교하는 부분은 읽을 때 어색할 수 있지만, 어느 분기로 가든 보트 한 대를 세고 종료되므로 별도 처리가 꼭 필요하지는 않다.

`Arrays.sort(people)`은 입력 배열의 순서를 직접 바꾼다. 이 문제에서는 원래 순서가 필요하지 않으므로 그대로 사용해도 된다.

## 8. 비슷한 문제에 적용하기

**정렬한 뒤 가장 작은 값과 가장 큰 값을 짝지을지 결정하는 문제**에서 양 끝 투 포인터를 떠올릴 수 있다.

다만 이 문제의 판단이 간단한 이유는 보트에 **최대 2명**만 탈 수 있기 때문이다. 한 보트에 3명 이상 탈 수 있다면 양 끝 두 사람만 확인하는 규칙을 그대로 적용할 수 있는지 다시 검토해야 한다.
