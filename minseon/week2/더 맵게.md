# 더 맵게 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42626

## 0. 문제 요약

모든 음식의 스코빌 지수를 `K` 이상으로 만들어야 한다. 한 번 섞을 때마다 **가장 낮은 지수 두 개**를 골라 다음 값으로 만든다.

```text
새 스코빌 지수 = 가장 낮은 지수 + (두 번째로 낮은 지수 × 2)
```

모든 음식이 `K` 이상이 될 때까지 섞은 횟수를 반환한다. 더 이상 섞을 수 없는데 `K` 미만인 음식이 남아 있다면 `-1`을 반환한다. 음식은 최대 `10⁶`개이고, `K`는 최대 `10⁹`이다.

## 사용 알고리즘 / 자료구조

- 최소 힙 (`PriorityQueue`)

## 1. 문제 접근

매번 **현재 남아 있는 음식 중 가장 낮은 값 두 개**를 꺼내야 한다. 섞어서 만든 새 음식도 다음 선택 대상이 되므로, 처음에 한 번만 정렬한 배열로 처리하기는 어렵다.

최소 힙인 `PriorityQueue`에 음식의 지수를 넣으면 가장 작은 값을 `poll()`로 꺼내고, 새 값을 `offer()`로 다시 넣을 수 있다.

```text
[1, 2, 3, 9, 10, 12], K = 7

1과 2를 섞음 → 1 + 2 × 2 = 5
남은 값: [3, 5, 9, 10, 12]

3과 5를 섞음 → 3 + 5 × 2 = 13
남은 값: [9, 10, 12, 13]

가장 작은 값 9가 K 이상 → 모든 음식이 K 이상, 정답 2
```

가장 작은 값이 이미 `K` 이상이라면 나머지도 모두 `K` 이상이므로 `pq.peek()`만 확인하면 된다.

처음 코드에서는 섞은 **뒤에** 원소가 하나 남았는지 확인하고, 그 값이 `K`보다 *클 때만* 성공으로 판단했다. 하지만 `K`와 **같아도 성공**이다. 최종 코드에서는 섞기 **전**에 원소가 2개 이상인지 확인하고, 반복이 끝난 뒤 최솟값으로 성공 여부를 판단하도록 정리했다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int[] scoville, int K) {
        Queue<Long> pq = new PriorityQueue<>();
        for (int s : scoville) {
            pq.offer((long) s);
        }

        int count = 0;
        while (pq.size() > 1 && pq.peek() < K) {
            long n1 = pq.poll();
            long n2 = pq.poll();
            pq.offer(n1 + (n2 * 2));
            count++;
        }

        return pq.peek() < K ? -1 : count;
    }
}
```

### 코드 구현 흐름

1. **음식 저장 — 첫 번째 `for`문, `pq.offer()`**: 모든 스코빌 지수를 최소 힙에 넣는다. 섞은 값이 커질 수 있으므로 `long`으로 저장한다.
2. **섞을 수 있는지 판단 — `while` 조건**: 음식이 2개 이상 남아 있고, 가장 작은 값이 `K` 미만일 때만 섞는다.
3. **가장 작은 두 값 선택 — `pq.poll()` 두 번**: 현재 지수가 가장 낮은 두 음식을 꺼낸다.
4. **새 값 저장 — `pq.offer()`**: 공식대로 계산한 지수를 다시 힙에 넣고 섞은 횟수를 늘린다.
5. **결과 판단 — 마지막 `return`**: 반복이 끝났는데도 최솟값이 `K` 미만이면 `-1`, 아니면 섞은 횟수를 반환한다.

## 3. 새롭게 배운 내용

### `int`와 `long`은 언제 구분해서 써야 할까?

Java 정수형의 범위는 다음과 같다.

| 자료형 | 저장할 수 있는 범위 |
| --- | --- |
| `int` | `-2,147,483,648` ~ `2,147,483,647` (약 ±`2.1 × 10⁹`) |
| `long` | 약 `-9.2 × 10¹⁸` ~ `9.2 × 10¹⁸` |

자료형은 **입력값만 보고 고르면 안 된다.** 계산 중간에 만들어지는 값의 최댓값도 봐야 한다.

이 문제에서 `K`는 최대 `10⁹`이므로 `int`에 들어간다. 하지만 새 지수는 `n1 + 2 × n2`로 계산하고, 섞은 결과를 다시 섞을 수 있다. 따라서 `K`가 `int`에 들어간다고 해서 섞은 값도 항상 `int`에 들어가는 것은 아니다.

예를 들어 지수가 `1,000,000`인 음식이 128개 있고 `K = 1,000,000,000`이라고 하자. 여러 번 섞은 뒤 마지막 두 값이 각각 `729,000,000`이 되면 다음 값은:

```text
729,000,000 + 729,000,000 × 2 = 2,187,000,000
```

이는 `int`의 최댓값 `2,147,483,647`보다 크다. `int`로 계산하면 오버플로가 발생해 잘못된 결과가 나온다.

그래서 큐를 `Queue<Long>`으로 선언하고 입력값을 `(long) s`로 변환해 넣었다. `n1`, `n2`도 `long`이므로 섞는 계산 역시 `long`으로 이루어진다. 반면 섞는 횟수는 최대 음식 개수에서 1을 뺀 값이므로 `count`는 `int`로 충분하다.

다음에 숫자 문제를 만나면 **① 입력의 범위 → ② 중간 계산의 최댓값 → ③ 결과의 범위** 순서로 확인하자. 특히 덧셈이나 곱셈을 반복할 때는 중간값이 입력보다 훨씬 커질 수 있다.

### 종료 조건은 왜 이렇게 나눌까?

```java
while (pq.size() > 1 && pq.peek() < K)
```

- `pq.size() > 1`: 섞으려면 음식이 최소 2개 필요하다.
- `pq.peek() < K`: 가장 작은 값이 `K` 미만인 동안만 섞는다.

반복이 끝난 이유는 **모든 음식이 `K` 이상이 되었거나**, **음식이 하나만 남아 더 섞을 수 없기 때문**이다. 마지막에 최솟값을 확인해 성공과 실패를 구분한다.

```java
return pq.peek() < K ? -1 : count;
```

`K`와 **같으면 성공**이므로 `pq.peek() > K`로 판단하면 안 된다. 예를 들어 `[1, 2]`, `K = 5`는 한 번 섞어 정확히 5가 되므로 정답이 1이다.

## 4. 처음 보는 문제에서의 사고 흐름

1. **매번 무엇을 골라야 하는지 확인한다.** 가장 작은 음식 두 개를 계속 골라야 한다.
2. **값이 바뀌는지 확인한다.** 새로 만든 값도 다시 후보에 들어가므로 정렬된 배열만으로 현재 최솟값을 관리하기는 불편하다.
3. **반복 연산에 맞는 자료구조를 고른다.** 최솟값을 꺼내고 새 값을 넣는 작업을 반복하므로 최소 힙을 떠올린다.
4. **언제 멈추는지 정한다.** 최솟값이 `K` 이상이면 성공, 아직 `K` 미만인데 음식이 하나뿐이면 실패다.
5. **계산 결과의 범위를 확인한다.** 섞은 값이 커질 수 있으므로 `long`이 필요한지 검토한다.

이 문제는 가장 작은 두 값을 고르는 규칙이 이미 정해져 있다. 핵심은 다른 조합을 탐색하는 것이 아니라 그 규칙을 **반복해서 빠르게 실행할 자료구조**를 찾는 것이다.

## 5. 시간복잡도 / 공간복잡도

음식 개수를 `n`이라고 하면 `n ≤ 10⁶`이다.

- 처음 `n`개를 힙에 넣기: `O(n log n)`.
- 한 번 섞기: 두 번 꺼내고 한 번 넣으므로 `O(log n)`.
- 섞는 횟수: 한 번마다 음식 수가 1개씩 줄어 최대 `n - 1`번.
- **전체 시간복잡도: `O(n log n)`**.
- **공간복잡도: `O(n)`** — 힙에 음식 값을 저장한다.

최대 입력에서 `log₂(10⁶)`은 약 20이므로 `n log₂ n`은 약 `2 × 10⁷` 규모다. 실제로는 한 번 섞을 때 힙 연산을 여러 번 하므로 이 숫자가 곧 실행 횟수나 실행 시간을 뜻하지는 않는다. 흔히 사용하는 `10⁸` 기준 역시 대략적인 판단 기준으로만 본다.

## 6. 엣지 케이스

- 처음부터 모든 값이 `K` 이상이면 한 번도 섞지 않고 `0`을 반환한다.
- 섞은 결과가 `K`와 정확히 같아도 성공이다.
- 음식이 하나만 남았는데 그 값이 `K` 미만이면 더 섞을 수 없으므로 `-1`이다.
- 섞은 값이 `int` 범위를 넘어갈 수 있으므로 `long`으로 계산한다.

## 7. 한줄평

가장 작은 두 값을 반복해서 꺼내야 한다는 조건에서 최소 힙을 떠올리면 풀이가 간단해진다. 종료 조건과 중간 계산의 자료형도 함께 확인해야 한다.

## 8. 더 나은 풀이와 코드 개선

현재 최종 코드는 문제의 규칙과 종료 조건이 잘 드러나므로 코딩테스트용으로 충분히 좋다. 특히 **섞을 수 있는지 `while` 조건에서 먼저 확인하고**, 반복이 끝난 뒤 성공 여부를 한 번만 판단하는 구조가 간결하다.

변수 이름을 조금 더 설명적으로 짓고 싶다면 `n1`, `n2` 대신 `leastSpicy`, `secondLeastSpicy`처럼 바꿀 수 있다. 알고리즘이나 성능이 달라지는 것은 아니므로 선택 사항이다.

## 9. 비슷한 문제에 적용하기

| 문제에서 반복하는 작업 | 떠올릴 방법 |
| --- | --- |
| 현재 최솟값 또는 최댓값을 계속 꺼냄 | 우선순위 큐 |
| 값을 꺼내 가공한 뒤 다시 후보에 넣음 | 우선순위 큐로 갱신하며 반복 |
| 정수의 덧셈·곱셈 결과가 입력 범위보다 커짐 | 중간 계산까지 고려해 `long` 검토 |

우선순위 큐는 **처음 한 번 정렬하는 문제**보다, 값이 계속 추가·변경되는 상황에서 현재 최솟값이나 최댓값이 반복해서 필요할 때 특히 유용하다.
