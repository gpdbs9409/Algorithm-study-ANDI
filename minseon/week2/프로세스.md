# 프로세스 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42587

## 0. 문제 요약

대기 큐의 맨 앞 프로세스를 꺼낸다. **대기 중인 다른 프로세스에 더 높은 우선순위가 있으면** 꺼낸 프로세스를 맨 뒤에 넣고, 없으면 실행한다. 처음에 `location`에 있던 프로세스가 몇 번째로 실행되는지 구한다.

예를 들어 우선순위가 `[2, 1, 3, 2]`라면 원래 위치 기준 실행 순서는 `2번 → 3번 → 0번 → 1번`이다. 우선순위가 같은 프로세스끼리는 현재 대기 순서를 따른다. 프로세스는 최대 100개이고 우선순위는 1~9다.

## 사용 알고리즘 / 자료구조

- 큐, 정렬

## 1. 문제 접근

프로세스가 뒤로 이동할 수 있으므로 **현재 대기 순서**는 큐로 관리한다. 같은 우선순위의 프로세스도 구별해야 하므로 `[원래 위치, 우선순위]`를 함께 저장한다.

실행 가능 여부를 판단할 때는 **남아 있는 가장 높은 우선순위**가 필요하다. `priorities`의 복사본을 오름차순 정렬하고, 배열의 끝에서부터 확인했다.

```text
큐 맨 앞의 우선순위 == 남은 우선순위 중 최댓값 → 실행
큐 맨 앞의 우선순위 < 남은 우선순위 중 최댓값  → 큐 맨 뒤로 이동
```

실제로 실행한 경우에만 정렬된 배열의 인덱스와 실행 횟수를 바꾼다. 뒤로 보낸 프로세스는 아직 대기 중이기 때문이다.

처음에는 `Arrays.sort(priorities, Collections.reverseOrder())`로 내림차순 정렬하려 했지만, 기본형 배열 `int[]`에는 `Collections.reverseOrder()`를 적용할 수 없다. 또한 `Arrays.sort()`는 배열을 반환하지 않는다. 그래서 원본을 `clone()`으로 복사해 오름차순 정렬한 뒤, 끝에서부터 읽었다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int[] priorities, int location) {
        Queue<int[]> q = new ArrayDeque<>();
        for (int i = 0; i < priorities.length; i++) {
            q.offer(new int[]{i, priorities[i]});
        }

        int[] array = priorities.clone();
        Arrays.sort(array);

        int idx = array.length - 1;

        int count = 0;
        while (!q.isEmpty()) {
            if (q.peek()[1] == array[idx]) {
                int[] cur = q.poll();
                idx--;
                count++;
                if (location == cur[0]) return count;
            } else {
                int[] cur = q.poll();
                q.offer(new int[]{cur[0], cur[1]});
            }
        }
        return count;
    }
}
```

### 코드 구현 흐름

1. **대기 순서 저장 — 첫 번째 `for`문, `q.offer()`**: 각 프로세스의 원래 위치와 우선순위를 큐에 넣는다.
2. **최고 우선순위 준비 — `clone()`, `Arrays.sort()`**: 원본 순서를 보존하면서 복사본을 정렬한다. `idx`는 현재 남은 우선순위 중 가장 큰 값을 가리킨다.
3. **실행 여부 판단 — `while`문의 `if`**: 큐 맨 앞의 우선순위가 `array[idx]`와 같으면 실행할 수 있다.
4. **실행 — `q.poll()`, `idx--`, `count++`**: 실행한 프로세스를 제거하고 다음 우선순위를 가리킨다. 목표 프로세스였다면 실행 순서를 반환한다.
5. **뒤로 보내기 — `else`문의 `q.poll()`, `q.offer()`**: 더 높은 우선순위가 남아 있다면 맨 뒤로 보낸다. 실행하지 않았으므로 `idx`와 `count`는 그대로 둔다.

## 3. 새롭게 배운 내용

### 왜 원래 위치를 함께 저장할까?

우선순위만 저장하면 같은 우선순위의 프로세스들을 구별할 수 없다. 이 문제에서 찾는 것은 특정 *우선순위*가 아니라 **처음에 `location`에 있던 프로세스**이므로, 원래 위치를 함께 가지고 다녀야 한다.

### `clone()`은 왜 사용할까?

`priorities`는 처음 주어진 프로세스의 순서다. 이를 그대로 정렬하면 원래 순서를 잃는다. 복사본을 정렬하면 큐는 대기 순서를, 정렬 배열은 남은 최고 우선순위를 관리할 수 있다. 이 풀이에서 `clone()`은 원본 보존을 위한 명확한 선택이다.

### 이전에 풀었던 `PriorityQueue` 방식

다음은 예전에 작성해 통과했던 코드다. `PriorityQueue`로 현재 최고 우선순위를 확인하고, 원본 배열을 반복 순회해 처리 순서를 따라간다.

```java
import java.util.*;

class Solution {
    public int solution(int[] priorities, int location) {
        PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
        for (int a : priorities) {
            pq.offer(a);
        }

        int answer = 0;
        while (!pq.isEmpty()) {
            for (int i = 0; i < priorities.length; i++) {
                if (pq.peek() == priorities[i]) {
                    answer++;
                    pq.poll();

                    if (location == i) return answer;
                }
            }
        }

        return answer;
    }
}
```

이 코드도 올바른 풀이이다. `for`문은 매번 한 칸을 확인한 뒤 다음 인덱스로 진행하고, 끝에 도달하면 다음 바퀴에서 0번으로 돌아온다. 즉, 원본 배열을 원형으로 순회하는 효과가 있다.

```text
priorities = [1, 2, 1]

1번(우선순위 2) 실행 → 같은 바퀴에서 2번(우선순위 1) 실행
→ 다음 바퀴에서 0번(우선순위 1) 실행
```

따로 실행 완료 표시가 없어도 되는 이유는, 같은 우선순위의 프로세스들을 한 바퀴 안에서 순서대로 모두 처리한 후에야 `PriorityQueue`의 최댓값이 더 낮아지기 때문이다. 이미 실행한 위치를 다음 바퀴에서 다시 만날 때는 그 위치의 우선순위가 현재 최댓값보다 크므로 다시 실행하지 않는다.

| 풀이 | 대기 순서를 관리하는 방법 | 남은 최고 우선순위를 확인하는 방법 |
| --- | --- | --- |
| 최종 풀이 | 실제 `Queue<int[]>` | 정렬된 배열을 뒤에서부터 읽기 |
| 이전 풀이 | 원본 배열을 반복 순회 | 내림차순 `PriorityQueue` |

## 4. 처음 보는 문제에서의 사고 흐름

1. **무엇이 순서대로 움직이는지 확인한다.** 실행할 수 없는 프로세스는 맨 뒤로 가므로 우선순위만 정렬해서는 실행 순서를 알 수 없다.
2. **필요한 정보를 나눈다.** 현재 대기 순서, 남아 있는 최고 우선순위, 목표 프로세스의 원래 위치가 필요하다.
3. **각 정보의 관리 방법을 정한다.** 대기 순서는 큐, 최고 우선순위는 정렬 배열, 원래 위치는 프로세스와 함께 저장한다.
4. **언제 상태가 바뀌는지 구분한다.** 뒤로 보낼 때는 대기 순서만 바뀌고, 실행할 때는 최고 우선순위를 가리키는 인덱스와 실행 횟수도 바뀐다.
5. **같은 우선순위도 확인한다.** 더 높은 우선순위가 없으면 실행하므로 현재 우선순위가 최댓값과 **같을 때** 실행한다.

## 5. 시간복잡도 / 공간복잡도

프로세스 개수를 `n`이라고 하면 이 문제에서 `n ≤ 100`이다.

- **최종 풀이:** 정렬은 `O(n log n)`, 큐에서 꺼내고 뒤로 보내는 과정은 최악의 경우 `O(n²)`이다. 전체 시간복잡도는 `O(n²)`, 추가 공간은 큐와 복사 배열 때문에 `O(n)`이다.
- **이전 `PriorityQueue` 풀이:** 우선순위 삽입·삭제에 총 `O(n log n)`, 반복적인 배열 순회에 최악의 경우 `O(n²)`이 걸린다. 전체 시간복잡도는 `O(n²)`, 추가 공간은 `O(n)`이다.

최대 입력을 대입하면 `n² = 100² = 10⁴` 규모이므로 두 방법 모두 충분하다. 흔히 말하는 `10⁸`회는 대략적인 비교 기준일 뿐, 실제 시간은 연산의 종류와 환경에 따라 달라진다.

## 6. 엣지 케이스

- 프로세스가 하나뿐이면 첫 번째로 실행된다.
- 우선순위가 모두 같으면 처음 대기 순서대로 실행된다.
- 최고 우선순위의 프로세스가 여러 개여도 현재 큐의 순서를 지켜야 한다.
- 목표 프로세스가 여러 번 뒤로 이동해도 원래 위치 `location`을 잃지 않아야 한다.

## 7. 한줄평

**대기 순서**와 **남은 최고 우선순위**를 각각 관리하니, 문제의 실행 규칙을 그대로 구현할 수 있었다.

## 8. 더 나은 풀이와 코드 개선

두 코드 모두 정답이지만, 코딩테스트에서 설명하고 검토하기에는 **최종 풀이인 큐 + 정렬 배열**을 추천한다. 큐에서 꺼내 실행하거나 맨 뒤로 보내는 과정이 문제의 규칙과 바로 대응하기 때문이다. 이전 `PriorityQueue` 풀이에서는 배열 순회가 대기 순서를 대신한다는 점을 별도로 설명해야 한다.

`clone()`을 피하려고 꼭 풀이를 바꿀 필요는 없다. 다만 이 문제처럼 우선순위 범위가 **1~9로 작다면**, `int[10]` 배열에 우선순위별 남은 개수를 기록해 최고 우선순위를 관리할 수도 있다.

## 9. 비슷한 문제에 적용하기

| 문제의 특징 | 떠올릴 방법 |
| --- | --- |
| 맨 앞 대상을 꺼내 조건에 따라 맨 뒤로 보냄 | 큐를 이용한 시뮬레이션 |
| 남은 값 중 최댓값을 반복해서 알아야 함 | 정렬, 우선순위 큐, 값의 범위가 작다면 개수 배열 |
| 값이 같은 대상도 각각 구별해야 함 | 값과 함께 원래 위치나 식별자 저장 |

큐의 **순서**와 **누가 우선순위가 높은지**는 다른 정보다. 비슷한 문제에서는 이 두 가지를 각각 어떻게 관리할지 먼저 정해 보자.
