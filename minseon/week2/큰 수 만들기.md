## 1. 문제 접근

### 첫 번째 접근: 숫자를 정렬하기

처음에는 큰 숫자가 앞자리에 와야 하므로 숫자를 정렬하는 방법을 생각했다. 스택도 떠올렸지만 어떤 숫자를 제거할지는 정하지 못했다.

```java
import java.util.*;

class Solution {
    public String solution(String number, int k) {
        String answer = "";

        char[] array = number.toCharArray();
        Arrays.sort(array);

        // number.length - k자리 중 가장 큰 수가 앞자리가 되어야 할까?
        // 스택을 쓸 수 있을까?
        for (int i = 0; i < number.length(); i++) {
        }

        return answer;
    }
}
```

하지만 이 문제는 숫자를 재배열하는 것이 아니라 `k`개를 **제거**하는 문제다. 남은 숫자의 원래 순서를 바꿀 수 없으므로 정렬한 배열로는 답을 만들 수 없다.

### 두 번째 접근: 우선순위 큐

다음에는 숫자의 값과 원래 인덱스를 함께 우선순위 큐에 넣어 큰 숫자부터 선택하려고 했다. 아래 코드는 완성된 풀이가 아니라 당시 고민이 남아 있는 코드다.

```java
import java.util.*;

class Solution {
    public String solution(String number, int k) {
        String answer = "";

        Queue<int[]> pq = new PriorityQueue<>((a, b) -> {
            if (a[1] == b[1]) {
                return Integer.compare(a[0] - b[0]);
            }
            return Integer.compare(b[1] - a[1]);
        });

        char[] charArray = number.toCharArray();
        for (int i = 0; i < number.length(); i++) {
            pq.offer(new int[]{i, charArray[i]});
        }

        int[] cur = pq.peek();
        for (int i = k; i > 0; i--) {
            if (cur[0] <= number.length() - k)
                list.add(pq.poll()[1]);
            else
                // 지금 꺼낼 수 없지만 다음 자리에서는 쓸 수도 있다.
        }
        return answer;
    }
}
```

이 접근에서는 **지금 선택할 수 없는 숫자를 큐에서 버릴 수 없다는 점**이 막혔다. 뒤쪽 자리에서는 그 숫자가 필요할 수 있기 때문이다. 우선순위 큐는 큰 숫자를 먼저 보여주지만, 답에는 원래 숫자의 순서도 유지되어야 해서 두 조건을 함께 관리하기 어려웠다. 위 코드는 `list`가 선언되지 않았고 `Integer.compare()`의 인자도 부족해 컴파일되지 않는다.

### 세 번째 접근: `Deque`로 남길 숫자 관리하기

숫자를 왼쪽부터 읽으며 현재까지 남기기로 한 숫자를 `deque`에 저장했다. 새 숫자가 `deque`의 맨 뒤 숫자보다 크고 삭제 횟수가 남았다면, 앞의 작은 숫자를 지우는 편이 유리하다. 같은 길이의 수는 앞자리부터 비교하기 때문이다.

```text
number = "1924", k = 2

1 읽기 → [1]       남은 삭제 2회
9 읽기 → [9]       1 삭제, 남은 삭제 1회
2 읽기 → [9, 2]    남은 삭제 1회
4 읽기 → [9, 4]    2 삭제, 남은 삭제 0회

결과: "94"
```

끝까지 읽었는데도 삭제 횟수가 남을 수 있다. 이때 남아 있는 숫자들은 앞에서 뒤로 갈수록 커지지 않으므로, 중요한 앞자리를 유지하고 뒤에서 남은 횟수만큼 지운다.

```text
number = "3921", k = 2

3 읽기 → [3]          남은 삭제 2회
9 읽기 → [9]          3 삭제, 남은 삭제 1회
2 읽기 → [9, 2]
1 읽기 → [9, 2, 1]

남은 삭제 1회는 맨 뒤의 1에 사용 → [9, 2]
```

원래 입력이 내림차순이어야 한다는 뜻은 아니다. 예를 들어 `"3912"`, `k = 2`에서는 마지막 `2`를 읽을 때 앞의 `1`을 지워 삭제 횟수를 모두 사용한다.

## 2. 문제 코드

마지막으로 작성한 코드다. 숫자를 고르는 로직은 맞지만, 마지막 문자열 연결은 7번에서 개선한다.

```java
import java.util.*;

class Solution {
    public String solution(String number, int k) {
        String answer = "";

        char[] array = number.toCharArray();

        Deque<Character> deque = new ArrayDeque<>();
        for (int i = 0; i < number.length(); i++) {
            while (!deque.isEmpty() && k > 0 && deque.peekLast() < array[i]) {
                deque.pollLast();
                k--;
            }
            deque.offerLast(array[i]);
        }

        while (k > 0) {
            deque.pollLast();
            k--;
        }

        while (!deque.isEmpty()) {
            answer += deque.pollFirst();
        }

        return answer;
    }
}
```

### 코드 구현 흐름

1. **숫자 읽기 — `for`문**: 원래 순서를 유지하려고 왼쪽부터 한 글자씩 읽는다.
2. **앞의 작은 숫자 제거 — 첫 번째 `while`문**: 삭제 횟수가 남았고 `deque` 맨 뒤 숫자가 현재 숫자보다 작으면 맨 뒤를 지운다. 실제로 지울 때만 `k`를 줄인다.
3. **현재 숫자 넣기 — `offerLast()`**: 더 지울 숫자가 없으면 현재 숫자를 맨 뒤에 넣는다.
4. **남은 삭제 횟수 처리 — 두 번째 `while`문**: 끝까지 읽고도 `k`가 남으면 맨 뒤부터 지운다.
5. **결과 만들기 — `pollFirst()`**: 남겨둔 숫자를 앞에서부터 꺼내 원래 순서대로 이어 붙인다.

## 3. 새롭게 배운 내용

### 그리디 문제를 생각하는 순서

그리디는 매 순간 유리한 선택을 하는 방식이다. 하지만 당장 좋아 보이는 선택이 항상 전체 정답으로 이어지는 것은 아니므로, **왜 그 선택이 나중에도 손해가 아닌지** 확인해야 한다.

1. **목표 확인**: 무엇을 가장 크게 또는 작게 만들어야 하는가? 이 문제는 정확히 `k`개를 제거해 길이가 같은 수들 중 가장 큰 수를 만든다.
2. **중요한 위치 확인**: 결과를 어디부터 비교하는가? 길이가 같은 수는 앞자리부터 비교하므로 앞자리가 더 중요하다.
3. **지금 가능한 선택 찾기**: 새 숫자를 읽었을 때 앞에서 남긴 숫자를 유지할지, 삭제 횟수를 써서 지울지 결정한다.
4. **선택이 유리한 이유 확인**: 앞의 숫자가 새 숫자보다 작다면, 앞 숫자를 지워 큰 숫자를 앞당긴 결과가 더 크다.
5. **제한 확인**: 숫자는 `k`개만 지울 수 있고, 남은 숫자의 순서는 바꿀 수 없다.
6. **남은 작업 확인**: 끝까지 읽어도 삭제 횟수가 남으면 어디서 지워야 하는지 판단한다.

다른 그리디 문제에서도 **목표 → 중요한 선택 기준 → 지금 가능한 선택 → 그 선택이 안전한 이유 → 제한 조건 → 남은 작업** 순서로 질문해볼 수 있다. 특히 선택이 안전한 이유를 설명할 수 없다면 그리디가 맞는지 더 확인해야 한다.

### 왜 앞의 작은 숫자를 지워도 될까?

첫 자리에 올 숫자는 원래 숫자의 **첫 `k + 1`자리** 안에서 골라야 한다. 그보다 뒤의 숫자를 첫 자리로 만들려면 앞의 숫자를 `k`개보다 많이 지워야 하기 때문이다. 가능한 범위 안에서 가장 큰 숫자를 앞에 놓는 것이 유리하다.

```text
number = "1924", k = 2
첫 자리 후보: 1, 9, 2
→ 9를 첫 자리로 선택하고 앞의 1을 지운다.
```

스택에서 작은 앞 숫자를 지우는 과정은 이 선택을 숫자를 읽으면서 수행하는 방법이다. 삭제한 뒤에는 남은 횟수와 남은 숫자 순서를 고려해 다음 자리를 정한다.

### 단조 스택과 `Deque`

새 숫자를 넣기 전에 `deque`의 맨 뒤에서 그보다 작은 숫자를 제거한다. 삭제 횟수가 남아 있는 동안 `deque`의 숫자는 앞에서 뒤로 갈수록 커지지 않는다. 같은 숫자는 `<` 조건에 걸리지 않으므로 `[9, 5, 5, 2]`처럼 남을 수 있다.

```java
deque.peekLast();  // 맨 뒤 숫자 확인
deque.pollLast();  // 맨 뒤 숫자 제거
deque.offerLast(current); // 맨 뒤에 현재 숫자 추가
```

### 왜 마지막에 뒤에서 지울까?

첫 번째 `while`문은 뒤에 **더 큰 숫자**가 왔을 때만 앞 숫자를 지운다. 끝까지 읽고도 `k`가 남았다면 더 큰 숫자로 대체할 기회가 없었던 것이다. 남아 있는 `deque`는 앞에서 뒤로 갈수록 커지지 않으므로, 큰 앞자리를 보존하려면 맨 뒤부터 지워야 한다.

## 4. 시간복잡도 / 공간복잡도

- `deque`에 숫자를 넣고 빼는 과정: `O(n)`. 각 숫자는 최대 한 번 들어가고 한 번 제거된다.
- 현재 코드 전체의 최악 시간복잡도: `O(n²)`. 반복문 안의 `answer += ...`가 매번 새 문자열을 만든다.
- `StringBuilder`를 사용한 개선 코드의 시간복잡도: `O(n)`.
- 공간복잡도: `O(n)`. 숫자를 담는 배열·`deque`·결과 문자열에 입력 길이에 비례한 공간을 사용한다.

## 5. 엣지 케이스

- `"4321"`처럼 뒤의 숫자가 계속 작아지는 경우: 첫 번째 `while`문에서 삭제 횟수를 사용하지 못하므로 마지막에 뒤에서 지운다.
- `"2222"`처럼 같은 숫자가 반복되는 경우: `<` 조건이므로 앞의 같은 숫자를 지우지 않는다. 남은 횟수는 뒤에서 사용한다.
- `"3912"`처럼 마지막에 더 큰 숫자가 나오는 경우: 앞의 작은 숫자를 지워 `k`를 모두 사용할 수 있다.
- `k`를 모두 사용한 뒤에도 숫자가 남아 있는 경우: 더 이상 제거하지 않고 순서대로 넣는다.

## 6. 한줄평

큰 숫자를 무조건 먼저 고르기보다, 원래 순서대로 읽으며 앞의 작은 숫자를 지울 수 있는지 판단하는 것이 핵심이었다.

## 7. 더 나은 풀이와 코드 개선

숫자를 선택하는 로직은 유지하고 결과를 만드는 부분만 `StringBuilder`로 바꾸면, 최대 100만 자리의 입력에서도 문자열 연결 때문에 느려지는 일을 피할 수 있다.

```java
import java.util.*;

class Solution {
    public String solution(String number, int k) {
        Deque<Character> deque = new ArrayDeque<>();

        for (int i = 0; i < number.length(); i++) {
            char current = number.charAt(i);

            while (!deque.isEmpty() && k > 0 && deque.peekLast() < current) {
                deque.pollLast();
                k--;
            }

            deque.offerLast(current);
        }

        while (k > 0) {
            deque.pollLast();
            k--;
        }

        StringBuilder answer = new StringBuilder();
        while (!deque.isEmpty()) {
            answer.append(deque.pollFirst());
        }

        return answer.toString();
    }
}
```

## 8. 비슷한 문제에 적용하기

**원래 순서는 유지하면서 일부 원소를 제거해 결과를 가장 크게 또는 작게 만들어야 하는 문제**에서 단조 스택을 떠올릴 수 있다.

| 목표 | 스택 맨 뒤를 제거할 조건 |
| --- | --- |
| 가장 큰 수 만들기 | 맨 뒤 숫자 `<` 현재 숫자 |
| 가장 작은 수 만들기 | 맨 뒤 숫자 `>` 현재 숫자 |

두 경우 모두 제거 가능 횟수를 지켜야 한다. 입력을 다 읽은 뒤에도 제거 횟수가 남았을 때 어느 쪽에서 제거해야 하는지는 목표와 남은 숫자의 순서를 확인해 결정한다.
