# 이모티콘 할인행사 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/150368

## 0. 문제 요약

각 이모티콘의 할인율을 **10%, 20%, 30%, 40% 중 하나**로 정한다. 사용자는 자신의 기준 할인율 이상인 이모티콘을 모두 구매한다. 구매 금액의 합이 가입 기준 금액 **이상**이면 구매를 취소하고 이모티콘 플러스에 가입한다.

목표는 **① 가입자 수를 최대화하고, ② 가입자 수가 같을 때 판매액을 최대화**하는 것이다. 사용자 수는 최대 100명, 이모티콘 수는 최대 7개다.

## 사용 알고리즘 / 자료구조

- 완전탐색, DFS, 배열
- 다른 구현: 4진수로 할인율 조합 나열

## 1. 문제 접근

먼저 **정해야 할 값**을 찾는다. 이 문제에서는 이모티콘마다 할인율을 하나씩 정해야 한다. 이모티콘 `m`개에 각각 선택지 네 가지가 있으므로 조합은 `4^m`가지다. 최대 `m = 7`일 때 `4⁷ = 16,384`가지라 모두 확인할 수 있다.

이모티콘 하나면 할인율 네 가지를 순회하고, 두 개면 첫 번째 할인율마다 두 번째 할인율 네 가지를 순회한다. 입력에 따라 이모티콘 수가 달라지므로 **현재 이모티콘의 할인율 선택 → 다음 이모티콘에서 같은 선택 반복**을 DFS로 작성한다.

할인율 조합이 완성되면 각 사용자의 구매 금액을 계산한다. 가입 기준 이상이면 구매를 취소하고 가입자로 세며, 그렇지 않으면 판매액에 더한다. 마지막에 **가입자 수를 먼저, 같으면 판매액을 비교**한다.

BFS도 검토했다. 큐에 선택 과정을 넣어 조합을 만들 수 있지만, 한 조합을 끝까지 완성하는 DFS가 코드 흐름에 잘 맞는다. 할인율을 하나씩 확정하는 그리디는 다른 이모티콘의 할인율에 따라 가입 여부가 바뀌어 정답을 보장하기 어렵다.

## 2. 문제 코드

```java
class Solution {
    private static final int[] RATES = {10, 20, 30, 40};

    public int[] solution(int[][] users, int[] emoticons) {
        int[] discounts = new int[emoticons.length];
        int[] answer = new int[2]; // [가입자 수, 판매액]

        dfs(0, discounts, users, emoticons, answer);

        return answer;
    }

    private void dfs(int idx, int[] discounts,
                     int[][] users, int[] emoticons, int[] answer) {
        if (idx == emoticons.length) {
            evaluate(discounts, users, emoticons, answer);
            return;
        }

        for (int rate : RATES) {
            discounts[idx] = rate;
            dfs(idx + 1, discounts, users, emoticons, answer);
        }
    }

    private void evaluate(int[] discounts, int[][] users,
                          int[] emoticons, int[] answer) {
        int subscribers = 0;
        int revenue = 0;

        for (int[] user : users) {
            int minRate = user[0];
            int subscriptionPrice = user[1];
            int purchase = 0;

            for (int i = 0; i < emoticons.length; i++) {
                if (discounts[i] >= minRate) {
                    purchase += emoticons[i] * (100 - discounts[i]) / 100;
                }
            }

            if (purchase >= subscriptionPrice) {
                subscribers++;
            } else {
                revenue += purchase;
            }
        }

        if (subscribers > answer[0]
                || (subscribers == answer[0] && revenue > answer[1])) {
            answer[0] = subscribers;
            answer[1] = revenue;
        }
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()` | 할인율 배열과 현재까지 가장 좋은 결과 `[가입자 수, 판매액]`를 준비한다. |
| 2 | `dfs(idx, ...)`의 `for`문 | `idx`번 이모티콘에 할인율 하나를 정하고 다음 이모티콘으로 간다. |
| 3 | `idx == emoticons.length` | 모든 할인율을 정했으므로 현재 조합을 평가하고 `return`한다. |
| 4 | `evaluate()`의 사용자 반복문 | 각 사용자가 살 이모티콘의 할인 후 가격을 합산한다. |
| 5 | `evaluate()`의 `if (purchase >= ...)` | 가입 기준에 도달하면 가입자로 세고, 그렇지 않으면 구매 금액을 판매액에 더한다. |
| 6 | `evaluate()`의 마지막 `if`문 | 가입자 수를 먼저 비교하고, 같을 때 판매액을 비교해 정답을 갱신한다. |

## 3. 새롭게 배운 내용

### DFS는 할인율 조합을 어떻게 만들까?

`idx`는 **이번에 할인율을 정할 이모티콘 번호**다. 한 단계에서 할인율 네 가지를 차례로 넣고 다음 단계로 간다. 두 개의 이모티콘이라면 `[10,10]`, `[10,20]`, `[10,30]`, `[10,40]`을 확인한 뒤 첫 번째 할인율을 `20`으로 바꿔 같은 일을 반복한다.

```text
dfs(idx=0): 첫 이모티콘에 10% 선택
  dfs(idx=1): 둘째 이모티콘에 10%, 20%, 30%, 40%를 각각 선택
dfs(idx=0): 첫 이모티콘에 20% 선택
  dfs(idx=1): 둘째 이모티콘에 10%, 20%, 30%, 40%를 각각 선택
... 총 4² = 16가지
```

재귀 호출 뒤에 `discounts[idx]`를 0으로 되돌리지 않아도 된다. 다음 할인율을 시도할 때 같은 칸을 새 값으로 **덮어쓰고**, 모든 칸의 할인율을 정했을 때만 평가하기 때문이다. `idx == emoticons.length`에서 `return`해야 더 이상 존재하지 않는 `discounts[idx]`에 접근하지 않는다.

### `RATES`는 왜 만들었을까?

문제에서 할인율 후보가 `{10, 20, 30, 40}`으로 정해져 있으므로 배열에 모아 반복한다. 이 문제에서는 10씩 증가하므로 아래처럼 작성해도 결과는 같다.

```java
for (int rate = 10; rate <= 40; rate += 10) {
    discounts[idx] = rate;
    dfs(idx + 1, discounts, users, emoticons, answer);
}
```

`RATES`는 필수 자료구조가 아니라 **네 후보를 명시한 상수 배열**이다.

### 가입자는 왜 판매액에 넣지 않을까?

구매 금액이 가입 기준 이상이면 그 사용자는 구매를 **모두 취소하고 가입**한다. 따라서 `subscribers++`만 하고 `revenue`에는 그 금액을 더하지 않는다. 금액이 기준보다 작을 때만 판매액에 더한다.

### 그리디와 완전탐색은 어떻게 다를까?

그리디는 각 단계에서 좋아 보이는 할인율 하나를 정하고 지나간 선택을 다시 시도하지 않는다. 완전탐색은 **가능한 최종 할인율 조합을 모두 만들고 비교**한다. DFS는 그 조합을 만드는 탐색 방식이다. DFS 자체가 언제나 완전탐색인 것은 아니다.

예를 들어 사용자가 30% 이상 할인한 이모티콘을 사고, 구매액이 1,300원 이상이면 가입한다고 하자. 정가 1,000원인 이모티콘 두 개를 모두 40% 할인하면 `600 + 600 = 1,200원`이어서 가입하지 않는다. 모두 30% 할인하면 `700 + 700 = 1,400원`이어서 가입한다. **할인을 더 많이 하는 선택이 가입자 수를 늘리는 것은 아니다.**

## 4. 처음 보는 문제에서의 사고 흐름

처음 보는 문제라면 알고리즘 이름부터 고르지 말고, **결정할 값 → 경우의 수 → 결과 계산 → 비교 기준** 순서로 질문한다.

| 문제의 문장 | 먼저 할 생각 | 코드로 옮길 것 |
| --- | --- | --- |
| “이모티콘마다 할인율 하나” | 무엇을 하나씩 결정하지? | `discounts[idx]`에 할인율 저장 |
| “10%, 20%, 30%, 40%” | 한 단계에서 선택지가 몇 개지? | 네 할인율을 순회하고 `dfs(idx + 1)` |
| “이모티콘 최대 7개” | 전부 시도하면 몇 가지지? | `4⁷ = 16,384`가지이므로 완전탐색 |
| “사용자마다 구매 기준이 다름” | 조합 하나의 결과는 어떻게 구하지? | 모든 할인율을 정한 뒤 사용자별 구매액 계산 |
| “기준 금액 이상이면 가입” | 구매액이 기준에 닿으면 어떻게 처리하지? | 가입자 수 증가, 그 사용자의 판매액은 제외 |
| “가입자 수 우선, 판매액은 다음” | 어느 결과가 더 좋은 답이지? | 가입자 수 비교 후 동률일 때 판매액 비교 |

**선택지가 네 가지여도 반복 횟수에 따라 경우의 수가 달라진다.**

- 이모티콘 할인행사: 최대 7번 선택 → `4⁷ = 16,384`가지.
- *n + 1 카드게임*: 최대 996장 중 처음 332장을 받고, 남은 664장을 두 장씩 뽑아 최대 332번 선택 → 단순 계산으로 `4³³²`가지.

따라서 완전탐색 가능 여부는 **한 단계의 선택지 수와 선택을 반복하는 횟수**를 함께 계산해 판단한다.

특히 **모든 할인율을 정한 뒤에야 사용자별 가입 여부가 결정된다**는 점이 DFS의 종료 조건을 알려준다. `idx == emoticons.length`에서 결과를 계산하는 이유다. 한 이모티콘의 할인율만 보고 답을 확정할 수 없으므로, 가능한 최종 조합을 비교한다.

## 5. 시간복잡도 / 공간복잡도

사용자 수를 `n`, 이모티콘 수를 `m`이라고 하면 할인율 조합은 `4^m`개다. 각 조합마다 사용자 `n`명에 대해 이모티콘 `m`개를 확인하므로 **시간복잡도는 `O(4^m × n × m)`**이다. 할인율 배열과 DFS 호출 깊이는 최대 `m`이므로 **추가 공간복잡도는 `O(m)`**이다.

최대 입력에서는 `4⁷ × 100 × 7 ≈ 1.15 × 10⁷`번의 이모티콘 확인 규모다. 흔히 참고하는 `10⁸`회보다 작지만, 실제 실행 시간은 연산 내용과 환경에도 영향을 받는다.

## 6. 다른 풀이: 4진수로 조합 나열하기

재귀 없이도 `0, 1, 2, 3`을 각각 `10%, 20%, 30%, 40%`로 대응시켜 모든 조합을 만들 수 있다. 이모티콘이 두 개라면 `00`부터 `33`까지의 4진수 `4² = 16`개가 할인율 조합이다.

```java
class Solution {
    private static final int[] RATES = {10, 20, 30, 40};

    public int[] solution(int[][] users, int[] emoticons) {
        int m = emoticons.length;
        int cases = 1;
        for (int i = 0; i < m; i++) {
            cases *= 4;
        }

        int[] answer = new int[2];

        for (int caseNumber = 0; caseNumber < cases; caseNumber++) {
            int[] discounts = new int[m];
            int number = caseNumber;

            for (int i = 0; i < m; i++) {
                discounts[i] = RATES[number % 4];
                number /= 4;
            }

            int subscribers = 0;
            int revenue = 0;
            for (int[] user : users) {
                int purchase = 0;
                for (int i = 0; i < m; i++) {
                    if (discounts[i] >= user[0]) {
                        purchase += emoticons[i] * (100 - discounts[i]) / 100;
                    }
                }

                if (purchase >= user[1]) {
                    subscribers++;
                } else {
                    revenue += purchase;
                }
            }

            if (subscribers > answer[0]
                    || (subscribers == answer[0] && revenue > answer[1])) {
                answer[0] = subscribers;
                answer[1] = revenue;
            }
        }

        return answer;
    }
}
```

`number % 4`로 현재 4진수 자리를 꺼내 할인율로 바꾸고, `number /= 4`로 다음 자리로 넘어간다. DFS와 **같은 할인율 조합을 전부 확인**하므로 시간복잡도는 `O(4^m × n × m)`이다. BFS로도 조합을 만들 수 있지만, 이 문제에서는 거리 순서가 필요하지 않아 DFS나 이 반복문 방식이 읽기 쉽다.

## 7. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 확인할 점 |
| --- | --- |
| 각 대상마다 정해진 선택지 중 하나를 골라야 함 | 모든 선택 조합이 필요한지 확인하고 DFS·재귀 검토 |
| 대상 수가 작고 선택지 수가 고정됨 | `선택지 수 ^ 대상 수`를 계산해 완전탐색 가능 여부 판단 |
| 선택 전체가 완성되어야 결과를 계산할 수 있음 | DFS의 종료 조건에서 결과 평가 |
| 목표가 여러 개이고 우선순위가 정해져 있음 | 첫 목표를 비교하고, 동률일 때 다음 목표 비교 |
| 선택지 수가 `k`개로 고정됨 | `k`진수로 조합을 반복문에서 나열하는 방법도 가능 |
