# 미로 탈출 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/159993

## 0. 문제 요약

미로의 시작점 `S`에서 레버 `L`을 당긴 뒤 출구 `E`로 가는 **최소 이동 시간**을 구한다. 한 칸 이동할 때마다 1초가 걸리고 `X`는 벽이다. 출구에 도착할 수 없으면 `-1`을 반환한다. 레버를 당기기 전에도 출구 칸을 지나갈 수 있고, 지나온 칸을 다시 지나는 것도 가능하다. 미로의 행과 열은 각각 최대 100개다.

## 사용 알고리즘 / 자료구조

- BFS, 큐, 방문 배열

## 1. 문제 접근

처음에는 이전에 푼 *게임 맵 최단거리*의 BFS를 한 번 사용하면서, 큐에 **레버를 당겼는지**도 함께 넣으려고 했다. `(행, 열, 레버 상태, 이동 시간)`을 탐색하고, `L`에 도착하면 레버 상태를 바꾼 뒤, 레버를 당긴 상태로 `E`에 도착했을 때 시간을 반환하는 방법이다. 이때 같은 칸도 레버를 당기기 전과 후에 각각 방문할 수 있어야 하므로 방문 배열은 `visited[행][열][레버 상태]`가 필요하다.

그런데 문제에는 **“출발 지점에서 먼저 레버가 있는 칸으로 이동하여 레버를 당긴 후, 문이 있는 칸으로 이동한다”**는 순서가 정해져 있다. 따라서 한 번의 BFS에서 레버 상태를 관리하는 대신, 경로를 두 구간으로 나눠 같은 BFS 함수를 두 번 호출하면 더 간단하게 표현할 수 있다고 생각했다.

```text
S → L까지의 최단 시간
L → E까지의 최단 시간
두 시간을 더해 최소 탈출 시간 계산
```

상하좌우 어느 방향으로 움직여도 한 칸에 1초가 걸린다. 이전에 푼 *게임 맵 최단거리*처럼 BFS로 각 구간의 최단 시간을 구할 수 있다. 같은 `bfs()` 함수를 시작 좌표와 목표 좌표만 바꿔 두 번 호출한다.

첫 구간이나 둘째 구간 중 하나라도 도착할 수 없으면 탈출할 수 없으므로 `-1`이다. 두 구간 모두 도착할 수 있으면 두 최단 시간의 합을 반환한다. `S → L`과 `L → E`는 반드시 차례로 지나야 하므로, 각 구간을 가장 빠르게 이동한 경로를 합치면 전체 이동 시간도 최소가 된다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(String[] maps) {
        int n = maps.length;
        int m = maps[0].length();

        int sr = 0, sc = 0; // 시작점
        int lr = 0, lc = 0; // 레버
        int er = 0, ec = 0; // 출구

        for (int r = 0; r < n; r++) {
            for (int c = 0; c < m; c++) {
                char cell = maps[r].charAt(c);

                if (cell == 'S') {
                    sr = r;
                    sc = c;
                } else if (cell == 'L') {
                    lr = r;
                    lc = c;
                } else if (cell == 'E') {
                    er = r;
                    ec = c;
                }
            }
        }

        int toLever = bfs(maps, sr, sc, lr, lc);
        if (toLever == -1) return -1;

        int toExit = bfs(maps, lr, lc, er, ec);
        if (toExit == -1) return -1;

        return toLever + toExit;
    }

    private int bfs(String[] maps, int sr, int sc, int tr, int tc) {
        int n = maps.length;
        int m = maps[0].length();

        int[] dr = {0, 0, 1, -1};
        int[] dc = {1, -1, 0, 0};

        boolean[][] visited = new boolean[n][m];
        Queue<int[]> q = new ArrayDeque<>();

        q.offer(new int[]{sr, sc, 0});
        visited[sr][sc] = true;

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int r = cur[0];
            int c = cur[1];
            int dist = cur[2];

            if (r == tr && c == tc) {
                return dist;
            }

            for (int i = 0; i < 4; i++) {
                int nr = r + dr[i];
                int nc = c + dc[i];

                if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
                if (maps[nr].charAt(nc) == 'X') continue;
                if (visited[nr][nc]) continue;

                visited[nr][nc] = true;
                q.offer(new int[]{nr, nc, dist + 1});
            }
        }

        return -1;
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()`의 이중 `for`문 | `S`, `L`, `E`의 행과 열을 각각 찾는다. |
| 2 | `bfs(maps, sr, sc, lr, lc)` | 시작점에서 레버까지의 최단 시간을 구한다. |
| 3 | `bfs(maps, lr, lc, er, ec)` | 레버에서 출구까지의 최단 시간을 구한다. |
| 4 | `bfs()`의 큐·`visited` | 해당 구간의 출발점부터 가까운 칸 순서로 탐색한다. |
| 5 | `bfs()`의 네 방향 검사 | 맵 밖, 벽, 이미 방문한 칸을 제외하고 `dist + 1`로 다음 칸을 넣는다. |
| 6 | `toLever + toExit` | 두 구간 모두 갈 수 있을 때의 최소 탈출 시간을 반환한다. |

`sr`, `sc`는 시작점의 행·열, `lr`, `lc`는 레버의 행·열, `er`, `ec`는 출구의 행·열이다. `bfs()`의 `tr`, `tc`는 **이번 호출에서 목표로 하는 칸**의 행·열이다. 좌표를 배열로 묶어 전달할 수도 있지만, 여기서는 각 좌표를 변수로 따로 두었다.

## 3. 새롭게 배운 내용

### 왜 BFS를 두 번 호출해도 될까?

레버를 반드시 먼저 지나야 하므로 모든 유효한 탈출 경로는 `S → L` 구간과 `L → E` 구간으로 나뉜다. 두 구간 모두 한 칸 이동하는 비용이 같아 BFS로 각각의 최단 시간을 구할 수 있다. 첫 구간에서 어떤 칸을 지났는지는 둘째 구간의 이동을 제한하지 않으므로 두 결과를 더하면 된다.

### `visited`를 다시 만들어야 하는 이유

문제에서는 같은 칸을 다시 지날 수 있다. `S → L`에서 방문한 칸이 `L → E` 경로에도 필요할 수 있다. 첫 번째 탐색의 `visited`를 그대로 사용하면 그 칸을 막아 잘못된 결과가 나온다. `visited`를 `bfs()` **안에서 생성**해 호출할 때마다 새 방문 배열을 사용한다.

### 출구 `E`는 레버를 당기기 전에도 지나갈 수 있다

첫 번째 BFS는 `L`을 찾는 동안 `E`를 만날 수도 있다. 이때 `E`에 도착했다고 멈추거나 벽처럼 취급하면 안 된다. 이동할 수 없는 칸은 `X`뿐이므로 코드도 `X`만 제외한다. 두 번째 BFS에서는 `S`와 `L` 역시 지나갈 수 있는 칸이다.

### 시작 거리는 왜 0일까?

이 문제는 **이동한 시간**을 묻고 한 칸 이동할 때 1초가 걸린다. 시작 위치에 가만히 있는 동안은 0초이므로 큐의 첫 상태는 `{sr, sc, 0}`이다. *게임 맵 최단거리*는 **지나간 칸의 수**를 물어 시작 칸을 1로 셌다. 두 문제의 거리 초깃값이 다른 이유는 세는 대상이 다르기 때문이다.

## 4. 처음 보는 문제에서의 사고 흐름

### “반드시 레버를 먼저 당긴다” → 어떤 값을 구해야 할까?

처음부터 출구까지 바로 가는 최단거리만 구하면 레버를 지나지 않은 경로가 답이 될 수 있다. 문제에서 반드시 거쳐야 하는 중간 지점 `L`을 지정했으므로 **`S → L`과 `L → E`의 거리**를 따로 구해야 한다고 생각한다.

### “한 칸 이동하는 데 1초” → 왜 BFS일까?

두 구간 모두 상하좌우로 움직이고 모든 이동 시간이 같다. 가까운 칸부터 살펴보는 BFS는 목표 칸을 처음 만났을 때의 이동 시간을 최단 시간으로 확정할 수 있다. 그래서 한 구간을 구하는 `bfs()`를 만든 뒤 시작점과 목표점만 바꿔 재사용한다.

### “여러 번 지나갈 수 있다” → 구현에서 무엇을 확인해야 할까?

한 번의 BFS 안에서는 같은 칸을 중복 탐색하지 않도록 방문 표시가 필요하다. 하지만 다음 구간에서는 이전 구간에서 지나간 칸을 다시 사용할 수 있다. 따라서 **방문 배열은 전체 탈출 과정이 아닌 각 BFS 호출에만 적용**한다.

| 문제에서 보이는 단서 | 풀이로 연결되는 질문 | 코드 |
| --- | --- | --- |
| `S`에서 `L`을 거쳐 `E`로 이동 | 구간별 최단 시간을 더하면 되나? | `toLever + toExit` |
| 이동마다 1초 | 각 구간의 최단 시간을 어떻게 구하나? | `bfs()` 두 번 |
| 이전 칸을 다시 지날 수 있음 | 두 구간이 방문 상태를 공유해도 되나? | `bfs()` 안의 새 `visited` |
| 도착할 수 없으면 `-1` | 어느 구간이 실패했는지 확인하나? | 각 BFS 결과 검사 |

## 5. 시간복잡도 / 공간복잡도

- 맵에서 `S`, `L`, `E`를 찾는 데 `O(n × m)`이 걸린다.
- BFS 한 번은 칸마다 최대 한 번 방문하고 네 방향을 확인하므로 `O(n × m)`이다. 두 번 호출해도 **전체 시간복잡도는 `O(n × m)`**이다.
- 방문 배열과 큐가 최대 `n × m`칸의 정보를 저장하므로 **추가 공간복잡도는 `O(n × m)`**이다.
- 최대 `100 × 100 = 10⁴`칸이다. BFS 두 번에서 각 칸의 네 방향을 모두 확인해도 최대 약 `2 × 4 × 10⁴ = 8 × 10⁴`번의 방향 검사 규모다. 흔히 참고하는 `10⁸`회보다 작지만, 그 수치는 실행 시간을 보장하는 절대 기준은 아니다.

## 6. 엣지 케이스

- `S → L`에 실패하면 출구에 갈 수 있어도 탈출할 수 없다.
- `S → L`에 성공했어도 `L → E`에 실패하면 `-1`이다.
- 레버를 당기기 전에 출구 `E`를 지나가도 된다.
- 두 번째 구간에서 첫 번째 구간의 칸을 다시 지나갈 수 있다.
- 맵이 정사각형이 아닐 수 있으므로 행 범위 `n`과 열 범위 `m`을 따로 검사한다.
- 이동 횟수를 세므로 출발점의 `dist`는 0이다.

## 7. 한줄평

**레버를 먼저 당긴다**는 조건을 보고 경로를 `S → L`, `L → E`로 나누니, 이전에 사용한 BFS를 두 번 재사용할 수 있었다.

## 8. 다른 풀이: 레버 상태를 넣어 BFS 한 번 실행하기

처음 생각한 대로 BFS 한 번으로도 풀 수 있다. 큐에 `(행, 열, 레버 상태, 이동 시간)`을 저장하고, `L`에 들어가면 레버 상태를 `1`로 바꾼다. `E`에 도착했을 때 레버 상태가 `1`이어야 탈출한 것이다.

```java
import java.util.*;

class Solution {
    public int solution(String[] maps) {
        int n = maps.length;
        int m = maps[0].length();

        int sr = 0, sc = 0;
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < m; c++) {
                if (maps[r].charAt(c) == 'S') {
                    sr = r;
                    sc = c;
                }
            }
        }

        int[] dr = {0, 0, 1, -1};
        int[] dc = {1, -1, 0, 0};

        boolean[][][] visited = new boolean[n][m][2];
        Queue<int[]> q = new ArrayDeque<>();

        q.offer(new int[]{sr, sc, 0, 0});
        visited[sr][sc][0] = true;

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int r = cur[0];
            int c = cur[1];
            int lever = cur[2];
            int dist = cur[3];

            if (maps[r].charAt(c) == 'E' && lever == 1) {
                return dist;
            }

            for (int i = 0; i < 4; i++) {
                int nr = r + dr[i];
                int nc = c + dc[i];

                if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;

                char nextCell = maps[nr].charAt(nc);
                if (nextCell == 'X') continue;

                int nextLever = nextCell == 'L' ? 1 : lever;
                if (visited[nr][nc][nextLever]) continue;

                visited[nr][nc][nextLever] = true;
                q.offer(new int[]{nr, nc, nextLever, dist + 1});
            }
        }

        return -1;
    }
}
```

`lever = 0`은 아직 레버를 당기지 않았고, `lever = 1`은 당겼다는 뜻이다. 예를 들어 `(2, 3)`을 레버를 당기기 전에 지나갔어도, 레버를 당긴 뒤 그 칸을 다시 지날 수 있다. 그래서 `visited[2][3][0]`과 `visited[2][3][1]`을 **서로 다른 방문 상태**로 관리한다. 두 풀이 모두 시간복잡도와 공간복잡도는 `O(n × m)`이다.

## 9. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 이유 |
| --- | --- |
| 최단 경로가 반드시 특정 지점을 거쳐야 함 | `시작 → 중간 지점`, `중간 지점 → 도착`으로 나눠 거리 계산 |
| 모든 이동의 비용이 같음 | BFS로 가까운 상태부터 탐색 |
| 구간 사이에 이전 방문 칸을 다시 지나갈 수 있음 | 구간별로 방문 배열을 새로 만들기 |
| 특정 조건 충족 전후에 지나갈 수 있는 길 자체가 달라짐 | 조건 상태까지 포함한 탐색이 필요한지 검토 |
