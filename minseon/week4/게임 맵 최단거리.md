# 게임 맵 최단거리 (프로그래머스 Lv.2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1844

## 0. 문제 요약

`n × m` 게임 맵의 왼쪽 위 `(0, 0)`에서 오른쪽 아래 `(n-1, m-1)`까지 이동한다. `1`인 칸만 지나갈 수 있고 `0`은 벽이다. 상하좌우로 한 칸씩 움직일 때 **지나가는 칸 수의 최솟값**을 반환한다. 도착할 수 없으면 `-1`을 반환한다. 행과 열은 각각 최대 100개다.

## 사용 알고리즘 / 자료구조

- BFS, 큐, 방문 배열

## 1. 문제 접근

출발점에서 도착점까지 가장 적은 칸을 지나야 한다. 한 번 움직일 때마다 인접한 칸으로 **똑같이 한 칸** 이동하므로, 출발점에서 가까운 칸부터 차례대로 살펴보면 된다. 큐를 사용하는 BFS가 이 순서로 칸을 탐색한다.

큐에는 `(행, 열, 현재까지 지나간 칸 수)`를 넣는다. 시작 칸도 지나간 칸에 포함하므로 `(0, 0, 1)`부터 시작한다. 현재 칸에서 상하좌우의 다음 칸을 확인하고, 맵 안에 있으며 벽이 아니고 아직 방문하지 않았다면 `dist + 1`과 함께 큐에 넣는다.

도착점을 처음 꺼냈을 때의 `dist`가 최솟값이다. 먼저 방문한 칸은 다시 볼 필요가 없으므로 큐에 **넣는 순간** 방문 표시한다.

## 2. 문제 코드

```java
import java.util.*;

class Solution {
    public int solution(int[][] maps) {
        int n = maps.length;
        int m = maps[0].length;
        boolean[][] visited = new boolean[n][m];
        int answer = bfs(maps, visited, n, m);

        return answer;
    }

    int bfs(int[][] maps, boolean[][] visited, int n, int m) {
        int[] dr = {0, 0, 1, -1};
        int[] dc = {1, -1, 0, 0};
        Queue<int[]> q = new ArrayDeque<>();
        q.offer(new int[]{0, 0, 1});
        visited[0][0] = true;

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int r = cur[0];
            int c = cur[1];
            int dist = cur[2];

            if (r == n - 1 && c == m - 1) {
                return dist;
            }

            for (int i = 0; i < 4; i++) {
                int nr = r + dr[i];
                int nc = c + dc[i];

                if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
                if (maps[nr][nc] == 0) continue;
                if (visited[nr][nc]) continue;

                visited[nr][nc] = true;
                q.offer(new int[]{nr, nc, dist + 1});
            }
        }
        return -1;
    }
}
```

### 코드 구현 흐름

| 순서 | 함수·코드 | 역할 |
| --- | --- | --- |
| 1 | `solution()` | 맵의 행·열 크기와 방문 배열을 준비하고 `bfs()`를 호출한다. |
| 2 | `bfs()`의 시작 처리 | `(0, 0, 1)`을 큐에 넣고 시작 칸을 방문 표시한다. |
| 3 | `bfs()`의 `q.poll()` | 현재까지 지나간 칸 수가 작은 순서대로 칸을 꺼낸다. |
| 4 | 도착점 검사 | 도착점을 처음 꺼냈다면 그 칸 수를 반환한다. |
| 5 | 상하좌우 탐색 | 범위 밖, 벽, 이미 방문한 칸을 제외한다. |
| 6 | `visited`와 `q.offer()` | 다음 칸을 방문 표시하고 `dist + 1`로 큐에 넣는다. |
| 7 | 마지막 `return -1` | 큐가 비어도 도착점을 찾지 못했을 때 실행된다. |

## 3. 새롭게 배운 내용

### BFS가 최단거리를 찾는 이유

큐는 먼저 넣은 칸을 먼저 꺼낸다. 거리 1인 시작 칸에서 거리 2인 칸들을 넣고, 그 칸들을 처리하면서 거리 3인 칸들을 넣는다. 따라서 BFS는 **거리 1 → 거리 2 → 거리 3** 순서로 확장한다. 모든 이동이 한 칸으로 같으므로, 도착점을 처음 발견한 경로보다 더 짧은 경로가 나중에 나타날 수 없다.

```text
출발 칸: dist = 1
  → 바로 옆 칸: dist = 2
    → 그다음 칸: dist = 3
```

이 문제는 지나간 **칸 수**를 묻는다. 시작 칸도 세기 때문에 `dist`를 0이 아니라 1로 시작한다.

### 왜 큐에 넣을 때 방문 표시할까?

하나의 칸에 여러 방향에서 도달할 수 있다. 큐에서 꺼낼 때까지 방문 표시를 미루면 같은 칸이 여러 번 큐에 들어갈 수 있다. `q.offer()`와 함께 `visited[nr][nc] = true`로 표시하면 중복 삽입을 막는다. BFS가 처음 발견한 경로가 그 칸까지의 최단 경로이므로 다시 넣을 필요도 없다.

### `dr`, `dc`가 나타내는 것

같은 인덱스의 값을 한 쌍으로 사용한다. 예를 들어 `i = 0`이면 `(dr[0], dc[0]) = (0, 1)`이므로 오른쪽 칸으로 간다. `i = 2`이면 `(1, 0)`이므로 아래 칸으로 간다. 이를 통해 상하좌우 탐색을 하나의 반복문으로 처리한다.

## 4. 처음 보는 문제에서의 사고 흐름

### “최소한의 칸을 지나간다” → 먼저 무엇을 확인할까?

최솟값을 구한다는 말만으로 바로 BFS를 정하기보다 **한 번 움직이는 비용이 모두 같은지** 확인한다. 이 문제에서는 어느 방향으로 가든 한 칸씩 움직이며, 한 칸을 지날 때마다 `dist`가 1씩 증가한다. 그래서 이동한 칸 수가 적은 상태부터 확인하면 도착점의 최솟값을 찾을 수 있다.

### “상하좌우로 이동하고 벽은 통과할 수 없다” → 다음 상태를 어떻게 만들까?

현재 좌표에서 네 방향의 좌표를 만든다. 새 좌표가 맵 밖이거나 벽이면 그 길은 탐색하지 않는다. 이동할 수 있는 칸이면 현재 거리보다 1 큰 거리로 큐에 넣는다. 같은 칸을 여러 번 처리하지 않도록 `visited`가 필요하다.

### “도착할 수 없으면 -1” → 언제 판단할까?

큐에 들어 있는 칸을 모두 처리했는데도 도착점을 꺼내지 못했다면, 출발점에서 갈 수 있는 모든 칸을 확인한 것이다. 그때 `-1`을 반환한다.

| 문제에서 확인한 조건 | 선택한 구현과 이유 |
| --- | --- |
| 한 번에 한 칸씩 이동 | 거리별로 탐색하는 BFS |
| 상하좌우 이동 | `dr`, `dc`로 네 이웃 확인 |
| 벽과 맵 경계 | 다음 칸을 큐에 넣기 전 검사 |
| 같은 칸으로 여러 경로가 이어질 수 있음 | 방문 배열로 중복 탐색 방지 |
| 도착할 수 없는 경우도 있음 | 큐가 빈 뒤 `-1` 반환 |

## 5. 시간복잡도 / 공간복잡도

- 각 칸을 큐에 최대 한 번 넣고, 꺼낼 때 네 방향을 확인하므로 **시간복잡도는 `O(n × m)`**이다.
- 방문 배열과 큐에는 각각 최대 `n × m`개의 칸 정보가 들어가므로 **추가 공간복잡도는 `O(n × m)`**이다.
- 최대 `n = m = 100`이면 칸은 `100 × 100 = 10⁴`개, 방향 확인은 최대 `4 × 10⁴`번 정도다. 흔히 참고하는 `10⁸`회보다 작은 규모다. `10⁸`은 실제 실행 시간을 보장하는 절대 기준은 아니다.

## 6. 엣지 케이스

- 출발 칸부터 개수를 세므로 시작 거리는 1이다.
- 직사각형 맵일 수 있으므로 행 범위는 `n`, 열 범위는 `m`으로 각각 검사한다.
- 벽(`0`)은 큐에 넣지 않는다.
- 목적지 주변이 막혀 도착할 수 없다면 `-1`이다.
- 방문 표시는 큐에 넣을 때 해서 같은 칸이 중복으로 들어가는 것을 막는다.

## 7. 한줄평

최단거리 문제에서는 먼저 **모든 이동 비용이 같은지** 확인한다. 이 문제는 한 칸씩 움직이므로 BFS로 가까운 칸부터 탐색하면 된다.

## 8. 더 나은 풀이와 코드 개선

현재 코드는 정답을 구하는 데 충분하다. `solution()`의 `answer`는 한 번만 사용하므로 `return bfs(maps, visited, n, m);`로 줄일 수 있다. `visited`를 `bfs()` 안에서 만들고 `n`, `m`을 `maps`에서 구하면 함수 매개변수도 줄어든다. 이는 가독성 선택이며 탐색 방식이나 복잡도는 같다.

## 9. 비슷한 문제에 적용하기

| 문제에서 보이는 특징 | 떠올릴 방법과 확인할 점 |
| --- | --- |
| 이동 비용이 모두 같고 최소 이동 횟수를 구함 | BFS로 거리 순서대로 탐색 |
| 벽이 있는 격자에서 길을 찾음 | 다음 칸을 넣기 전 범위·벽·방문 여부 검사 |
| 이동마다 비용이 다름 | 일반 BFS로 최저 비용이 보장되는지 확인하고, 필요하면 다익스트라 검토 |
| 연결된 영역의 개수를 구함 | 미방문 칸에서 BFS/DFS를 시작할 때마다 영역 하나로 세기 |
