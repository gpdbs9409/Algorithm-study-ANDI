- 문제: 피로도 — DFS / 백트래킹
- 문제 핵심
  - 각 던전에는 두 가지 피로도가 있다.
    - 최소 필요 피로도: 던전에 입장할 수 있는 조건
    - 소모 피로도: 탐험 후 실제로 차감되는 피로도
  - 던전을 탐험하는 순서에 따라 탐험 가능한 개수가 달라진다.
- 풀이 아이디어
  - 던전이 최대 8개이므로 가능한 탐험 순서를 모두 확인한다.
  - 현재 상태에서 방문하지 않았고 피로도가 충분한 던전을 선택해 탐험한 뒤, 그 상태에서 다시 다음 던전을 선택하는 과정을 DFS로 구현한다.
  - 한 순서의 탐색이 끝나면 방문 표시를 해제해 다른 순서도 확인한다. 이를 백트래킹이라고 한다.
- 예시
  - 초기 피로도가 80이고 던전이 다음과 같다고 하자.

    | 던전 | 최소 필요 피로도 | 소모 피로도 |
    | --- | --- | --- |
    | A | 80 | 20 |
    | B | 50 | 40 |
    | C | 30 | 10 |

    | 탐험 순서 | 남은 피로도 변화 | 탐험 개수 |
    | --- | --- | --- |
    | A → B | 80 → 60 → 20, C 입장 불가 | 2 |
    | A → C → B | 80 → 60 → 50 → 10 | 3 |

  - 가능한 순서를 모두 탐색하면서 최대 탐험 개수를 갱신한다.
- 풀이 코드

  ```cpp
  #include <vector>
  #include <algorithm>
  using namespace std;

  void dfs(int fatigue, int count,
           const vector<vector<int>>& dungeons,
           vector<bool>& visited, int& answer) {

      // 지금까지 탐험한 개수로 최댓값 갱신
      answer = max(answer, count);

      for (int i = 0; i < dungeons.size(); i++) {
          // 이미 탐험한 던전이면 건너뛰기
          if (visited[i]) continue;

          // 입장에 필요한 피로도가 부족하면 건너뛰기
          if (fatigue < dungeons[i][0]) continue;

          // 현재 던전 선택
          visited[i] = true;

          // 피로도를 소모하고 다음 던전 탐색
          dfs(fatigue - dungeons[i][1],
              count + 1,
              dungeons,
              visited,
              answer);

          // 다른 탐험 순서를 확인하기 위해 선택 취소
          visited[i] = false;
      }
  }

  int solution(int k, vector<vector<int>> dungeons) {
      int answer = 0;
      vector<bool> visited(dungeons.size(), false);

      dfs(k, 0, dungeons, visited, answer);

      return answer;
  }
  ```

- 헷갈렸던 부분
  1. 방문 표시를 왜 다시 해제할까
     ```cpp
     visited[i] = true;
     dfs(...);
     visited[i] = false;
     ```
     - `visited`는 현재 탐험 순서에서 방문한 던전을 기록한다.
     - 예를 들어 A → B를 확인한 다음에는 B의 방문 표시를 해제해야 A → C → B라는 다른 순서에서도 B를 선택할 수 있다.
     - 같은 탐험 순서에서 던전을 두 번 방문하는 게 아니라, 서로 다른 순서를 각각 시험하는 것이다.
  2. 피로도는 왜 복구하지 않을까
     ```cpp
     dfs(fatigue - dungeons[i][1], ...);
     ```
     - `fatigue`는 값으로 전달되므로 각 함수가 자기만의 피로도 값을 가진다.
     - 다음 함수에 차감한 값을 전달해도 현재 함수의 `fatigue`는 바뀌지 않으므로, 재귀 호출이 끝난 뒤 피로도를 다시 더해 줄 필요가 없다.
     - 반면 `visited`는 참조로 전달해 함께 사용하므로 직접 방문 표시를 해제해야 한다.
  3. 종료 조건은 어디에 있을까
     - 탐험 가능한 던전이 없으면 반복문에서 재귀 호출이 더 발생하지 않고 함수가 끝난다.
     - 별도의 종료 조건 없이도 탐색이 종료된다.
- 시간 복잡도
  - 던전 수를 n이라고 하면 시간 복잡도는 O(n × n!)이다.
  - 던전이 최대 8개이므로 모든 순서를 탐색해도 충분하다.
