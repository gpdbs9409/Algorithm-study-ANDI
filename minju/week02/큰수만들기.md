
# 큰수 만들기
## 문제

코딩테스트 연습 - 큰 수 만들기

- 문제 접근
    - 처음에는 숫자를 비교해가면서 앞에수보다 뒤에수가 더 클때 앞에꺼 없애는 식으로 지우면 되지 않을까 생각했음 → 그렇게 하면 안되는 이유  : 시간복잡도가 너무 크다? 테스트 10번이 너무 오래걸림 → 시간복잡도에서 틀리는가봄

    - 문제코드 → 시간복잡도 최악일 때 n^2 나옴
        
        ```jsx
        #include <bits/stdc++.h>
        using namespace std;
        
        string solution(string number, int k) {
            for(int i=0; i<k; i++){
                bool de = false;
                
                for(int j=0; j<number.length() - 1; j++){
                    if(number[j] < number[j+1]){
                        number.erase(j,1);
                        de = true;
                        break;
                    }
                }
                if(!de){
                    // 지울 게 없으면 마지막꺼 지워야됨
                    number.pop_back();
                }
            }
            return number;
        }
        ```
        
- 정답 접근
    - 앞에서부터 배열에 넣으면서 앞숫자가 뒤에있는 숫자보다 작으면 앞에꺼 삭제
- 문제 코드
    
    예시 : 1924
    
    ```jsx
    #include <bits/stdc++.h>
    using namespace std;
    
    string solution(string number, int k) {
        string answer = "";
        for(char n : number){
            while(!answer.empty() && k > 0 && answer.back() < n){
                answer.pop_back();
                k--;
            }
            answer.push_back(n);
        }
        
        while(k > 0){
            answer.pop_back();
            k--;
            
        }
        return answer;
    }
    ```
    
- 새롭게 배운 내용
    - 그리디 알고리즘 → **"매 순간 당장 눈앞에 보이는 최선의 선택을 반복하여 최종 목적지에 도달하는 알고리즘"**
        1. **당장의 이익만 생각한다 :**
            - 전체적인 큰 그림을 멀리 내다보고 계산하는 게 아니라, "지금 이 순간 가장 좋아 보이는 것"을 고름
        2. **과거의 선택을 번복하지 않는다:**
            - 한 번 선택을 내리면 뒤로 돌아가서 "아 그때 다르게 할 걸" 하고 수정하지 않음 그냥 그 선택을 그대로 밀고 나감
    
    주의점 : 그리디 알고리즘은 "당장의 최선이 모여 결국 전체의 최선이 되는 문제"에서만 통함. 만약 당장의 이익만 찾다가 나중에 거대한 손해를 보는 문제라면 그리디로 풀면 안 되고, 모든 경우를 다 보거나(완전탐색) 다른 방식을 써야만 함
