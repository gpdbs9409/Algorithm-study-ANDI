# 구명보트
## 문제

코딩테스트 연습 - 구명보트

- 문제 접근
    - 처음에는 limit 수로 초기화된 배열 만들어서 앞에서부터 그 채워나가면서 하면 되지 않을까 생각했는데 문제를 다시 읽어보니 구명보트는 작아서 최대 2명밖에 탈 수 없다고 함. → 무조건 제일 무거운 애랑 제일 가벼운 애랑 같이 태우면 되는거라 포인터로 접근함
- 문제 풀이 코드
    
    ```jsx
    #include <bits/stdc++.h>
    
    using namespace std;
    
    int solution(vector<int> people, int limit) {
        int answer = 0;
        sort(people.begin(), people.end());
        
        int left = 0;  // 가장 가벼운 사람                  
        int right = people.size() - 1;  // 가장 무거운 사람 
        
        while(left <= right){
            if(left == right){
                answer++;
                break;
            }
            
            if(people[left] + people[right] <= limit){
                left++;
                right--;
                answer++;
            }else{
                right--; 
                answer++;
            }
        }
        
        return answer;
    }
    ```
    

- 새롭게 배운 내용
    - 정렬을 하면 좋겠다는 생각!
- 한줄평
    - 비슷한 다른 문제들이 문득 생각났음 냅색이 떠올랐는데 개념은 좀 달라서 이번주 이내로 풀어보려고 함 (예정)
        
        ### 1. 빈 패킹 문제 (Bin Packing Problem) 
        
    - **상황:** 무게가 제각각인 여러 개의 물건들이 있고, 일정한 용량(`limit`)을 가진 상자(보트)들이 있습니다.
    - **목표:** **상자의 개수를 최소한으로 사용**해서 모든 물건을 담는 문제입니다.
    - **특징:** 구명보트 문제의 "2명 제한"이 풀리고, 한 보트에 3명이든 4명이든 무게만 안 넘으면 무한히 탈 수 있는 버전입니다. 이 문제는 **NP-hard**라는 악명 높은 최적화 문제여서, 완벽한 최솟값을 한 번에 찾는 수학적 공식이 없기 때문에 보통 **그리디(Greedy) 방식의 근사 알고리즘**을 사용합니다. (예: 무거운 것부터 내림차순으로 정렬한 뒤, 들어갈 수 있는 첫 번째 상자에 무조건 집어넣는 **First-Fit Decreasing** 방식 등)

    단속카메라(lv3), 디스크 컨트롤러 (lv3) 라고 하는데 정확하진 않음


    ### 2. 냅색 문제 (Knapsack Problem, 배낭 문제)
    
    - **상황:** 배낭에 담을 수 있는 **최대 무게(`limit`)가 정해져** 있고, 각 물건마다 무게와 '가치(중요도)'가 다릅니다.
    - **목표:** 배낭 무게 초과하지 않는 선에서 **담은 물건들의 '가치'의 합이 최대**가 되도록 고르는 문제입니다.
    - **특징:** 다이나믹 프로그래밍(DP)이나 완전탐색으로 푸는 대표적인 알고리즘 유형입니다.
    
    만약 구명보트 문제에서 "2명 제한"만 없애고 최대한 여러 명을 태워 보내는 시뮬레이션을 구현하고 싶다면, 앞서 이야기한 **내림차순 정렬 + 그리디(First-Fit)** 방식을 활용해 상자(보트) 리스트를 관리하며 쑤셔 넣는 방식으로 코드를 짜야 합니다!

    n으로 표현(lv3), 등굣길(lv3), 도둑질(lv4)
