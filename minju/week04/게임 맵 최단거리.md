# 게임 맵 최단거리 (Lv2)

코딩테스트 연습 - 게임 맵 최단거리

- 풀이코드

  ```jsx

  #include <bits/stdc++.h>
  using namespace std;

  int dx[4] = {0, 0, -1, 1};
  int dy[4] = {-1, 1, 0, 0};
  int solution(vector<vector<int>> maps) {
      int n = maps.size();
      int m = maps[0].size();

      queue<pair<int, int>> q;

      q.push({0, 0});

      while (!q.empty()) {
          int x = q.front().first;
          int y = q.front().second;
          q.pop();

          for (int i = 0; i < 4; i++) {
              int nx = x + dx[i];
              int ny = y + dy[i];


              if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;

               if (maps[nx][ny] == 1) {
                  maps[nx][ny] = maps[x][y] + 1;
                  q.push({nx, ny});
              }
          }
      }

      int answer = maps[n - 1][m - 1];
      if (answer == 1) {
          return -1;
      }

      return answer;
  }
  ```

  - 코드

- vector, pair 차이
  ### pair가 vector보다 효율적인 이유
  **<값이 어디에 저장되느냐>의 차이**
  **`pair<int, int>`**
  - 정수 두 개를 담은 작은 구조체이고, 크기는 8바이트로 고정입니다.
  - 큐 안에 값이 그대로 들어갑니다. 넣거나 꺼낼 때 숫자 두 개만 복사하면 끝납니다.
    **`vector<int>`**
  - vector 객체는 "데이터가 있는 곳의 주소, 크기, 용량" 정보만 가집니다(보통 24바이트). 실제 숫자는 **힙 메모리에 따로** 저장됩니다.
  - 그래서 `q.push({nx, ny})`를 할 때마다 힙 메모리를 새로 할당하고, `pop()`할 때마다 해제합니다. 메모리 할당은 숫자 복사보다 훨씬 비싼 작업입니다.
  - `vector<int> cur = q.front();`도 복사본을 만드는 것이라 할당이 한 번 더 일어납니다.
  - 숫자가 메모리 여기저기에 흩어져 있어서 CPU 캐시도 잘 활용하지 못합니다.
    비유하자면 pair는 **상자 안에 물건을 직접 넣는 것**이고, vector는 **상자에 창고 위치를 적은 쪽지를 넣고 물건은 창고에 따로 보관하는 것**입니다. 매번 창고를 빌리고 반납해야 하니 느릴 수밖에 없습니다.
    값이 세 개 이상 필요하다면 vector 대신 아래 방법을 쓰는 게 좋습니다. 둘 다 크기가 고정이고 힙 할당이 없습니다.
- bfs 코드 풀이 로직

  ### BFS 코드를 짤 때의 접근 순서
  1.  **문제를 그래프로 바꾸기 (코드 짜기 전에)**
      - 정점(상태)이 무엇인가? → 이 문제에서는 `(x, y)` 칸
      - 간선(이동)은 무엇인가? → 상하좌우 한 칸
      - 시작점과 도착점은 어디인가? → `(0,0)`, `(n-1, m-1)`
      - 모든 이동의 비용이 같은가? → 같다면 BFS, 다르면 다익스트라
  2.  **저장할 배열 정하기**
      - 방문 여부만 필요하면 `visited`, 거리도 필요하면 `dist`를 씁니다.
      - 지금처럼 `dist`를 0으로 초기화하면 방문 체크까지 같이 할 수 있습니다.
  3.  **시작점 넣기**
      - 큐에 시작점을 넣고, **바로 방문 처리**합니다(`dist[0][0] = 1`).
  4.  **while 루프 (BFS의 몸통)**
      1. 큐에서 하나 꺼냅니다(`front` 다음 `pop`).
      2. (필요하면) 도착했는지 확인합니다.
      3. 네 방향을 확인합니다. 다음 순서로 **안 되는 경우부터 `continue`로 거릅니다**.
         - 맵 밖인가?
         - 벽인가?
         - 이미 방문했는가?
      4. 통과하면 **방문 처리를 먼저 하고** 큐에 넣습니다.
  5.  **도착 못 한 경우 처리** - 루프가 끝났는데 도착점이 방문 안 된 상태면 -1을 반환합니다.
      **방문 처리는 큐에 넣을 때 해야 합니다. 꺼낼 때 하면 안 됩니다.**
      꺼낼 때 처리하면 같은 칸이 아직 큐에 대기 중인 상태에서 다른 칸이 그 칸을 또 넣습니다. 그러면 같은 칸이 큐에 여러 번 들어가서 시간 초과나 메모리 초과가 납니다.

  #### 외워 두면 좋은 구조

  ```cpp
  queue<pair<int,int>> q;
  q.push({sx, sy});
  dist[sx][sy] = 1;                 // 넣으면서 방문 처리

  while (!q.empty()) {
      int x = q.front().first;
      int y = q.front().second;
      q.pop();

      for (int i = 0; i < 4; i++) {
          int nx = x + dx[i];
          int ny = y + dy[i];
          if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;  // 범위
          if (maps[nx][ny] == 0) continue;                        // 벽
          if (dist[nx][ny] != 0) continue;                        // 방문

          dist[nx][ny] = dist[x][y] + 1;  // 넣으면서 방문 처리
          q.push({nx, ny});
      }
  }
  ```

- 다른 조건이라면
  | 가중치 조건 | 알고리즘 | 시간 복잡도 |
  | --------------------- | ------------------------------ | ----------- |
  | 모두 같음 (예: 1) | BFS | O(V + E) |
  | 0 또는 1만 있음 | 0-1 BFS (덱 사용) | O(V + E) |
  | 음수가 아닌 임의의 값 | **다익스트라** | O(E log V) |
  | 음수가 있음 | 벨만-포드 (음수 사이클도 판별) | O(V·E) |
