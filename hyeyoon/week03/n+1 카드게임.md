# n+1 카드게임

## 문제

처음에 전체 카드의 `n/3`장을 가지고 시작한다.

매 라운드마다 카드 2장을 뽑으며, 동전 1개를 사용하면 카드 1장을 가져올 수 있다.

합이 `n+1`이 되는 카드 2장을 제출해야 다음 라운드로 진행할 수 있다.

**목표: 주어진 동전으로 최대 몇 라운드까지 도달할 수 있는지 구하기**

---

## 풀이 아이디어

### 1. 동전을 최소한으로 사용하는 조합 선택

따라서 매 라운드마다 다음 순서로 카드 조합을 확인한다.

1. **기존 카드 + 기존 카드** → 0코인
2. **기존 카드 + 후보 카드** → 1코인
3. **후보 카드 + 후보 카드** → 2코인

가능한 조합 중 동전을 가장 적게 사용하는 조합을 우선 선택한다.

### 2. 후보 카드 관리 (구매 시점 지연)

새롭게 뽑은 카드를 바로 구매하거나 버리는 대신 `candidate`에 저장한다.

```python
firstdeck = set(cards[:n//3])
remain = deque(cards[n//3:])
candidate = set()
```

- `firstdeck`: 처음부터 가지고 있던 카드
- `remain`: 앞으로 뽑을 카드
- `candidate`: 지금까지 뽑았지만 아직 사용하지 않은 후보 카드

`candidate`에 저장했다고 실제로 구매한 것은 아니다.

**카드를 조합에 사용할 때만 동전을 차감하는 방식**으로 구현한다.

### 3. `set`을 활용한 카드 조합 탐색

두 카드의 합이 `n+1`이어야 하므로 현재 카드의 짝은 다음과 같이 구할 수 있다.

```python
target = n + 1 - card
```

이때 `set`을 사용하면 다음과 같은 장점이 있다.

- **빠른 탐색**: `target in firstdeck`처럼 특정 카드의 존재 여부를 평균 O(1)에 확인할 수 있다.
- **빠른 삭제**: 사용한 카드를 `remove()`로 평균 O(1)에 삭제할 수 있다.
- **불필요한 조합 생성 방지**: `combinations`나 `product`로 모든 카드 쌍을 만들 필요가 없다.

```python
for card in firstdeck:
    target = n + 1 - card

    if target in firstdeck:
        firstdeck.remove(card)
        firstdeck.remove(target)
        break
```

카드의 짝이 `n+1-card`로 정해져 있기 때문에, 모든 조합을 생성하지 않고도 필요한 카드를 바로 확인할 수 있다.

## 정답

```python
from collections import deque

def solution(coin, cards):
    answer = 1
    n = len(cards)

    firstdeck = set(cards[:n//3])
    remain = deque(cards[n//3:])
    candidate = set()

    while len(remain) >= 2:
        two_cards = [remain.popleft(), remain.popleft()]
        candidate.update(two_cards)

        found = False

        # 1. 기존 카드끼리 (0코인)
        for card in firstdeck:
            target = n + 1 - card

            if target in firstdeck:
                firstdeck.remove(card)
                firstdeck.remove(target)
                found = True
                break

        if found:
            answer += 1
            continue

        # 2. 기존 카드 + 후보 카드 (1코인)
        if coin >= 1:
            for card in firstdeck:
                target = n + 1 - card

                if target in candidate:
                    firstdeck.remove(card)
                    candidate.remove(target)
                    coin -= 1
                    found = True
                    break

        if found:
            answer += 1
            continue

        # 3. 후보 카드끼리 (2코인)
        if coin >= 2:
            for card in candidate:
                target = n + 1 - card

                if target in candidate:
                    candidate.remove(card)
                    candidate.remove(target)
                    coin -= 2
                    found = True
                    break

        if found:
            answer += 1
            continue

        break

    return answer
```

## 시간복잡도

**O(n²)**

1. `while`문은 매 라운드마다 카드 2장을 뽑으므로 최대 `n/3`번 실행된다. → O(n)
2. 각 라운드에서 `firstdeck` 또는 `candidate`를 순회한다. → 최대 O(n)
3. `set`의 포함 여부 확인 및 삭제는 평균 O(1)이다.

따라서 전체 시간복잡도는 **O(n²)**이다.

---

## 공간복잡도

**O(n)**

1. `firstdeck`: 처음 카드 n/3장 저장 → O(n)
2. `remain`: 남은 카드 저장 → O(n)
3. `candidate`: 새롭게 뽑은 후보 카드 저장 → 최대 O(n)

따라서 전체 공간복잡도는 **O(n)**이다.

## 배운 점 및 느낀 점

1. **동전을 최소한으로 사용하는 선택 기준**

   매 라운드마다 0코인 → 1코인 → 2코인 순서로 조합을 확인했다. 모든 카드 조합을 탐색하기보다 문제의 조건을 활용해 선택 기준을 세우는 것이 중요했다.

2. **`set` 자료구조의 장점**

   처음에는 `combinations`나 `product`로 카드 쌍을 만들어야 한다고 생각했다. 하지만 `set`을 활용하면 특정 카드의 존재 여부를 평균 O(1)에 확인할 수 있고, 사용한 카드도 빠르게 삭제할 수 있다.

   특히 이번 문제처럼 **찾아야 할 값이 `n+1-card`로 정해져 있다면, 모든 조합을 만들지 않고 `set`에서 바로 탐색하는 것이 효율적**이다.

3. **카드 구매 시점을 미루는 방식**

   새로 뽑은 카드를 바로 구매하거나 버리는 대신 `candidate`에 저장하고, 실제 사용할 때만 동전을 차감하면 구현이 간단해진다.

4. **`while coin`을 사용하면 안 되는 이유**

   동전이 0개여도 기존 카드끼리 조합을 만들면 다음 라운드로 진행할 수 있다. 따라서 동전이 아니라 **남은 카드가 2장 이상인지**를 반복 조건으로 설정해야 한다.

5. **중첩 반복문에서 `break`와 `continue` 사용**

   `break`는 현재 실행 중인 `for`문만 종료한다. 따라서 `found` 변수로 조합을 찾았는지 확인하고, 바깥 `while`문에서 `continue`를 실행해 다음 라운드로 넘어갔다.

6. **`deque` 활용**

   카드 뭉치의 앞에서부터 순서대로 카드를 꺼내야 하므로 `deque.popleft()`를 사용했다. 리스트의 `pop(0)`과 달리 O(1)에 맨 앞 원소를 꺼낼 수 있다.
