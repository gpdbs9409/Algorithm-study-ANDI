# 이모티콘 할인행사 (프로그래머스)

## 문제 분석

각 이모티콘에 10%, 20%, 30%, 40% 중 하나의 할인율을 적용한다.

사용자마다 다음 두 가지 구매 기준이 있다.

1. 본인이 원하는 할인율 이상인 이모티콘만 구매한다.
2. 구매 금액의 합이 기준 금액 이상이면 구매를 취소하고 이모티콘 플러스에 가입한다.

목표는 다음과 같다.

1. 이모티콘 플러스 가입자 수 최대화
2. 가입자 수가 같다면 이모티콘 매출액 최대화

**가입자 수가 매출액보다 우선한다.**

---

## 왜 이 알고리즘?

### 완전탐색 + DFS(백트래킹)

각 이모티콘마다 가능한 할인율은 4개다.

이모티콘이 M개라면 가능한 할인율 조합은 총 `4^M`개다.

이모티콘은 최대 7개이므로

`4^7 = 16,384`

모든 할인율 조합을 탐색할 수 있다.

각 할인율 조합마다 모든 사용자의 구매 금액을 계산하고, 가입자 수와 매출액을 비교하면 된다.

이번에는 `itertools.product()`를 사용하지 않고 DFS로 직접 할인율 조합을 생성하는 방법을 고민했다.

---



할인율 조합을 하나씩 생성한 뒤, 모든 사용자에게 적용해 가입자 수와 매출액을 계산한다.

```python
def solution(users, emoticons):
    answer = [0, 0]

    groups = [
        [10, 20, 30, 40] for _ in range(len(emoticons))
    ]

    def dfs(depth, path):
        nonlocal answer

        # 모든 이모티콘의 할인율을 선택했다면
        if depth == len(groups):
            subscribers = 0
            revenue = 0

            for min_discount, limit_price in users:
                total = 0

                for price, discount in zip(emoticons, path):
                    if discount >= min_discount:
                        total += price * (100 - discount) // 100

                # 기준 금액 이상이면 플러스 가입
                if total >= limit_price:
                    subscribers += 1
                else:
                    revenue += total

            # 가입자 수 우선, 같으면 매출액 비교
            if subscribers > answer[0]:
                answer = [subscribers, revenue]

            elif subscribers == answer[0] and revenue > answer[1]:
                answer = [subscribers, revenue]

            return

        for discount in groups[depth]:
            path.append(discount)
            dfs(depth + 1, path)
            path.pop()

    dfs(0, [])

    return answer
```

예를 들어 이모티콘이 2개라면

```python
groups = [
    [10, 20, 30, 40],
    [10, 20, 30, 40]
]
```

생성되는 할인율 조합은 다음과 같다.

```python
[
    [10, 10], [10, 20], [10, 30], [10, 40],
    [20, 10], [20, 20], [20, 30], [20, 40],
    [30, 10], [30, 20], [30, 30], [30, 40],
    [40, 10], [40, 20], [40, 30], [40, 40]
]
```

각 그룹에서 하나씩 선택하는 것이므로 데카르트 곱(Cartesian Product)에 해당한다.

`itertools`를 사용하면 다음과 동일하다.

```python
from itertools import product

result = list(product(*groups))
```

---


### 1. depth는 현재 선택할 그룹의 인덱스

- `depth = 0`: 첫 번째 이모티콘의 할인율 선택
- `depth = 1`: 두 번째 이모티콘의 할인율 선택
- `depth = 2`: 세 번째 이모티콘의 할인율 선택

모든 그룹에서 하나씩 선택하면 탐색을 종료한다.

### 2. append → dfs → pop

```python
path.append(num)        # 선택
dfs(depth + 1, path)     # 다음 그룹으로 이동
path.pop()              # 선택 취소
```

여기서 재귀함수를 호출하면 현재 함수는 잠시 멈춘다.

호출한 DFS가 종료되어 돌아오면 그다음 줄인 `path.pop()`이 실행된다.

예를 들어 그룹이 2개일 때:

```text
path = []

첫 번째 그룹에서 10 선택
→ [10]

두 번째 그룹에서 10 선택
→ [10, 10]
→ 결과 저장
→ return

pop() 실행
→ [10]

두 번째 그룹에서 20 선택
→ [10, 20]
→ 결과 저장
→ return

pop() 실행
→ [10]

두 번째 그룹의 탐색 종료
→ 첫 번째 그룹의 DFS로 복귀

pop() 실행
→ []

첫 번째 그룹에서 20 선택
→ [20]

...
```



### 구매 금액 계산

```python
for min_discount, limit_price in users:
    total = 0

    for price, discount in zip(emoticons, path):
        if discount >= min_discount:
            total += price * (100 - discount) // 100
```

`zip()`을 이용해 이모티콘 정가와 해당 할인율을 함께 가져온다.

사용자가 원하는 최소 할인율 이상일 때만 구매 금액에 더한다.

### 가입자 수와 매출액 계산

```python
if total >= limit_price:
    subscribers += 1
else:
    revenue += total
```

구매 금액이 기준 이상이면 플러스에 가입하므로 해당 사용자의 구매 금액은 매출액에 포함하지 않는다.

### 결과 비교

```python
if subscribers > answer[0]:
    answer = [subscribers, revenue]

elif subscribers == answer[0] and revenue > answer[1]:
    answer = [subscribers, revenue]
```

가입자 수가 우선이고, 가입자 수가 같을 때만 매출액을 비교한다.

## 시간 복잡도

**O(4^M × N × M)**

- M: 이모티콘 개수
- N: 사용자 수

각 이모티콘마다 할인율이 4가지이므로 할인율 조합은 `4^M`개다.

각 할인율 조합마다 N명의 사용자를 확인한다.

각 사용자의 구매 금액을 계산하기 위해 M개의 이모티콘을 확인한다.

따라서 시간복잡도는

`O(4^M × N × M)`

이다.

최대 이모티콘 수는 7개, 사용자 수는 100명이므로 충분히 탐색할 수 있다.

---

## 공간 복잡도

**O(M)** — 최종 풀이 기준

- 재귀호출 깊이: 최대 M
- path 길이: 최대 M
- groups 크기: M × 4 = O(M)

최종 풀이에서는 모든 할인율 조합을 저장하지 않고, 하나의 조합이 완성될 때마다 바로 계산한다.

따라서 추가 공간복잡도는 O(M)이다.

단, Sol 1처럼 모든 할인율 조합을 `result`에 저장한다면 O(M × 4^M)의 공간이 필요하다.

## 엣지 케이스

1. 모든 사용자가 플러스에 가입하는 경우
   - 가입자 수는 증가하지만 이모티콘 매출액은 0원이 될 수 있다.

2. 플러스 가입자가 한 명도 없는 경우
   - 가입자 수가 같으므로 매출액이 가장 큰 조합을 선택한다.

3. 사용자의 구매 금액이 가입 기준과 정확히 같은 경우
   - `total >= limit_price`이므로 플러스에 가입한다.

4. 이모티콘이 1개인 경우
   - 가능한 할인율 4가지만 탐색한다.

5. 서로 다른 할인율 조합에서 가입자 수가 같은 경우
   - 매출액이 더 큰 조합을 선택한다.

---

## 새로 배운 것

1. 여러 그룹에서 하나씩 선택하는 모든 경우의 수는 DFS와 백트래킹으로 구현할 수 있다.

2. `depth`를 현재 선택할 그룹의 인덱스로 활용하면 그룹 수가 달라져도 중첩 for문을 추가할 필요가 없다.

3. `append()` → `dfs()` → `pop()` 구조에서 DFS가 종료되어 돌아온 뒤 pop()이 실행된다.

4. 함수 호출 스택은 파이썬이 자동으로 관리하지만, path 리스트의 선택 상태는 직접 pop()으로 복구해야 한다.

5. DFS에서 결과를 저장할 때는 `path[:]`로 복사해야 이후 백트래킹 과정에서 결과가 변경되지 않는다.

6. 모든 경우의 수를 리스트에 미리 저장하지 않고, DFS 종료 조건에서 바로 계산하면 공간을 절약할 수 있다.

7. 우선순위가 있는 최적화 문제에서는 가입자 수를 먼저 비교하고, 가입자 수가 같을 때만 매출액을 비교해야 한다.
