
# 큰 수 만들기 (Greedy)

## 문제

어떤 숫자에서 k개의 수를 제거했을 때 얻을 수 있는 가장 큰 숫자를 구하려고 한다.

예를 들어 숫자 `1924`에서 수 두 개를 제거하면 다음과 같은 숫자를 만들 수 있다.

`[19, 12, 14, 92, 94, 24]`

이 중 가장 큰 숫자는 `94`이다.

문자열 형식으로 숫자 `number`와 제거할 수의 개수 `k`가 주어진다.

`number`에서 k개의 수를 제거했을 때 만들 수 있는 가장 큰 숫자를 **문자열 형태로 반환**한다.

---

## 문제 접근

### Sol 1. 가장 작은 숫자를 제거하는 방식

처음에는 숫자를 한 자리씩 분리한 뒤, 가장 작은 숫자부터 k개 제거하는 방식으로 접근했다.

```python
def solution(number, k):
    answer = ''
    numberlist = list(map(int, number))

    # 1, 9, 2, 4

    for i in range(k):  # k만큼 뺄 거니까
        min_number = min(numberlist)
        index = numberlist.index(min_number)  # 가장 작은 숫자 중 첫 번째 인덱스를 찾기

        numberlist.pop(index)  # 인덱스값을 빼다.

    answer = ''.join(map(str, numberlist))

    return answer
```

#### 시간복잡도에 대한 고민

이렇게 값으로 찾아서 빼면 아마 연산할 때마다 시간복잡도가 O(n)만큼 걸릴 것이다.

삭제 연산을 좀 더 빠르게 하는 방법이 있을까?

새로운 배열을 만들기?

투포인터로 삭제하는 것처럼 구현할 수 있었던 이유는 정렬되어 있고 한 방향으로만 가기 때문인데, 이 문제는 그런 상황이 아니다.

배열을 하나 더 복제한 다음 거기에서 뭔가 연산한다고 해도 포인터를 사용하는 방식이 아니기 때문에 어차피 동일하게 O(n)만큼의 연산이 발생할 것 같다.

#### 실행 결과 및 문제점

**TC 3개 중 2개만 맞았다.**

알고 보니까 시간복잡도 이전에 논리가 틀렸다.

무조건 작은 숫자를 제거하는 것이 정답은 아니다.

TC3을 커버하지 못한다.

**첫 번째 자릿수가 중요하다는 컨셉을 가져가야 한다.**

그러려면 `min()`을 찾는 게 아니라, for문으로 첫 번째 자릿수부터 훑으면서 다음과 같이 판단해야 할 것 같다.

- 앞의 숫자가 뒷자리 숫자보다 작다면 삭제한다.
- 앞의 숫자가 더 크다면 유지하고 다음 숫자로 넘어간다.
- 이러한 과정을 k개를 제거할 때까지 반복한다.

`while iter < k`를 사용하면 될 것 같다.

### Sol 2. 연속된 자릿수를 비교하는 방식

첫 번째 자릿수부터 순서대로 확인하면서, 바로 뒤의 숫자보다 작으면 제거하는 방식으로 접근했다.

```python
def solution(number, k):
    answer = ''
    numberlist = list(map(int, number))

    # 1, 9, 2, 4

    iter = 0
    now = 0

    while iter < k:
        if numberlist[now] < numberlist[now + 1]:
            # 앞의 자릿수가 더 작으므로 빼도 되는 상황
            numberlist.pop(now)
            iter += 1

        else:
            now += 1
            # 만약 앞의 자릿수가 더 큰 상황이라면
            # 그다음 자릿수를 가리키도록 하자.

    answer = ''.join(map(str, numberlist))

    return answer
```

#### 고민한 부분

그런데 걸리는 점이 있다.

**정말 바로 뒤에 있는 숫자(`now + 1`)만 비교해도 모든 경우를 커버할 수 있을까?**

아니다.

간혹 앞의 숫자도 다시 확인해야 한다.

만약 앞에 있는 숫자가 더 작으면 앞의 숫자를 제거해야 하기 때문이다.

즉, 단순히 `now`를 증가시키는 방식만으로는 모든 상황을 처리하기 어렵다.


### Sol 3. 최종 답변 (Greedy + Stack)

Sol 2에서는 앞뒤 숫자를 비교했지만, 숫자를 삭제한 뒤 이전 자릿수까지 다시 확인해야 하는 문제가 있었다.

이를 해결하기 위해 **스택(Stack)** 을 사용했다.

현재 숫자가 스택의 마지막 숫자보다 크다면, 앞의 작은 숫자를 제거하는 방식이다.

```python
def solution(number, k):
    answer = ''
    numberlist = list(map(int, number))

    stack = []
    iter = 0

    for now in numberlist:
        # 현재 숫자보다 앞의 숫자가 작으면 제거
        # k개까지만 제거할 수 있음
        while stack and stack[-1] < now and iter < k:
            stack.pop()
            iter += 1

        stack.append(now)

    # 끝까지 순회했는데 k개를 다 제거하지 못한 경우
    # 뒤에서 남은 개수만큼 제거
    if iter < k:
        stack = stack[:-(k - iter)]

    answer = ''.join(map(str, stack))

    return answer
```

#### 핵심 아이디어

1. 숫자를 왼쪽부터 하나씩 확인한다.
2. 현재 숫자가 스택의 마지막 숫자보다 크다면 `pop()`으로 제거한다.
3. 제거 후에도 이전 숫자가 더 작을 수 있으므로 `if`가 아니라 `while`을 사용한다.
4. 숫자를 제거한 횟수가 `k`에 도달하면 더 이상 제거하지 않는다.
5. 끝까지 확인했는데 k개를 제거하지 못했다면 뒤에서 남은 개수만큼 제거한다.

#### 왜 Stack을 사용하는가?

예를 들어 `4177`에서 숫자 `7`을 만났을 때,

```text
stack = [4, 1]
now = 7

1 < 7 → pop()
4 < 7 → pop()

stack = [7]
```

스택을 사용하면 **앞의 숫자로 되돌아가면서 비교하는 효과**를 낼 수 있다.

또한 리스트의 중간 원소를 삭제하는 대신 맨 뒤에서 `pop()`하므로 삭제 연산이 O(1)이다.

## 시간복잡도

**최종 풀이: O(n)**

여기서 n은 `number`의 길이이다.

```python
for now in numberlist:
    while stack and stack[-1] < now and iter < k:
        stack.pop()
```

겉으로 보면 이중 반복문이므로 O(n²)처럼 보일 수 있다.

하지만 각 숫자는 스택에 최대 한 번 들어가고, 최대 한 번 제거된다.

- `numberlist` 생성: O(n)
- 스택에 숫자 추가: 전체 O(n)
- 스택에서 숫자 제거: 전체 O(n)
- `join()`으로 문자열 생성: O(n)

따라서 전체 시간복잡도는 **O(n)** 이다.

### 기존 풀이와 비교

| 풀이 | 시간복잡도 | 문제점 |
|---|---|---|
| Sol 1. 최솟값 제거 | O(kn) | 논리적으로 틀린 접근 |
| Sol 2. 인접 숫자 비교 | 최악 O(kn) | 이전 숫자 재확인 불가, 인덱스 오류 가능 |
| Sol 3. Greedy + Stack | O(n) | 최종 정답 |

Sol 1에서 `min()`, `index()`, 중간 위치 `pop()`은 각각 O(n)이므로 k번 반복하면 O(kn)이다.

---

## 공간복잡도

**최종 풀이: O(n)**

- `numberlist`: O(n)
- `stack`: O(n)
- `answer`: O(n)

입력 숫자의 길이에 비례하는 추가 공간을 사용하므로 전체 공간복잡도는 **O(n)** 이다.
